### 実施して分かったこと

**GUI テストは、これまで一度も開発ビルドで動いていなかった。** 2 つの不具合を直した。

1. **`run.mjs` が開発モードの環境変数を渡していなかった** — `VSCODE_DEV=1` /
   `NODE_ENV=development` / `VSCODE_CLI=1` が無いと本番ビルドとして読み込みにいき、
   CSS が JS モジュールとして取得されて MIME で弾かれ、`workbench.desktop.main.js` ごと
   読み込めない。症状は「`.monaco-workbench` が現れないまま 120 秒でタイムアウト」で、
   原因が分かりにくい（`scripts/code.sh` は同じ変数を渡している）
2. **アクティビティバーのアイコンはトグル** — 起動時に `NIMBUS_SMOKE` が
   `nimbus.cockpit.focus` で開いているので、ケースが素直に押すと**閉じる**。
   `helpers.mjs` の `openNimbusSidebar()` で「開いている状態にする」形に統一した

さらに、テスト側の誤りを 2 つ直した（**製品側の不具合ではなかった**）。

3. `03-theme.mjs` がテーマ色を `document.body` から読んでいた。テーマの CSS 変数は
   `.monaco-workbench` に載るので、その**親**である body は継承せず必ず空になる。
   `.monaco-workbench` から読むよう直したところ、実測で
   `editor.background #1f1e1d` / `focusBorder #d97757`（テラコッタ）と確認できた
4. `09` は「5 列が出ること」を見ようとしていたが、**板はタスクが 0 件のときは列を描かず
   空の案内を出す**。列を出すにはタスクが要り、作ると worktree と Claude セッションが
   走る（課金と後片付けが発生する）ので、既定のテストでは空の案内までを見る。
   列の並び自体は `core/tasks.ts` の `KANBAN_COLUMNS` を単体テストが押さえている
