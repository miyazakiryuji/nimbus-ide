# リポジトリの構造要約カード（T-176）

新しいリポジトリを開いたとき、人は「何のプロジェクトで、どこに何があるか」を掴むまで動けない。
**エージェントも同じで、最初の数ターンを「まず構造を調べる」に使ってしまう。**
数えれば分かることは、先に数えて渡す。

## 振る舞い

コマンド **「リポジトリの構造要約を作る」**（`nimbus.repoSummary`）で、Markdown のカードが開く:

```markdown
# nimbus

| | |
| --- | --- |
| 種類 | Node.js / TypeScript |
| 設定ファイル | `package.json` |
| ブランチ | nimbus |
| 最後のコミット | テストを足す（3 分前） |
| CLAUDE.md | 2 個 |

## どこに何があるか
- `src/` — 120 ファイル
- `extensions/` — 40 ファイル

## 使われている言語
.ts 150 · .md 20
```

**「セッションに渡す」**を押すと、このカードがそのままコックピットへ送られる。

## 実装

- `extensions/nimbus/src/core/repoSummary.ts` — カードの文面（純関数）
- `extensions/nimbus/src/repoSummary.ts` — 数え上げ（`findFiles` / `readDirectory` / `git`）
- テスト: `extensions/nimbus/src/test/repoSummary.test.ts`

## 決めたこと

**数えた事実しか書かない。** 「たぶん MVVM です」のような推測を混ぜると、それを前提に
読まれてしまう。種類の判定も manifest の有無だけで、コードの中身は読まない。

**無い情報は行ごと出さない。** 「ブランチ: 不明」のような行は、読む人の時間を奪うだけ。

**数えるのは 4,000 ファイルまで。** 大きなリポジトリで固まらせない。
`node_modules` / `.git` / `out` / `dist` / `build` / `.dart_tool` / `target` / `vendor` / `.venv` は除く。

**開いた瞬間には出さない。** 自動で出すと、開くたびにカードが割り込む。
コマンドで呼ぶ形にして、必要なときだけ作る。

## 確認すること

- [ ] コマンドでカードが開き、種類・ブランチ・ディレクトリ・言語が出る
- [ ] `package.json` の name / description が使われる（無ければフォルダ名）
- [ ] `node_modules` がディレクトリ一覧に出ない
- [ ] git 管理外のフォルダでも、ブランチ行が出ないだけで落ちない
- [ ] 「セッションに渡す」でコックピットにカードが送られる

## 残っていること

- 複数ルートのワークスペースでは最初のフォルダだけ（T-173 と一緒に直す）
- 依存関係（何のライブラリを使っているか）は数えていない。manifest を読ませれば足りる
