# ノートブック（`.ipynb`）対応（T-174）

ノートブックのセルは、VS Code から見ると `vscode-notebook-cell:` という**別のファイル**。
そのまま扱うと 2 つのことが壊れる:

- **git に渡せない** — セルは管理単位ではないので「そんなファイルは無い」と言われる
- **場所が伝わらない** — 不透明な URI を渡されても、人もエージェントも開き直せない

## 振る舞い

**セルでも使える機能**（場所を `main.ipynb（セル 3）` の形で渡す）:

- 「Nimbus に頼む」（右クリック / コードレンズ）
- 「選択範囲をスニペットとして保存」（セルの言語で保存される）
- 「移行前の振る舞いを固定する」（セルは `HEAD` と比較せず、いまの内容をそのまま渡す）

**セルでは使えない機能**は、理由と代わりの手順を添えて断る:

> 履歴を辿る機能はノートブックのセルでは使えません（セルは git の管理単位ではありません）。
> ノートブック全体を対象にしたいときは、エクスプローラで `.ipynb` を選んでから実行してください。

## 実装

- `extensions/nimbus/src/core/notebooks.ts` — 判定と言い方（純関数）
- `extensions/nimbus/src/notebooks.ts` — セル URI からノートブックと番号を割り出す
- テスト: `extensions/nimbus/src/test/notebooks.test.ts`

## 決めたこと

**URI を自前で解析しない。** セル URI の中身は不透明で、形が変わる可能性がある。
開いているノートブックから**そのセルを探す**（`notebookDocuments`）方が確実。

**セル番号は 1 起点。** 画面の並びと同じにする。ファイル名とセル番号は**両方**出す —
どちらが欠けても開き直せない。

**できないことは、代わりの手順ごと断る。** 「使えません」だけで終えると、
利用者はそこで詰まる。`.ipynb` を選び直せばよいことを毎回書く。

## 確認すること

- [ ] ノートブックのセルで「Nimbus に頼む」を実行すると、`main.ipynb（セル 3）` と出る
- [ ] セルの内容をスニペットとして保存できる
- [ ] セルで「なぜこうなっているのかを辿る」を実行すると、理由つきで断られる
- [ ] 通常のファイルでは、これまでと同じ表示になる

## 残っていること

- ノートブック全体（`.ipynb`）を対象にした履歴・仕様の逆生成は、
  エクスプローラから選んだときの経路を作っていない
- 出力（実行結果）は渡していない。渡すならサイズの上限が要る
