# ロックファイルの変更を読む

`pubspec.lock` / `package-lock.json` の差分を「何がなぜ上がったか」に翻訳する（T-119）。

## 何を解決するのか

ロックファイルの差分は行数ばかり多くて読み取れない。**レビューで飛ばされる差分の代表格で、
飛ばされた結果いちばん壊れる場所**でもある。版の対応表に落として、先に見るべきものを上に出す。

## 振る舞い

コマンド「ロックファイルの変更を読む」（`nimbus.explainLockDiff`）。

- 開いているのが対応形式ならそれを、違えばワークスペースから探して選ばせる
  （対応: `pubspec.lock` / `package-lock.json`。`node_modules` は除外）
- **HEAD の中身**（`git show HEAD:<path>`）と**いまの中身**を比べる
- 出すもの
  - 上がった数（うちメジャーの数）・増えた数・消えた数
  - **先に見るべきもの（メジャー更新）** を別立てで
  - そのほかの更新（マイナー／パッチ／その他）
  - 増えたもの・消えたもの
- 版に変化が無ければ「並び順や整形だけの差分です」と書く（騒がない）
- git 管理下にない・新規追加のファイルはその旨を出して終わる（黙って空を見せない）
- Markdown の新規ドキュメントとして横に開く

## 設計

- `extensions/nimbus/src/core/lockDiff.ts` — 読み取り・比較・Markdown 化（VS Code 非依存）
- `extensions/nimbus/src/lockDiff.ts` — ファイルの特定と git からの取得

版が数字で始まらないもの（`git` 参照・パス依存など）は上がり方を判定せず「その他」にする。

## 受け入れ条件

- [x] `pubspec.lock` から名前と版を取り出す（`sdks:` を混ぜない）
- [x] `package-lock.json` から取り出す（`node_modules/` を剥がす・スコープ付きも）
- [x] 知らない形式・壊れた中身で落ちない
- [x] メジャー／マイナー／パッチを分類し、メジャーを先頭に並べる
- [x] 版に変化が無いときはその旨だけを書く
- [x] 画面確認: 材料を置いて開くと、その中身から答えが出る
      — GUI ケース `33-fixture-commands.mjs`（材料を置いた作業ツリーで開き、その中身から答えが出ることを見る）

単体テスト: `extensions/nimbus/src/test/lockDiff.test.ts`（7 件）

## 決めなかったこと・やらないこと

- **`yarn.lock` / `Podfile.lock` 対応** — まず手元で毎日出る 2 形式から。足すのは読み手を 1 つ書くだけ
- **なぜ上がったかの推測** — 変更履歴やリリースノートは読まない。ここは「何が動いたか」を出す場所
