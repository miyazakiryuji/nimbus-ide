# 承認を会話の中で受ける

**タスク**: T-266 / **実装**: `extensions/nimbus/src/permissions.ts`（待ち合わせ・既存）,
`src/cockpit/CockpitViewProvider.ts`, `media/cockpit.js`, `src/extension.ts` /
**確認**: `nimbus/tests/gui/cases/44-approval-card.mjs`（`--with-claude`）

## なぜ

これまでの承認はブロッキングのモーダル（`showWarningMessage({ modal: true })`）だった。

- **窓ごと止まる。** 承認待ちのあいだ、そのウィンドウでは何もできない。
  並列で走らせるほど「止まっている窓」が増える
- **読む場所と決める場所が違う。** 何を頼んだかはコックピットにあり、
  判断はモーダルの中。目と手が往復する（人間工学 E2）

Cursor のように**会話の流れの中にカードで出して、その場で決める**形へ寄せる。

## どう出るか

コックピットの入力欄のすぐ上に、答え待ちのカードが積まれる。手はもうそこにある。

| ボタン | 決めること |
| --- | --- |
| 許可 | この 1 回だけ |
| このセッションは許可 | このセッションのあいだ聞かない |
| 常に許可 | 設定へルールとして残す（ルールを作れるときだけ出す） |
| 拒否 | 断る。エージェントには「利用者が拒否しました」と返る |

押した瞬間にカードは消える。**拡張からの更新を待たない** — 押せたのかどうかが分からない間が
いちばん不安なので、手応えはその場で返す。

## 逃げ道（コックピットが無いとき）

`queueMode` が真のときだけカードで受ける。判定は
**「設定でキューモード」または「コックピットの面が作られている」**。

一度もコックピットを開いていないウィンドウでは、今までどおりモーダルを出す。
面が無いところにカードを出しても、**誰も見られないまま待ち続ける**ことになるため。
承認が来たらコックピットを前面に出すので、開いてさえいれば見落とさない。

横断の「承認待ち」ビュー（T-010）とステータスバーの件数は**そのまま残す** —
別ウィンドウのぶんを拾う口はここにしか無い（置き場所の見直しは T-263）。

## 差分は「開く」に留める

危ない編集の中身は、カードに埋め込まず既存の差分エディタ（F3・`core/editPreview.ts`）で見せる。
カードに全部載せると、決めるための 1 行が差分に埋もれる。

## 止まらないこと

カードで受けるあいだ、ウィンドウは止まらない。他のファイルを読む・別のセッションへ指示を出す・
承認を後回しにする、のどれもできる。答えを待っているのは**そのツール呼び出しだけ**。
