# なぜこうなっているのかを辿る（T-079）

「なぜこのコードはこうなっているのか」は、コードを読んでも分からない。
分かるのは**いつ・誰が・どのコミットで入れたか**で、そこに書かれた意図だけが手がかり。

経緯を知らずに直すのが、いちばん危ない。**直す前に、まず辿る。**

## 振る舞い

範囲を選んで（選ばなければカーソル行）**「なぜこうなっているのかを辿る」**（`nimbus.exploreHistory`）:

```
src/a.ts:10–12 は 2 コミット由来です。
  2026-08-13  境界を直す  (別の人 · 1 行)
  2026-08-12  最初の実装  (宮崎 · 2 行)
```

**「なぜこうなっているかを調べさせる」**を押すと、コミットの一覧と対象のコードを添えて
コックピットへ送られる。頼むのは「直して」ではなく**「何を解決しようとしたのかを読み取って」**。

## 実装

- `extensions/nimbus/src/core/archaeology.ts` — `--line-porcelain` の解析と文面（純関数）
- `extensions/nimbus/src/archaeology.ts` — `git blame` の口
- テスト: `extensions/nimbus/src/test/archaeology.test.ts`

## 決めたこと

**`--line-porcelain` を使い、省略されたヘッダを引き継ぐ。** 同じコミットが続くと
作者や日付の行が省かれる。そこを取りこぼすと、行ごとに作者が消えて表が壊れる。

**コミット単位にまとめて新しい順。** 行ごとに並べても読めない。
「この範囲は 2 つのコミットで出来ている」が分かれば十分。

**「推測を事実として書かないでください」を必ず入れる。** 考古学でいちばん危ないのは、
それらしい物語を作ってしまうこと。分からないものは分からないと書かせる。

**未コミットのファイルでは素直に失敗を伝える。** `git blame` は追跡されていない
ファイルで失敗するので、「未コミットかもしれません」と理由を添える。

## 確認すること

- [ ] 範囲を選んで実行すると、コミットの一覧が日付つきで出る
- [ ] 何も選ばずに実行すると、カーソル行が対象になる
- [ ] 同じコミットが続く範囲でも、作者と日付が全行に付く
- [ ] 「調べさせる」でコックピットにコミット一覧とコードが送られる
- [ ] 追跡されていないファイルでは、理由つきのエラーが出る

## 残っていること

  コミットの言葉だけが手がかりで、**そのとき何を頼まれたか**までは辿れない
