# リリースノートの下書き

コミット履歴から、人が読む形に並べ替える（T-062）。

## 何を解決するのか

リリースのたびに「何を入れたっけ」とログを遡る作業が発生する。事実はコミットに残っているので、
**並べ替えるところまで**を機械にやらせる。文章にするのは人（または本文をセッションに渡す）。

## 振る舞い

コマンド「リリースノートの下書きを作る」（`nimbus.draftReleaseNotes`）。

- 起点は**直近のタグ**を既定にする（`git describe --tags --abbrev=0`）。タグが無ければ `HEAD~20`。
  入力欄で好きな範囲に変えられる
- `<起点>..HEAD` のコミットを分類して並べる

  | 分類 | 判定 |
  | --- | --- |
  | 足したもの | `feat:` / 「足す」「作る」「追加」「対応」「〜できるようにする」 |
  | 直したもの | `fix:` / 「直す」「バグ」「落ちる」「壊れ」 |
  | ドキュメント | `docs:` / 「ドキュメント」「仕様」「記録」「台帳」 |
  | そのほか | 上に当てはまらないもの |

- **迷ったら「そのほか」に落とす。** 間違った分類で並べるより、分類しないほうが惑わせない
- 件名は**そのまま載せる**。要約して事実が落ちるより、多少長くても原文がいい
- タスク ID（`T-123`）を拾って添える。ただし**件名に既にあるときは足さない**（二重に出さない）
- 末尾に「利用者から見て何が変わったかの言葉に直してから配ってください」と添える
- Markdown の新規ドキュメントとして開く

## 設計

- `extensions/nimbus/src/core/releaseNotes.ts` — 解析・分類・Markdown 化（VS Code 非依存）
- `extensions/nimbus/src/releaseNotes.ts` — git の呼び出しとコマンド

## 受け入れ条件

- [x] `git log` の出力を読む（壊れた行は飛ばす）
- [x] 接頭辞と動詞で分類し、迷ったら「そのほか」に落とす
- [x] 件名をそのまま載せる
- [x] 件名に無いタスク ID だけを添える
- [x] 範囲にコミットが無ければその旨だけを書く
- [ ] 画面確認（実際のタグから作る・未実施）

単体テスト: `extensions/nimbus/src/test/releaseNotes.test.ts`（6 件）

## 決めなかったこと・やらないこと

- **文章の生成** — ここは事実を並べる場所。言葉にするのは人か、この下書きを渡されたセッション
- **コミットの取捨選択** — 全部載せる。落とす判断は人がする
