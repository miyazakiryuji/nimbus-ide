# テストが守っているかを確かめる（T-182）

カバレッジは「実行されたか」しか言わない。**実行されているのに何も確かめていない**テストは、
カバレッジ 100% でも通ってしまう。エージェントに書かせたテストほど、この形になりやすい。

見分ける方法は 1 つ — コードをわざと壊して、**テストが落ちるかどうか**を見る。
落ちなければ、そこは誰も守っていない。

## 振る舞い

コマンド **「テストが守っているかを確かめる」**（`nimbus.checkMutations`）:

```
src/core/usage.ts: 3 通りの壊し方が作れます
  12: >= → >  if (percent >= limit) {
  30: && → ||  if (a && b) {
  44: true → false  return true;
```

**「確かめさせる」**を押すと、次の手順つきでコックピットへ送られる:

1. その 1 か所**だけ**を書き換える
2. 関係するテストを走らせる
3. **必ず元に戻す**（次に進む前に、戻したことを確かめる）

そして「**落ちなかった壊し方**」と「どんなテストを足せば捕まえられるか」を報告させる。
**コードの改善はさせない。確かめるだけ。**

## 実装

- `extensions/nimbus/src/core/mutations.ts` — 候補出しと文面（純関数）
- `extensions/nimbus/src/mutations.ts` — エディタの口
- テスト: `extensions/nimbus/src/test/mutations.test.ts`

## 決めたこと

**意味が変わることが確実な壊し方だけを出す。** `>=`→`>` / `===`→`!==` / `&&`→`||` /
`true`→`false` など。「たぶん変わる」ものを混ぜると、落ちなかった理由が
「そもそも壊れていない」になり、評価にならない。

**コメントと空行は壊さない。** `trueValue` のような語の一部も対象にしない。

**1 行につき 1 つ、12 個まで。** それ以上出しても回しきれない。

**壊すのは Nimbus ではなくセッション。** ファイルを勝手に書き換えて走らせるのは、
戻し忘れたときの被害が大きすぎる。**手順として渡し、承認の経路に乗せる。**

## 確認すること

- [ ] 比較演算子や真偽値を含むファイルで、候補が行番号つきで出る
- [ ] コメント行の `>=` は候補にならない
- [ ] 候補が無いファイルでは「見つかりませんでした」と出る
- [ ] 「確かめさせる」で、1 つずつ・必ず戻す手順つきの指示が送られる

## 残っていること

- 実際に壊して走らせるところは自動化していない（上の判断のとおり）
- 言語ごとの構文差は見ていない（テキストとして置き換えられるものだけ）
- カバレッジ差分（[test-runner](test-runner.md) の T-109）と組み合わせると、
  「実行されているのに守られていない行」が絞れる。連携はまだ無い
