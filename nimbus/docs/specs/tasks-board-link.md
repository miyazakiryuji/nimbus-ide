# tasks.md とタスク板の対応づけ・待機列の優先度

## 何を解決するのか

**対応づけ**（T-013）— 「やること」は `tasks.md` にあり、「走っているもの」は板にある。
同じものが 2 か所にあると、どちらが正か分からなくなる。転記も手作業になる。

**優先度**（T-233）— 同時実行の上限があるので、待機列ができる。
急ぎのものを後ろで待たせておく理由はない。

## 振る舞い

### tasks.md から着手する（T-013）

コマンド **「Nimbus: tasks.md から着手する」**（`nimbus.taskFromFile`）。

- ワークスペース直下の `tasks.md` を読み、**定義行**（`- [ ] T-001 …`）を候補にする。
  本文中の参照（「T-024 と対」など）は拾わない
- **完了済みと claim 済みは候補に出さない。** claim は `@session-a 2026-08-13` の形で判定する。
  出すと二重作業の元になる
- 優先度順（P1 → P2 → P3 → 無印）に並べる
- 選ぶと指示を確認して、板のタスクを作る。`tasks.md` の `[P1]` は**待機列の優先度「高」**に、
  `[P3]` は「低」に持ち込む
- タスクは元の項目 ID を覚えている

### 完了したら tasks.md も動かす（T-013）

板のタスクを完了にしたとき、元の項目 ID があれば
**「tasks.md も完了にしますか」**と聞く。承認すると `## 完了` の先頭へ移す。

- **行ごと動かす**（`tasks.md` の約束）。本文は書き換えない。
  書き換えると、並行して編集している他のセッションと機械的にマージできなくなる
- 見つからない・すでに完了・完了セクションが無い、のいずれでも**何もしない**（黙って壊さない）

### 待機列の優先度（T-233）

- 「高 / 中 / 低」の 3 段階。既定は「中」
- **優先度が先、同じなら作った順**（同じ優先度なら、先に入れたものを追い越さない）
- コマンド **「Nimbus: 待機中タスクの優先度を変える」**（`nimbus.setTaskPriority`）
- **待機中のタスクだけ**変えられる（走り出したあとに変えても意味がない）
- 保存済みの古いタスクに優先度が無くても「中」として扱う（既存データを壊さない）

## 決めなかったこと・やらないこと

- **自動では移さない。** 完了のたびに `tasks.md` が勝手に書き変わると、
  並行して編集している他のセッションのコミットに巻き込まれる。必ず一度聞く
- **claim を Nimbus が書き込むことはしない。** 着手した時点で `tasks.md` に
  `@session-x` を書くのが本来だが、それは書き換えであって行の移動ではない。
  誰がやるかの取り決めが先（いまは人間・AI とも手で書いている）
- **双方向の同期はしない。** `tasks.md` → 板の一方向と、完了時の一往復だけ。
  常時同期は、どちらが正かの問題を増やすだけ
