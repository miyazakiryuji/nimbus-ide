# 実物との突き合わせと、仮の応答

スキーマと実際に返ってくるものを比べ、無い API の代わりを作る（T-218 / T-124）。

## 何を解決するのか

スキーマは**書いた時点の約束**でしかない。実物とずれていることは普通にあり、そのずれは
**動かして初めて分かる**。逆に API がまだ無い段階では、スキーマから作った偽の応答があれば
先へ進める。

## 振る舞い

### 実物とスキーマを突き合わせる（`nimbus.checkApiResponse`）

- スキーマと定義を選び、**選択範囲かクリップボード**の JSON と比べる（curl の結果を貼る使い方）
- 出すもの
  - 返ってきていない必須フィールド
  - 型が違うもの（`integer` の場所に `number` が来ても騒がない。JSON では区別されないため）
  - 許していない `null`
  - **スキーマに無いもの** — 挙げるが、**間違いとは言わない**。サーバーが足しただけのことが
    多く、壊れているわけではない（型を作り直す合図にはなる）
- オブジェクトでないものが返ったら、それだけを言う

### 仮の応答を作る（`nimbus.generateMockResponse`）

- スキーマから、それらしい JSON を作ってエディタに開く
- **本物のように見せない。** 値は「明らかに仮のもの」（`text` / `0` / `true`）にして、
  気づかないまま本番の判断材料にされないようにする
- `$ref` は 2 段までたどる（循環で止まらないため）
- **サーバーは立てない。** 立てると片付け忘れる

## 設計

- `extensions/nimbus/src/core/apiCheck.ts` — 突き合わせと生成（VS Code 非依存）
- `extensions/nimbus/src/apiCheck.ts` — スキーマ選択・入力の取得・表示
- スキーマの読み込みは [`openapi`](openapi.md) を使い回す

## 受け入れ条件

- [x] JSON の値から型を見分ける（整数と小数を分ける）
- [x] 必須の欠け・型違い・許していない null を挙げる
- [x] `integer` の場所の `number` で騒がない
- [x] 余分なフィールドを挙げるが、間違いとは言わない
- [x] 仮の応答が明らかに仮の値になる
- [ ] 画面確認（実際の応答で試す・未実施）

単体テスト: `extensions/nimbus/src/test/apiCheck.test.ts`（10 件）

## 決めなかったこと・やらないこと

- **モックサーバーの起動** — 立てると片付け忘れ、古い応答を返し続ける。JSON を出すまで
- **配列の中身を全部見ること** — 先頭だけで足りる。全部見ると出力が読めなくなる
