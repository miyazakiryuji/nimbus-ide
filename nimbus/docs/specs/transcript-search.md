# 過去セッションの横断検索

## 何を解決するのか

「あの実装どうやったっけ」を探すのが、Claude Code 単体だと一番つらい。
会話は残っているのに、探す手段が無い。ファイル名でも、使ったツールでも辿れない。

対応する tasks.md の項目: T-034。

## 調べたこと — 自前の DB は要らなかった

タスクには「フォークにはまだ永続化層が無い。自前 DB を作る前に、Claude Code 本体が
`~/.claude/projects/**` に残している JSONL を読む線を調べる」とあった。**読める。自前 DB は要らない。**

- 置き場所: `~/.claude/projects/<エンコードした cwd>/<セッション UUID>.jsonl`
- 1 行 1 レコードの JSONL。会話に関係するのは `type: "user"` と `type: "assistant"` の行だけで、
  実測では**全体の 3 割ほど**。残りは `attachment` / `mode` / `permission-mode` /
  `file-history-snapshot` / `file-history-delta` / `queue-operation` など
- `type: "ai-title"` の行に Claude Code が付けた**セッションのタイトル**が入っている（一覧の見出しに使う）
- `user` / `assistant` の行は `cwd` / `gitBranch` / `timestamp` / `isSidechain` / `isMeta` を持つ
- ツール呼び出しは `message.content` の `tool_use` ブロック。`input.file_path` から**触ったファイル**が取れる

実測（このリポジトリの記録 28 本）: 1,172 レコード。`tool:Edit` で 215 件、
`file:tasks.md` で 84 件が当たる。

**Nimbus は書き込まない。** 他人（Claude Code 本体）の記録なので、読むだけにする。

## 振る舞い

コマンド **「Nimbus: 過去セッションを検索」**（`nimbus.searchTranscripts`）。

- 入力は空白区切り。**すべての語を含む**発言を拾う（AND）
- `file:` と `tool:` で絞り込める
  - `file:normalize.ts` — 触ったファイルのパスに部分一致
  - `tool:Edit` — 使ったツール名（大文字小文字は無視）
  - 例: `file:normalize.ts tool:Edit フック`
  - **`file:` / `tool:` だけでも検索できる**（語は無くてよい）
- 進捗つきで走り、途中でキャンセルできる。新しい記録から順に見る
- 結果は新しい順。行には抜粋・セッションのタイトル・日時・ブランチ・ツール・触ったファイル
- **当たった語が見えるように抜粋の中心をずらす**（頭から 100 文字だと長い発言で当たりが見えない）
- ツールだけの発言は本文が空になるので、`Edit — /path/to/file` のように何をしたかを出す
  （実測: `tool:` での検索は本文が空の当たりが大半）
- 選ぶと、その発言を **Markdown で開く** — タイトル・セッション ID・記録のパス・
  作業ディレクトリ・ブランチ・日時・使ったツール・触ったファイル・本文。
  見つかっても中身が読めないなら、探せていないのと同じ
- 300 件で打ち切り、**打ち切ったことをタイトルに出す**（黙って切ると「これで全部」と誤解する）
- 1 ファイル 12MB を超える記録は飛ばす（拡張ホストを止めないための保険）

## 設計

- `extensions/nimbus/src/core/transcripts.ts` — 行の解釈・検索語の解釈・絞り込み・抜粋・見出し。
  VS Code にもファイルシステムにも依存しない。
  `parseTranscript()` / `parseQuery()` / `searchEntries()` / `snippetAround()` /
  `readSessionMeta()` / `projectDirName()` / `formatTimestamp()`
- `extensions/nimbus/src/transcriptSearch.ts` — 記録の列挙・読み込み・UI

**壊れた行で止まらない。** 他人が書いている最中のファイルを読むので、
途中で切れた JSON が混ざる。その行だけ落として検索は続ける。見出しの読み取りも同じ。

### 2 つの実装を 1 つにした経緯

この機能は**並行していた 2 つのセッションが同時に実装していた**（作業ツリーを共有しているため、
一方の `core/transcripts.ts` がもう一方のものを上書きし、`transcriptSearch.ts` から見て
API が噛み合わない＝ビルドが通らない状態になった）。

解決は「後から書いたほうを捨てる」ではなく**統合**にした。土台は先に置かれていた
`parseTranscript` / `searchEntries` 系の API をそのまま残し、もう一方にしか無かった
次の 3 つを足している（既存の関数シグネチャとテストは 1 つも変えていない）:

1. `readSessionMeta()` — `type: "ai-title"` からセッションのタイトルを拾う
2. `isSidechain` / `isMeta` の行を落とす
3. 記録の列挙・進捗表示・打ち切り・Markdown で開く UI 側

## 受け入れ条件

- [x] `file:` / `tool:` を絞り込みとして切り出す（単体テスト）
- [x] 会話の行だけを拾い、`attachment` などは無視する（単体テスト）
- [x] 壊れた行・空行で止まらない（単体テスト）
- [x] サブエージェント（`isSidechain`）と meta の行は結果に混ぜない（単体テスト）
- [x] ツール結果の本文は検索対象に入れない（長くて邪魔になる。単体テスト）
- [x] 当たった語が見えるように抜粋の中心をずらす（単体テスト）
- [x] 実記録での動作確認（28 本 1,172 レコード・`tool:Edit` 215 件・`file:tasks.md` 84 件）
- [ ] 画面確認: 検索してから結果を開くまで

## 決めなかったこと・やらないこと

- **索引（インデックス）は作らない。** 実測で 28 本の全文走査が体感で止まらない範囲に収まる。
  記録が増えて遅くなったら、そのとき索引を足す。先に作ると、壊れたときに直す場所が増えるだけ
- **記録への書き込みはしない。** Claude Code 本体のものなので、読み取り専用で扱う
- **thinking ブロックは検索対象に入れていない。** 本文が長く、探しているのはたいてい
  「何を頼んだか」「何を返したか」のほう
- **セッションを再開する導線は付けていない。** 開くのは記録の写しまで。
  再開は SDK の `resume` を使う別の仕事（`SessionManager.createSession` に口はある）
