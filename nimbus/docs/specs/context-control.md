# 文脈の制御（ピン留め・予算・効率）

## 何を解決するのか

文脈は有限で、しかも**黙って埋まる**。埋まると圧縮が走り、前提が抜け落ちる。
「毎回これは踏まえて」を指し忘れる、いつの間にか予算を使い切る、同じファイルを
何度も読み直して枠を溶かす — どれも見えていないから起きる。

対応する tasks.md の項目: T-152（コンテキストのピン留め）/ T-153（コンテキスト予算の割り当て）/
T-156（コンテキスト効率のスコア表示）。読ませたくない場所の指定は T-155（`protected-paths.md`）。

## 振る舞い

### ピン留め（T-152）

コマンド **「Nimbus: 常に含めるファイル（ピン留め）」**（`nimbus.pinnedFiles`）。

- QuickPick で一覧が出る。**選ぶと外れる**、先頭の「ファイルを足す」で追加
- 設定を直接書かせない（パスの綴り間違いが一番多い）。保存先は
  `nimbus.context.pinnedFiles`（ワークスペース設定・相対パス）
- セッション開始時に読み、SDK の `systemPrompt: { type:'preset', preset:'claude_code', append }`
  に**足す**。preset を置き換えないので、Claude Code としての振る舞いは残る
- 積む文章には「これが前提であること」と「**セッション開始時点の写しで、
  途中で変わっても追従しないこと**」を書く。書かないと古い内容を信じ続ける
- **合計 60KB まで。** 毎ターン積まれるので、ここが膨らむと他のことを何も覚えられなくなる
- 上限を超えたぶんは**黙って切らず**、外したファイル名を通知で出す
- 指定した順を守る（並び順が利用者の優先順位そのもの）
- 読めなかったファイルはログに名前を出す（設定に残ったままのパスに気づけるように）

### 予算（T-153）

- 設定 `nimbus.context.budgetTokens`（既定 `0` = 予算なし）
- 使用量ビューに「予算」ゲージが出る
- **8 割で警告、超えたら再度警告。** どちらも「圧縮する」ボタン付きで、
  押すと `nimbus.compact` が走る
- **止めない。** 圧縮という手が残っているので、止めるより「いま圧縮しますか」と
  聞くほうが役に立つ
- 段階ごとに一度だけ出す。予算内に戻れば、また出せるようになる

### 効率（T-156）

使用量ビューの「読み込みの効率」。

- スコア = 読んだファイルの種類数 ÷ 読み込みの総回数（%）。1 ファイル 1 回なら 100%
- 読み直しが多いファイルを上位 5 件まで並べる
- **読み込みが無いときは 0% ではなく 100%**（減点しようがない）

## 設計

- `extensions/nimbus/src/core/pinned.ts` — 上限の選別とプロンプトの組み立て
- `extensions/nimbus/src/core/efficiency.ts` — スコアの算出
- `extensions/nimbus/src/core/usage.ts` — `thresholdLevel()` / `budgetGauge()`
- `extensions/nimbus/src/usageView.ts` — 予算ゲージと効率の表示
- `extensions/nimbus/src/extension.ts` — ピン留めの読み込み・管理コマンド・予算の警告

### 「無駄な読み込み」を言い切らない

タスクには「無駄な読み込みを検出する」とあるが、**ある読み込みが無駄だったかは機械には分からない**。
理解のために読んだファイルは、編集されなくても無駄ではない。

そこで、**言い切れるものだけ**を数えることにした。同じファイルの 2 回目以降の読み込みは、
内容が既に文脈にある以上、明確に重複している。スコアはこの重複だけを見ている。

`thresholdLevel()` は T-059（コスト上限）と共有している。上限に対する 3 段階の判定は
費用でも文脈でも同じ規則でよく、2 つ持つと片方だけ直す事故が起きる。

- [x] 入らなかったものを黙って切らず、名前を残す（単体テスト）
- [x] プロンプトに「前提」と「写しなので読み直せ」を書く（単体テスト）
- [x] ピン留めが無ければプロンプトも空（単体テスト）

- [x] 予算は 8 割で警告、超えたら over（単体テスト）
- [x] 1 ファイル 1 回なら満点、読み直しは重複として数える（単体テスト）

- [ ] 画面確認: ピン留めしたファイルの内容を Claude が前提として答える
- [ ] 画面確認: 予算の 8 割で警告が出て「圧縮する」が効く

## 決めなかったこと・やらないこと

- **ピン留めの内容を毎ターン読み直さない。** セッション開始時の写しにする。
  毎ターン読むと、大きいファイルほど読み込みだけで枠を使う。
  代わりに「写しなので読み直せ」とプロンプトに書いてある
- **予算を超えても止めない。** 圧縮という手が残っているうちに止めるのは早すぎる
- **「無駄な読み込み」を判定しない**（上記）。重複だけを数える
- **圧縮前に何を残すか選ばせる画面（T-154）は含めない。** 別タスク
