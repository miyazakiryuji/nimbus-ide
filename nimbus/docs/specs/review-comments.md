# レビューコメントの取り込み

届いたコメントを、直す作業に変える（T-116）。

## 何を解決するのか

コメントは散らばって届く。**どれが直しの依頼で、どれが感想か**を仕分けるだけで手が動き出す。
場所（ファイル・行）が付いていれば、そのまま作業になる。

## 振る舞い

コマンド「レビューコメントを取り込む」（`nimbus.importReviewComments`）。

- 取り込み元は `gh pr view --json comments,reviews`。**無ければ諦める**
  （Nimbus は GitHub の API を自分で叩かない — 資格情報を持たない方針）
- 仕分ける — **依頼 → 質問 → 感想**の順に見る

  | 種類 | 見るもの |
  | --- | --- |
  | 直しの依頼 | 「直して」「すべき」「漏れ」「バグ」など |
  | 質問 | 末尾の `?`、「でしょうか」「なぜ」 |
  | 感想 | 「いいですね」「LGTM」など |
  | その他 | 上に当てはまらないもの |

- **褒め言葉が混ざっていても、直しの依頼なら依頼。**「いいですね。ただ、ここは直して」は依頼
- **感想を依頼として扱わない。** 全部を対象にすると、いちいち確認が要って結局止まる
- 手を動かすものだけを一覧にし、**場所が分かるものを先に**並べる
- 選ぶと、その 1 件をコックピットへ送る。**まとめて渡さない**（どれに対する修正か分からなくなる）
- 送る文には「意図が読み取れないときは、そのまま直さずに聞いてください」を入れる

## 決めなかったこと・やらないこと

- **返信の自動投稿** — 返事は人の言葉で。下書きまでにする
- **GitHub API を直接叩くこと** — 資格情報を持たない。`gh` に任せる
