# 日本語の指示の補助・設定の世代・週のふりかえり

## 何を解決するのか

**日本語の補助**（T-090）— 日本語の指示は**主語と対象が落ちやすい**。
「あれを直して」「いい感じにして」は、書いた側には自明でも受け取る側には決められない。
走り出してから食い違いに気づくと、そのターンぶんの時間と枠が丸ごと無駄になる。

**設定の世代**（T-095）— スキルや CLAUDE.md を直したあと「前のほうが良かった」と思っても
戻せない。Git に入っていれば済むが、**`.claude/` を commit していないプロジェクトは多い**。

**ふりかえり**（T-097）— 続けるための仕掛け。

## 振る舞い

### 日本語の指示の補助（T-090）

送る**直前**に見て、曖昧なら一度だけ聞く。**止めない**（そのまま送る選択肢を必ず出す）。

| 種類 | 例 | 聞き返すこと |
| --- | --- | --- |
| 対象の無い指示語 | 「それを直して」 | どのファイル・どの箇所か |
| 基準の無い言い方 | 「いい感じにして」 | 何をもって良しとするか |
| 対象も動詞も無い | 「直して」 | 何をどう直すか |
| 範囲が不明 | 「全部きれいに」 | どこまでが対象か |

- **対象がはっきり書かれていれば拾わない。** `` `src/a.ts` のこれを直して`` は曖昧ではない。
  パス・拡張子・`` ` `` ・「」・`関数()` があれば「示されている」とみなす
- **候補を決めつけない。** 「〇〇のことですか」ではなく、何が決まっていないかを言う
- 設定 `nimbus.clarifyVagueJapanese` で切れる。**既定は off**（送るたびに割り込むため・T-268）。判定と文言は残してあるので `true` で戻る

### 設定の世代（T-095）

- `.claude/` のファイルを保存したときに控えを残す
- **中身が同じなら足さない**（同じものが並ぶと、どれが違うのか分からなくなる）
- 1 ファイル 10 世代まで。古いものから落とす
- 世代の説明に**何行変わったか**を出す（戻す先を選べるように）

### 週のふりかえり（T-097）

コマンド **「Nimbus: 今週のふりかえりを見る」**（`nimbus.weeklyReview`）。

> セッション 3 本 · 12 ファイルに触りました · テストが 8 回通りました ·
> いちばん働いたのは Explore（5 回）

- **盛らない。** 実際に起きたことしか出さない。数字を大きく見せると、
  次に見たときに信用されなくなる
- **無かったものは書かない**（空欄を埋めるために作らない）

## 設計

- `extensions/nimbus/src/core/ambiguity.ts` — 曖昧さの判定。VS Code 非依存
- `extensions/nimbus/src/core/settingsHistory.ts` — 世代の管理。VS Code 非依存
- `extensions/nimbus/src/core/weeklyReview.ts` — 集計。VS Code 非依存
- `extensions/nimbus/src/extension.ts` — 送信前の確認・コマンド

`core/highlights.ts`（T-214・教材になるやり取りの切り出し）とは別物。
あちらは 1 セッションから見せ場を抜く話で、こちらは**週をまたいで数える**話。

### 実装中に踏んだ 2 つの不具合

1. **長さで切ると `no-target` が一度も効かない。** 「直して」は 3 文字なので、
   最小長を 4 にしていたときは拾えなかった。2 まで下げ、規則の具体性で誤検知を防ぐ形にした
2. **後続を縛りすぎると当たらない。** 「きれいに」の直後は「して」なので、
   `(?=[\sにでをと、。]|$)` のような先読みを付けると当たらない。
   多文字で具体的な語は、後続を縛らないほうが正しい

どちらもテストで固定してある。

## 受け入れ条件

- [x] 対象が書いてあれば指示語を拾わない（単体テスト）
- [x] 対象の無い指示語・基準の無い言い方・一言・範囲不明を拾う（単体テスト）
- [x] 「はい」「ありがとう」やはっきりした指示を拾わない（単体テスト）
- [x] 中身が同じなら世代を足さない（単体テスト）
- [x] 世代は上限まで、古いものから落とす（単体テスト）
- [x] 材料が無ければ「無い」と言う（単体テスト）
- [x] 無かったものは書かない（単体テスト）
- [x] 画面確認: 「それを直して」と打つと確認が出て、閉じれば送られない — GUI ケース `32-vague-instruction.mjs`
      ※聞き返しの文言そのものは画面から読めない（ネイティブダイアログのため）。文言は `core/ambiguity.ts` の単体テストで押さえてある。
      ここで見ているのは**判定が送信経路に実際に繋がっているか**と、**閉じたときに送られないか**

## 決めなかったこと・やらないこと

- **曖昧でも止めない。** 曖昧なまま進めたいこともある。確認は 1 回だけで、
  「このまま送る」を必ず出す
- **書き換えの提案はしない**（「〇〇のことですか」と候補を出さない）。
  決めつけると、違ったときに直す手間が増える
- **世代を Git に入れない。** `.claude/` を commit するかはプロジェクトの判断で、
  Nimbus が決めることではない
- **ふりかえりはセッションをまたがない。** 週の集計には永続化層が要る（T-034 の記録から
  作れなくはないが、プロジェクトをまたぐと意味が薄れる）
