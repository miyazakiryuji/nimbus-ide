# 読ませたくないファイルの指定

秘匿ファイルの遮断（[safety](safety.md) の T-164）を、`settings.json` を開かずに画面から
足し引きできるようにする（T-155）。

## 何を解決するのか

遮断そのものは既に動いている。問題は**編集経路**で、既定の一覧を外したり、自分の環境固有のもの
（社内の鍵置き場・顧客データの CSV など）を足すには設定ファイルを手で書くしかなかった。
**危ないものほど「設定ファイルを開いて書く」の一手間で後回しにされる。**

## 振る舞い

コマンド「読ませたくないファイルを指定する」（`nimbus.editProtectedPaths`）。

- いま有効な一覧を出す。設定が空のときは**既定の一覧を読み取り専用として見せる**。
  何が守られているのか分からないまま「守られているはず」と思うのが一番危ない
- `!` で始まるものは例外（読める）として区別して見せる（`.env.example` など）
- **足す** — glob を入力する。設定が空（既定を使用中）のときは、既定＋入力したものを自分の設定へ書く
- **既定を取り込む** — 既定の一覧を丸ごと自分の設定へ写す。既定そのものは壊さない
- **既定に戻す** — 自分の設定を空にする
- **外す** — 「読ませない」をやめる操作なので、**必ずモーダルで一度確認する**
- 保存先はグローバル設定（ワークスペースを開いていなくても使えるように）

## 設計

- `extensions/nimbus/src/protectedPaths.ts` — QuickPick と入力
- `extensions/nimbus/src/core/secrets.ts` — 既定の一覧と判定（[safety](safety.md)・読むだけ）
- 設定 `nimbus.safety.protectedPaths`

## 受け入れ条件

- [x] 既定を使用中でも、何が守られているかが一覧で見える
- [x] 例外（`!` 始まり）が区別して見える
- [x] パターンを足すと設定に保存される
- [x] 既定を取り込んでから編集できる／既定に戻せる
- [x] 外すときに確認が出る
- [ ] 画面確認（`nimbus/docs/testing/protected-paths.md`・未実施）

## 決めなかったこと・やらないこと

- **既定の一覧を直接編集させること** — 既定は製品の一部。触りたいときは取り込んでから
- **ワークスペース単位の保存** — 秘匿の設定は環境に紐づくものなので、まずグローバルに置く
