# うまくいった流れをスキルにする／預かり箱／ピン留めとタグ

## 何を解決するのか

**スキル化**（T-168）— うまくいった手順は、セッションが終われば消える。
次に同じことをするとき、また一から指示することになる。

**預かり箱**（T-151）— 席を外している間に回線が切れていた、というだけで
**打った文が消える**のが一番困る。

**ピン留めとタグ**（T-147）— タスクが増えると、板の中で目的のものを探すことになる。

## 振る舞い

### セッション → スキル化（T-168）

コマンド **「Nimbus: このセッションをスキルにする」**（`nimbus.sessionToSkill`）。

名前と「どんなときに使うか」を聞いて、`.claude/skills/<name>/SKILL.md` の**下書き**を作り、
エディタで開く。

書くのは**骨格まで**。中身を練るのは Claude の仕事なので、ここは
**エディタでないと分からないこと**だけを埋める:

- **手順** — 実際に出した指示を、出した順に。触ったファイルは
  「このとき触ったもの（参考）」として**括弧に入れる**（手順に焼き込むと別の場所で使えない型になる）
- **確かめかた** — 実際に走らせたテストと、そのときの結果
- **気をつけること** — 空欄（人が埋める）

**テストを走らせていないセッションでは「確かめかた」を捏造しない。**
「このセッションではテストを実行していません」と書く。確かめていないことを
確かめたと書くと、型として害になる。

**既にあるスキルは絶対に上書きしない**（「既にあります」と出して開くだけ）。

### 預かり箱（T-151）

- 送信が**繋がらない類の失敗**（`ENOTFOUND` / `socket hang up` / `fetch failed` など）で
  終わったとき、打った文を預かる
- 書き方の誤りや権限の問題は**預からない**（送り直しても同じ結果になる）
- 通知に「送り直す」ボタンを添える。コマンド **「Nimbus: 預かっている入力を送り直す」**
  （`nimbus.flushOutbox`）でも出せる
- **勝手には送らない。** 繋がった瞬間に自動で流すと、意図しない時点で走り出す
- 20 件まで。溢れたら**古いほうから落とす**（新しい指示のほうが今の状況に合っている）

### ピン留めとタグ（T-147）

- **ピン留め**（`nimbus.pinTask`）— 板の先頭に固定する。**待機列の優先度（T-233）とは別物**。
  優先度は「次に何を走らせるか」、ピン留めは「どれを目に入れておきたいか」
- **タグ**（`nimbus.tagTask`）— カンマ区切り。空にすると外れる。
  既に使われているタグを候補として出す（表記ゆれを防ぐ）

## 設計

- `extensions/nimbus/src/core/sessionToSkill.ts` — 下書きの組み立て。VS Code 非依存
- `extensions/nimbus/src/core/outbox.ts` — 預かる箱と、一時的な失敗かどうかの判定
- `extensions/nimbus/src/core/tasks.ts` — `sortForBoard()` / `filterByTags()` / `collectTags()`
- `extensions/nimbus/src/tasks/TaskService.ts` — `togglePinned()` / `setTags()`

スキル化は T-024（指示ごとの修正）と T-081（テストの証跡）をそのまま使っている。
同じ材料から別の出口を作っているだけなので、拾い直していない。

## 決めなかったこと・やらないこと

- **繋がったら自動で送らない**（T-151 の「繋がったら送る」の後半）。
  意図しない時点で走り出すほうが害が大きい。押せるところに置くまでにした
- **スキルの中身を Claude に書かせない。** 下書きを開いて人が整える。
  「うまくいった流れ」を型にするのは、何がうまくいったかを知っている人にしかできない
- **タグでの絞り込み UI は板側に無い。** 判定（`filterByTags`）は用意したが、
  板の描画は別セッションの持ち物なので、そちらの番で載せる
