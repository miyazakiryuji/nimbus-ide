# セッションの健康診断

## 何を解決するのか

台帳（`globalStorage/idris.nimbus/sessions/`）は 1 セッション 1 ファイル。持ち主は**心拍**で決まり、
5 秒ごとに書き直され、**20 秒**途切れたら手放したと見なす（`OWNER_TTL_MS`）。
落ちても壊れない作りの代わりに、**ウィンドウが落ちると持ち主のいない記録が残る**。

残っていること自体は壊れていない。困るのは**横断で数える手段が無い**ことだった。

- 画面はウィンドウの中しか出さない
- アプリ側の `sweep()` が落とすのは「持ち主がいないまま **7 日**」だけで、
  しかも **Nimbus が動いているときにしか走らない**

実際に手元の台帳を診たら、**14 時間前に落ちた `awaiting-input` の記録が 1 件**残っていた。

## 振る舞い

```bash
node nimbus/scripts/session-health.mjs            # 人が読む形式
node nimbus/scripts/session-health.mjs --json     # 機械が読む形式
node nimbus/scripts/session-health.mjs --dir <台帳のパス>
node nimbus/scripts/session-health.mjs --forget   # 「忘れてよい」ものだけ消す
```

残骸があれば終了コード **1**、無ければ 0。

### 仕分け

| 見立て | 条件 | 扱い |
| --- | --- | --- |
| 走行中 | 持ち主が生きていて `starting` / `running` | 触らない |
| 待機 | 持ち主が生きていて、走ってはいない | 触らない |
| 終了 | `completed` / `error` | **正常**。復帰の候補として残る（T-252） |
| 持ち主なし | 持ち主がいないのに終わってもいない | **残骸** |
| 忘れてよい | 持ち主がいないまま `FORGET_AFTER_MS`（7 日）超 | `--forget` の対象 |
| 重なり | 同じ `cwd` を生きた持ち主が 2 つ以上で持っている | 片方の前提が黙って壊れる |

**古いものを先に見る。** 忘れてよいものを残骸として二重に数えない。
**終了を残骸と読まない** — 終わった記録は「続きから」の材料なので、残っているのが正しい。

### 消す範囲を狭く固定する

`--forget` が触るのは**「忘れてよい」だけ**。走行中・待機・持ち主なしには触らない。
判定はアプリ側の `sweep()` と**同じ関数**（`forgettable()`）を通すので、
診断とアプリで線が食い違わない。

**「持ち主なし」は機械では決められない**ので、消さずに見せるだけにした ──
続きからやりたい仕事なら消すと `claudeSessionId` ごと失われ、
要らないなら残っていても 7 日で落ちる。どちらに転んでも、勝手に消す理由が無い。

## 設計

- 仕分けは `extensions/nimbus/src/core/sessionHealth.ts`（vscode 非依存・モジュールテスト 8 件）
- 線を引く関数（生きているか・走っているか・忘れてよいか）は
  `core/sessionRegistry.ts` を**使い回す**。ここで別の線を引かない
- スクリプト `nimbus/scripts/session-health.mjs` は**置き場所と出しかた**だけを持つ。
  置き場所は `product.json` の名前から組み立てるので、アプリ名を変えても追随する
- 読めない JSON は**数に混ぜず別に出す**（黙って捨てない）
- スキルは `.agents/skills/session-health/`

## 受け入れ条件

- [x] 持ち主の生死で、走行中と残骸を分ける（モジュールテスト）
- [x] 入力待ちでも、持ち主がいなければ残骸として数える（モジュールテスト）
- [x] 終わった記録は、持ち主がいなくても残骸にしない（モジュールテスト）
- [x] 同じフォルダの重なりを、生きた持ち主のあいだでだけ数える（モジュールテスト）
- [x] `--forget` が「忘れてよい」以外に触らない（作った台帳で実地確認 —
      走行中・持ち主なしを残し、古いものだけ消えることを確認）
- [x] 実際の台帳で残骸を検出できる（手元で 1 件検出）

## 決めなかったこと・やらないこと

- **定期実行にしない。** 残っていること自体は壊れていないので、毎回出すと
  「いつもの赤」になって効かなくなる
- **「持ち主なし」を自動で消さない**（上記）
- **`.observer.lock` のような外部ツールの残骸は見ない。** 生成元がリポジトリに無く、
  Nimbus の管轄外
- **ドクター（`doctor.mjs`）に混ぜない。** あちらはリポジトリを見るもので、
  手元の実行状態が診断結果に混ざると、CI で意味が変わってしまう
