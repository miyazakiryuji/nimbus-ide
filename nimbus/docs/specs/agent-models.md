# サブエージェントごとのモデル指定

## 何を解決するのか

サブエージェントの仕事は重さがまちまちで、「ファイルを探すだけ」に一番重いモデルを
使う理由はない。軽いモデルで足りるものを分けられれば、枠も費用も持つ。

対応する tasks.md の項目: T-232。

## 振る舞い

コマンド **「Nimbus: サブエージェントのモデルを決める」**（`nimbus.agentModels`）。

- `.claude/agents/*.md`（プロジェクト）と `~/.claude/agents/*.md`（利用者）を読む。
  **同じ名前があればプロジェクト側が勝つ**
- 一覧には、いまの割り当て → 定義ファイルの `model` → 「既定」の順で出す
- モデルの候補は**動いているセッションから引く**（`Query.supportedModels()`）。
  セッションが無ければ候補は空になり、その旨を出す
- 「既定に戻す」で割り当てを外せる
- 保存先は `nimbus.agents.models`（ワークスペース設定）。次のセッションから効く

## 設計

- `extensions/nimbus/src/core/agentDefs.ts` — 定義ファイルの読み取りと差し替えの組み立て。VS Code 非依存
- `extensions/nimbus/src/session/SessionManager.ts` — `supportedModels()`
- `extensions/nimbus/src/extension.ts` — 定義の探索・割り当ての UI・`buildOptions` への反映

### 割り当てが無ければ何も渡さない

SDK の `Options.agents` は**定義そのもの**を渡す形なので、モデルだけを差し替えるには
元の定義を読み直して組み立て直すことになる。つまり `agents` を渡した時点で、
**利用者が書いた定義は Nimbus が組み直したもので置き換わる**。

そのため、割り当てが 1 つも無ければ `agents` を渡さない。割り当てたものだけを載せる。
触らないほうが安全なので。

### YAML の完全な実装は持ち込まない

frontmatter に要るのは `key: value` と、カンマ区切り・角括弧のリストだけ。
そのために YAML パーサを依存に足す理由がない。

`description` と本文は SDK の `AgentDefinition` で必須なので、
**どちらかが空なら定義として扱わない**（空のまま渡すと相手が困る）。

## 決めなかったこと・やらないこと

- **`.claude/agents/*.md` を書き換えない。** 割り当ては Nimbus 側の設定に持つ。
  定義ファイルは利用者のもので、Nimbus が勝手に触るものではない
- **モデル名の妥当性は検証しない。** 使えるモデルはアカウントとプランで変わるので、
  候補はセッションから引き、手入力も許す
- **効果の比較（T-167）はここに含めない。** 割り当てられることと、
  どれが良いかを測ることは別の仕事
