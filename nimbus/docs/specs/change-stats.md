# 変更のようす

いまの変更を数え、テストが伴っていないときに静かに指摘する（T-159 / T-082）。

## 何を解決するのか

差分は「見た」つもりで見落とす。行数と触ったファイル数が分かるだけで、レビューにかける
時間の見積もりが変わる。あわせて**テストが伴っていない変更**に気づける形にする。
**止めはしない** — テストを書けない事情はある。気づける形にするだけ。

## 振る舞い

コマンド「変更のようすを見る」（`nimbus.openChangeStats`）。

- `git diff HEAD --numstat` を読む（staged / unstaged の両方を含む）
- 出すもの
  - 触ったファイル数・追加行数・削除行数
  - ファイルの一覧（変更の大きい順。テストには〈テスト〉と添える）
  - **テストが伴っていないとき**の指摘と、その対象
- バイナリ（`-` で来る行）は 0 として数える。数えられないものを数えたことにしない
- **ドキュメントや設定だけの変更では指摘しない**（`.md` / `.json` / `.ya?ml` / `docs/` など）。
  誤って指摘すると、その指摘自体が無視されるようになる
- 指摘には「書けない事情があるなら理由を `tasks.md` に 1 行残す」まで書く（README の作法と揃える）

テストとして扱うパス: `test/` `tests/` `spec/` `__tests__/` 配下、`*.test.*` / `*.spec.*`、
`*_test.dart`、`*_test.go`、`*Test.java`。
