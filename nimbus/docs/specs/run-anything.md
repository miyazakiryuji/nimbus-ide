# Run Anything

## 何を解決するのか

「何かを走らせる」入口が分かれている — シェルコマンドはターミナルを開いてから、IDE の操作は
コマンドパレットから。しかも**さっき打ったコマンドをもう一度打つ**のに、ターミナルの履歴を
遡る必要がある。IntelliJ IDEA の Run Anything と同じく、1 つの入口から打てるようにする。

## 振る舞い

### 開きかた

`Cmd+Alt+Shift+R`、またはコマンドパレットの `Run Anything`。

### 出るもの

| 並び | 内容 |
|---|---|
| 先頭 | **Run in Terminal: 入力した文字列**（入力があるとき） |
| Recent | 過去に走らせたもの（シェル・IDE コマンドの両方）を新しい順 |
| Commands | 一致する IDE コマンド（上限 10 件） |

**シェル実行の行が必ず先頭に来る。** 打った文字列をそのまま走らせるのがこの機能の主目的なので、
あいまい一致したコマンドに押し下げられてはいけない。

### 実行

- シェル — 新しいターミナルを作り、フォーカスして実行する
- コマンド — そのまま実行する

どちらも履歴に記録する。

### 履歴

`StorageScope.WORKSPACE` に保存（キー `nimbus.runAnything.history`）。上限 30 件。

- **同じものを再実行すると、古い方は消えて先頭に来る**（重複が溜まらない）
- シェルの `build` と IDE コマンドの `build` は別物として扱う
- 絞り込みはシェル文字列・コマンド ID・コマンド名のいずれにも当たる（大文字小文字を無視）

### エラー・境界

- 入力が空のときはシェル実行の行を出さない（空コマンドを走らせない）
- 壊れた履歴は読める分だけ残す

## 設計

| ファイル | 役割 |
|---|---|
| `contrib/runAnything/common/runAnything.ts` | 履歴の純粋関数（`addToHistory` / `filterHistory` / `parseHistory`）と上限値 |
| `contrib/runAnything/browser/runAnything.contribution.ts` | ピッカー、ターミナル実行、コマンド実行 |
| `contrib/runAnything/test/common/runAnything.test.ts` | 純粋関数のテスト（5 件） |

起動経路は `sessions.common.main.ts` の `// Run Anything` セクション。

各カテゴリが自前で絞り込むので、ピッカー側の照合は切ってある。

### 配色について

独自 CSS なし。カテゴリはセパレータ、種別はアイコン（ターミナル／履歴／コマンド）で区別する。

## 受け入れ条件

- [ ] `Cmd+Alt+Shift+R` でピッカーが開く
- [ ] `ls -la` と打って Enter でターミナルが開き、実行される
- [ ] もう一度開くと Recent に `ls -la` が出る
- [ ] Recent から選ぶと再実行され、先頭に移動する（重複しない）
- [ ] IDE コマンド名で絞ると Commands に出て、選ぶと実行される
- [ ] 入力が空のときシェル実行の行が出ない
- [ ] ウィンドウを再起動しても履歴が残る

確認記録は `../testing/run-anything.md`。

## 決めなかったこと・やらないこと

- **実行構成（Run/Debug configuration）は出さない** — セッションウィンドウではデバッグサービスが
  Null 実装なので、出しても選べない。デバッグを載せる判断をしたら足す
- **タスク（tasks.json）は出さない** — 同上で、まずシェルとコマンドで足りるか見る
- **実行中プロセスの管理はしない** — ターミナルに委ねる
- **既存のターミナルを再利用しない** — 走っているものを踏まないよう毎回新しく作る
