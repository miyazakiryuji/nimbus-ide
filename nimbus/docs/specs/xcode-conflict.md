# Xcode プロジェクトの衝突を解く

`project.pbxproj` の衝突を、両方のエントリを残す形で解く（T-199）。

## 何を解決するのか

`project.pbxproj` は「両側でファイルを足した」だけでも衝突する。中身は行の集まりなので
**たいていは両方残せば正しい**のに、手で直すと括弧や `isa` の並びを崩して Xcode が開かなくなる。
**壊しやすい割に、判断はほとんど機械的**という場所。

## 振る舞い

コマンド「Xcode プロジェクトの衝突を解く」（`nimbus.resolveXcodeConflict`）。

- ワークスペースの `*.pbxproj` を探す（`Pods` / `build` は除く）。複数あれば選ばせる
- 衝突の塊ごとに判定する
  - 両側とも**エントリを足しただけ**（24 桁の 16 進 ID で始まる行）→ 順序を保って両方残す。
    同じ行は 1 つに畳む
  - 構造（括弧・`isa` の並び）を触っていたら**解かない**
- **1 つでも解けない塊があれば、何も書き換えない。** 半端に直すのがいちばん危ない
- 書き換える前に**差分エディタで見せて、確認を取ってから**保存する（承認と同じ考え方）

## 設計

- `extensions/nimbus/src/core/pbxprojConflict.ts` — 解析と解決（VS Code 非依存）
- `extensions/nimbus/src/pbxprojConflict.ts` — ファイル選択・差分表示・保存

## 受け入れ条件

- [x] 衝突の塊を取り出す
- [x] 両側の追加を、順序を保って残す／同じ行は畳む
- [x] 構造を触っている塊は解かない
- [x] 1 つでも解けなければ何も書き換えない
- [x] 前後の行を保つ（マーカーだけが消える）
- [x] 適用前に差分を見せる
- [ ] 画面確認（実際の衝突で試す・未実施）

単体テスト: `extensions/nimbus/src/test/pbxprojConflict.test.ts`（8 件）

## 決めなかったこと・やらないこと

- **確認なしで保存すること** — プロジェクトファイルを壊すと Xcode が開かなくなる。必ず見せる
- **`.xcworkspace` や `Podfile.lock` の衝突** — 構造が違うので別の判定が要る
