# 共有マーケット — 入れる側（T-070）

**出す側は [skill-package](skill-package.md)。** T-070 は「出す」と「入れる」で
別のものになったので、2 つに分かれている。

| どちら | 何をするか | 形式 | 読むのは |
| --- | --- | --- | --- |
| 出す側（`core/skillPackage.ts`） | 自分のスキルを配れる形に整える | Claude Code のマーケットプレイス形式 | **Claude Code 自身** |
| 入れる側（`core/market.ts`・ここ） | 誰かが置いた一覧から探して入れる | Nimbus の配布物（T-043） | Nimbus |

**形式は揃えていない。** Claude Code が既に読める形式を Nimbus 専用に作り直すのは損だし、
配る中身も違う（片方はスキル、もう片方は設定を含む一式）。

---

## 新しい仕組みを足さない

配る中身は **T-043 の配布物（`core/bundle.ts`）そのまま**。
足りないのは「**どこに何があるか**」の一覧だけだった。

一覧は **JSON を 1 枚 `https` に置くだけ**。サーバーも登録も審査も要らないので、
Gist でも GitHub Pages でも成立する。OSS として出す方向と噛み合うのはこの形。

```json
{
  "name": "みんなの一覧",
  "entries": [
    {
      "id": "flutter-kit",
      "name": "Flutter 一式",
      "description": "Flutter 開発のスキルとサブエージェント",
      "url": "https://example.invalid/flutter.json",
      "author": "nimbus-community",
      "contains": { "skills": 3, "agents": 1 },
      "tags": ["flutter", "mobile"],
      "updated": "2026-08-01"
    }
  ]
}
```

`id` / `name` / `description` / `url` / `author` は**必須**。
とくに `author` を必須にしたのは、**出どころの分からないものを入れさせない**ため。

## 決めたこと

### `https` だけを通す

`url` が `https` でなければ**一覧ごと断る**。
ここを緩めると、**一覧を差し替えるだけで任意の場所から設定を入れさせられる**。

### 壊れた一覧を部分的に受け入れない

1 件でも形が違えば、その一覧は使わない。
一部だけ受け入れると「**入れたつもりが入っていない**」が起きる。

断るときは `entries[3].author がありません` のように**どこの何かまで言う**
（一覧を書く側が直せるように）。`id` の重複も断る（どちらが入ったか分からなくなるため）。

### 既定の一覧は空

出荷時にどこかを指しておくと、**「Nimbus が推している」ことになってしまう**。
誰の一覧を見るかは利用者が決める。

### 入れる前に「設定が含まれうる」と言う

配布物には `settings.json` が入りうる（`core/bundle.ts` の `BUNDLED_FILES`）。
つまり**他人の設定でこちらの承認方針が変わりうる**。

T-043 の取り込みは差分を見せてから当てるが、
**出どころが他人であることは、差分を見せる手前で言う**。
先に言わないと、差分を読む姿勢が変わらない。

### 一覧の 1 行に、出どころと中身を必ず添える

`nimbus-community · スキル 3 / サブエージェント 1 · 2026-08-01` のように出す。
**中身を開く前に判断できる**ようにするため。
記載が無ければ「中身の記載なし」と書く（無いものをあるように見せない）。

## 確認すること

- [x] 正しい一覧をそのまま読める
- [x] JSON でない・配列でない・`name` が無い、をそれぞれ理由つきで断る
- [x] 足りない項目を `entries[0].author がありません` の形で言う
- [x] `http` / `file` / `ftp` を断る
- [x] `id` の重複を断る
- [x] 500 件を超える一覧を断る
- [x] 名前・説明・作者・タグのどれでも探せる
- [x] 入れる前の警告に、設定・承認方針・取得元がすべて入る
- [ ] 画面確認: 実際の一覧 URL を指定して、探して入れるところまで通す

## やっていないこと

- **一覧を配る側の道具。** 一覧 JSON は手で書く前提。
  出す側の整形は [skill-package](skill-package.md) にある
- **評価・星・ダウンロード数。** 集めるにはサーバーが要る。
  サーバーを持たない形にしたので、そこは入れない
