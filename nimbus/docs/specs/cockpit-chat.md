# コックピットの作り（VS Code のチャットに寄せる）

## 何を解決するのか

コックピットは素の `textarea` と**プレーンテキスト**だった。応答は Markdown で返ってくるのに、
`**強調**` も箇条書きも記法のまま出て、コードは本文に溶けていた。出てきたコードを使うには
手で選び直して貼るしかなく、ツールの呼び出しは列に流れ続けて会話が読めなくなっていた。

VS Code のチャットと同じ作りに寄せる。作法が既に決まっているものを、わざわざ別の形にする理由がない。

## 検討: コア側のチャットを使わないこと

`src/vs/workbench/contrib/chat/` には完成したチャットがある（**932 ファイル**）。使わない。

- **ワークベンチ内部なので、拡張の webview からは参照できない。** 使うには Nimbus を拡張から
  ワークベンチの contribution へ作り替えることになり、フォークの作りごと変わる
- それはコアへ深く入る変更で、`// --- Start Nimbus ---` の中だけという約束と両立しない

**借りるのは構造値とテーマ色だけ**にした。`chat.css` から実測した値をそのまま使う ──
行の余白 `12px 16px`、アバターは 24px の丸、名前は 13px の semibold、
入力欄は「丸めた 1 枚の箱にツールバーが同居」。色は `chat.requestBackground` /
`chat.requestBorder` / `chat.avatarBackground` を参照し、持たないテーマのために既定を添える。

## 振る舞い

### 会話の列

| 出るもの | 見た目 |
| --- | --- |
| 依頼 | 人のアイコン＋「あなた」。行に地を敷いて応答と見分ける |
| 応答 | 雲のアイコン＋アシスタント名。**Markdown を描く** |
| 思考 | 畳んだ 1 行。読みたい人だけ開く |
| ツール呼び出し | 畳んだ 1 行。回っているあいだは印が回り、返ると ✓ / ✗ に変わる。**失敗したものだけ開いた状態で出す** |
| 実行中 | 「考えています… 12s」。経過を出すのは、止まっているのか動いているのか分からない時間が一番つらいため |
| エラー | エラー色の行 |
| 置いた仮定 | 従来どおり、本文とは別に囲って出す（T-186） |
| 承認 | 従来どおり、入力欄のすぐ上にカードで出す（T-266） |

### Markdown

**Webview では解析しない。** 拡張ホスト側（`core/chatMarkdown.ts`）で塊に分けてから渡す。

- ここなら VS Code に依存せず**単体で検証できる**（モジュールテスト 9 件）
- webview を「受け取った塊を DOM に写すだけ」に保てる。文字列を組み立てて `innerHTML` へ
  入れる作りにすると、応答やツール結果がそのまま HTML として解釈される余地が残る

対応するのは応答に実際に出てくるものだけ ── 見出し / 段落 / 箇条書き / 番号付き / 引用 /
区切り線 / コードブロック / インラインコード / 強調 / リンク / **表**（T-304）。

表は**区切り行（`| --- | --- |`）があるときだけ**表として読む。無いものは段落のまま流す
── `a | b` のような普通の文まで表に化けると本文が壊れる。描くときは横に溢れたぶんを
表の中でスクロールさせる（`md-table-scroll`・面ごと横に広げない）。

決めたこと 2 つ:

- **`_強調_` は採らない。** `snake_case` の識別子が頻繁に出るので、拾うと本文の意味が変わる
- **リンクは `http(s):` と `mailto:` だけ通す。** 通らないものは記法ごと文字として残す（消さない）

### コードブロック

言語名と、VS Code のチャットと同じ 4 つの操作を付ける。

| 操作 | 何が起きるか |
| --- | --- |
| 写す | クリップボードへ |
| エディタへ入れる | 開いているエディタの選択範囲を置き換える。開いていなければ**その旨を出す** |
| 新しいファイルにする | 言語 ID を推測して未保存の文書で開く（`ts` → `typescript` など） |
| ターミナルへ送る | **送るだけで実行はしない。** 改行を付けない |

ターミナルで実行までしないのは、押した瞬間に走ると取り返しがつかないため。
何が走るかを見てから Enter を押せるほうがよい（人間工学 E3）。

### 入力欄

丸めた 1 枚の箱に、添付・入力・ツールバーが同居する（VS Code と同じ）。

- **自動で伸びる**（最大 220px）
- Enter で送信 / Shift+Enter で改行（従来どおり）
- **送信⇄停止が入れ替わる。** 走っているあいだは停止だけが出る
- 📎 で画像を選ぶ。webview からはダイアログを開けないので**拡張側で開く**。
  貼り付け・ドロップも従来どおり効く
- **`/` で定型を引ける。** 中身は既にある「指示のテンプレート」。↑↓ で選び Enter で入る
- **↑ で送った文に戻れる**（入力欄の先頭にいるときだけ）
- 状態（セッション未開始 / 実行中・ターン数・費用）は**入力欄の中**に出す。
  送るときに要る情報なので、送信ボタンと同じ視野に置く（人間工学 E2 / E3）

### 空のとき

「◯◯ に頼む」の見出しと、書きかたの一行、頼みかたの例が 3 つ。
例は**押すと入力欄に入る**（押しても何も起きない飾りにしない・T-244）。

## 設計

- 解析は `src/core/chatMarkdown.ts`（vscode 非依存）。コードブロックの操作は `src/cockpit/codeActions.ts`
- 絵柄は **SVG を自前で持つ**。webview の CSP に `font-src` が無く codicon のフォントは読めない。
  外から何も読み込まないので、確実に出る
- コックピットとヘルプ（ゆあ）は**同じ実装**を使い回している。片方だけ直せない

### 文字の積み

`--vscode-font-family` も `--vscode-editor-font-family` も**日本語を名指ししていない**ので、
任せると字ごとに OS 依存で落ちる（typography T1）。表示言語を日本語にしてある以上、
落ち先を決めておかないと版が変わるたびに見え方が変わる。

| 用途 | 積み | なぜこの順か |
| --- | --- | --- |
| UI | `--vscode-font-family` → Hiragino Sans → Hiragino Kaku Gothic ProN → Noto Sans JP → Yu Gothic UI → Meiryo | 利用者のテーマ設定を先に立てる。日本語は macOS → Linux/同梱 → Windows の順で拾う |
| 等幅 | `--vscode-editor-font-family` → Hiragino Sans → Noto Sans JP → monospace | **macOS に日本語の等幅は無い**ので、日本語はプロポーショナルに落ちる。避けられないが、名指ししておけば**どの環境でも同じように落ちる** |

Hiragino Sans は W0〜W9 を持つので、名指しすれば `600`（`semiBold`）が**実体**で出る。
名指ししないと合成太字になり、画数の多い漢字が小さい字でつぶれる（typography T2）。

ツール出力を読ませる面（折りたたみの中身）は行間 `1.55`。
英数で決めた行間をそのまま当てると、日本語は詰まって見える（typography T3）。

### 実測でわかったこと

- **`display: flex` は UA の `[hidden] { display: none }` に勝つ。** 送信⇄停止を `hidden` で
  入れ替えていたが、停止ボタンが出っぱなしになっていた。`[hidden]` を明示で戻している

- [x] `/` で定型が出て、**選ぶと入力欄に入る**（GUI ケース 45）

- [x] 表を塊として読み、区切り行の無い縦棒は表にしない（T-304）— `表を塊として読む` /

- [x] `snake_case` が強調に化けない（モジュールテスト）
- [x] 危ない枠組みのリンクを `href` にしない（モジュールテスト）
- [x] ゆあの入力欄が従来どおり（GUI ケース 11）／曖昧な指示の聞き返しが従来どおり（GUI ケース 32）
- [ ] 応答が**並んだ状態**の見えかた（Markdown・コードブロック・ツールの折りたたみ）は
      実セッションが要るので `--with-claude` の経路で見る

## 決めなかったこと・やらないこと

- **コア側チャットの流用はしない**（上の「検討」）
- **`#ファイル` の参照は入れていない。** 定型（`/`）と添付で足りるか様子を見てから決める
- **応答の「やり直す」は入れていない。** 同じ指示を送り直すのは ↑ で戻せるので、
  二重に入口を作らない
- **コードの色付けはしない。** webview に文法解析を持ち込むと、この層が薄くなくなる

## 意匠は役割と段で決める（T-272）

値を目分量で決めない。**文字は役割、角丸は段**で選び、`:root` に控えを 1 か所だけ置く。

| 決めるもの | 書きかた |
| --- | --- |
| 文字 | `--nimbus-heading3` / `--nimbus-body1-2` / `--nimbus-label1-2`。太さは 400 と 600 だけ |
| 角丸 | `--nimbus-radius-control`（Control 4px・押すもの）/ `--nimbus-radius-inner`（Inner 6px・面の中の容器） |
| 文字の積み | `--nimbus-ui-font` / `--nimbus-mono-font`（[typography](typography.md)） |

- webview にはワークベンチの `--vscode-cornerRadius-*` が**届かない**ので、
  段の名前で書いて段の値を控えに置く（`var(--vscode-cornerRadius-small, 4px)`）。
  同じ数字がファイル中に散らないようにするのが目的
- **焦点の色（`focusBorder`）は焦点にだけ使う。** 承認カードが常時それを着ていたのをやめた —
  常時着ていると、本当に焦点があるときに区別がつかない（*Quiet at rest*）
- 依頼と応答の序列は、VS Code のチャットと同じ**依頼の行にだけ地を敷く**形（T-271）。
  自分の打った文が最も強く見えていた問題は、この作り替えで解けている
- 描画した Markdown の見出し（`h1`〜`h4`）だけは相対値のまま。本文に対する比を保ちたいので、
  役割トークンに寄せない
