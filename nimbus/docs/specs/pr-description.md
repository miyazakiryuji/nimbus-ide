# PR の説明文

コミットと差分から、レビューする人が知りたいところまでを埋める（T-220）。

## 何を解決するのか

レビューする側がまず知りたいのは「何のための変更か」「どこを見ればいいか」「確かめたか」の 3 つ。
このうち 2 つは機械で埋められるので、**埋まった状態から書き始められる**ようにする。

## 振る舞い

コマンド「PR の説明文を作る」（`nimbus.draftPrDescription`）。

- 比べる先は「[ブランチのようす](branch-health.md)」と同じ決め方（設定 → `main` → `master`）
- 題は、コミットが 1 つならその件名、複数ならタスク ID をまとめる。
  **決められないときは空にして人に書かせる**（それらしい題を捏造しない）
- 節の構成
  - **何のための変更か** — 空欄。「ここだけは機械では埋められません」と書いておく
  - **入っているもの** — コミットを分類して並べる（[リリースノート](release-notes.md)と同じ分類）
  - **どこを見ればいいか** — 触ったファイルを変更の大きい順に 10 件（テストには〈テスト〉）
  - **確かめたこと** — 空欄。テストが伴っていないときは⚠️で警告する
    （[変更のようす](change-stats.md)と同じ判定）
- Markdown の新規ドキュメントとして開く

## 設計

- `extensions/nimbus/src/core/prDescription.ts` — 組み立て（VS Code 非依存）
- `extensions/nimbus/src/prDescription.ts` — git の呼び出しとコマンド
- 分類は `core/releaseNotes.ts`、統計は `core/changeStats.ts` を使い回す

## 受け入れ条件

- [x] コミット 1 つならその件名、複数ならタスク ID を題にする
- [x] 決められないときは題を空にする
- [x] 「何のための変更か」は機械で埋めない
- [x] 入っているものを分類して並べる
- [x] 触ったファイルを大きい順に出す
- [x] テストが伴っていなければ説明文の中で警告する
- [ ] 画面確認（コマンドから開く・未実施）

単体テスト: `extensions/nimbus/src/test/prDescription.test.ts`（7 件）

## 決めなかったこと・やらないこと

- **変更の意図を推測して書くこと** — 嘘を書くくらいなら空欄のほうがいい
- **PR の作成そのもの** — `gh` に任せる。ここは本文を用意するところまで
