# 社内 Wiki / Notion へ出す

**タスク**: T-208 / **実装**: `extensions/nimbus/src/core/wikiExport.ts`（変換）,
`extensions/nimbus/src/wikiExport.ts`（VS Code 層） / **テスト**: `src/test/wikiExport.test.ts`

## なぜ

仕様書も ADR も、リポジトリの中にあるうちは**リポジトリを開ける人にしか届かない**。
社内 Wiki に貼れば届くが、そのまま貼ると 2 つの理由で壊れる。

1. **相対リンクが全部死ぬ** — `[pr-stack](pr-stack.md)` は Wiki 側では行き先が無い。
   読む人はリンクを踏んで、404 を見て、それきり読まなくなる
2. **社外に出せないものが混ざる** — 内部の URL・仮の判断が、そのまま社内 Wiki へ出る

## 貼るのは人

**出すのは貼れる形にするところまで。** どこに出すかはその組織の話で、機械が決めることではない。
Notion / Confluence へ直接投稿するには資格情報が要り、それを Nimbus が持つ理由が無い
（貼るか、MCP サーバー経由で出す）。

## 何をするか

| 段 | すること |
| --- | --- |
| front matter | 先頭の `---` 区画を落とす（Wiki 側では意味を持たない） |
| 内部向け | `<!-- internal -->` 〜 `<!-- /internal -->` を伏せる |
| リンク | 相対リンクを絶対 URL に直す |
| 題 | 最初の `#` 見出しを題として拾う |

### 伏せた跡は残す

`> （社内向けの記述をここから外しています）` に置き換える。
**黙って消すと、読む人は「そこに何かあった」ことすら分からない。**

### リンクは、直せるときだけ直す

`git remote get-url origin` から `https://github.com/owner/repo` を作り、
`blob/<ref>/<path>` へ向ける。画像は `raw/<ref>/<path>`（Wiki 側で画像として出るように）。

- **リポジトリの URL が分からなければ書き換えない。** 間違った行き先を作るより、
  「直せなかった」と数えて言うほうがよい
- `http://` などのスキーム付き、`//`、`#見出し` は触らない
- `../` は基準のパスから辿って畳む（`nimbus/docs/specs/` から `../../` は `nimbus/`）
- **remote に資格情報が混ざっていたら落とす** — `https://user:token@host/...` を貼らせない

## 出るもの

| コマンド | すること |
| --- | --- |
| `nimbus.exportToWiki`（社内 Wiki に貼れる形にする） | 開いている Markdown を変換し、写すか新しいエディタで開く |

`ref` は今いる枝（`git rev-parse --abbrev-ref HEAD`）。枝が消えるとリンクも切れるので、
長く残す文書はタグや `main` に切り替えてから出すのがよい。

## 確認項目

- [ ] front matter が落ちて、`#` 見出しが題として出る
- [ ] `<!-- internal -->` の中身が消え、跡の 1 行が残る
- [ ] 相対リンクが `blob/<枝>/<パス>`、画像が `raw/<枝>/<パス>` になる
- [ ] `https://` の外部リンクと `#見出し` が書き換わらない
- [ ] remote が無いリポジトリで、リンクが書き換わらず「直せなかった」件数が出る
- [ ] `https://user:token@github.com/owner/repo.git` から token が消える
