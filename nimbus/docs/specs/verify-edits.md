# 生成直後の型検証と自動ループ（T-101 / T-102）

ハルシネーション対策としていちばん強いのは「**書いた直後に、その場で型を当てる**」こと。
存在しない API を呼んだ・引数の数が違う・import を書き忘れた — どれも言語サーバーは
即座に知っている。素の Claude Code はビルドを回すまで気づけないが、フォークの中では
**編集した瞬間に診断が出ている**。[lsp-tools](lsp-tools.md) と同じ土台の上の応用。

## 振る舞い

1. Claude が `Edit` / `Write` / `MultiEdit` / `NotebookEdit` を使う
   → **その直前**の診断を控える（ファイルごとに 1 回）
2. ターンが終わる → 診断が落ち着くまで待って、もう一度取る
3. **そのターンで増えたエラーだけ**を取り出す
4. 既定（`ask`）では「いま書いたコードに型エラーが 3 件あります（2 ファイル）」と通知。
   **「差し戻す」**を押すと、場所つきの指摘がセッションへ送られる
5. `auto` にすると、確認せずに差し戻す（上限あり）
6. 通知を閉じてしまっても、コマンドパレットの**「型エラーを差し戻す」**（`nimbus.verifyEdits`）で拾い直せる

## 実装

- `extensions/nimbus/src/core/verifyEdits.ts` — 診断の差分と、渡す文の組み立て（純関数）
- `extensions/nimbus/src/editVerifier.ts` — `vscode.languages.getDiagnostics` と待ち合わせ
- `extensions/nimbus/src/extension.ts` — `tool-use` で控え、`turn-result` で確かめる
- テスト: `extensions/nimbus/src/test/verifyEdits.test.ts`

## 決めたこと

**「そのターンで増えたエラー」だけを渡す。** もともと赤かった箇所まで突きつけると、
頼んでいない修正が始まる。前後を比べ、増えた分だけを出す。

**同じ指摘かどうかに行番号を使わない。** 編集すれば行はずれる。`ファイル + 出どころ + 文言`で
見分け、同じ文言が元から N 件あれば N 件は既存として差し引く。

**既定では警告を対象にしない。** エラー（severity 0）だけ。直せと言うだけの根拠が無いものでループを
回すと、時間と金を使うだけになる。lint / analyzer の警告まで回したいときは
`nimbus.lsp.verifyIncludes` を `warnings` にする（情報・ヒントは入れない）。

## 編集 → 解析 → 再編集の自動ループ（T-102）

**この機能の `auto` モードが、そのままループになっている。**

1. Claude が編集する
2. ターンが終わる → 増えた指摘を集める
3. `auto` なら確認せずセッションへ差し戻す
4. Claude が直す → ターンが終わる → 2 へ

止まるのは「指摘が増えなくなったとき」か「`nimbus.lsp.maxAutoFixes`（既定 2 回）に達したとき」。
**回数上限は必ず要る** — 直らないまま回り続けるのが一番高くつく。上限に達したら通知して人に戻す。

`nimbus.lsp.verifyIncludes` を `warnings` にすると、lint / analyzer の指摘もこのループに乗る
（「人が見る前に整えておく」用途）。

**ターンの区切りまで待つ。** 途中で割り込むと、編集の途中経過を叩くことになる。
待ったあとも**診断が変化しなくなるまで**最大 4 回見る（言語サーバーは編集直後に古い結果を持っている）。

**自動差し戻しには上限を置く（既定 2 回）。** 直らないまま回り続けるのが一番高くつく。
上限に達したら人に戻す。

**既定は `ask`。** 黙ってトークンを使わない。自動で回してほしい人だけが `auto` にする。

**1 回に渡すのは 20 件まで。** 全部渡しても直せないし、最初の 1 件を直せば消えることが多い。

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `nimbus.lsp.verifyEdits` | `ask` | `off` / `ask`（通知して選ばせる）/ `auto`（自動で差し戻す） |
| `nimbus.lsp.verifyIncludes` | `errors` | `errors` / `warnings`（lint の警告まで回す・T-102） |
| `nimbus.lsp.maxAutoFixes` | `2` | 自動差し戻しの上限（1 セッションあたり） |

## 残っていること

- **T-102 編集 → 解析 → 再編集の自動ループ**は、この上に lint / analyzer を足す形になる
- 回数の数え直しは「新しいセッション」単位。人が手で指示を出したときには戻らない
- サブエージェントの編集は拾えない（`parent_tool_use_id` のある `tool-use` は正規化の時点で落ちている）
