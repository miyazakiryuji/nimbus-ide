# 板をウィンドウ横断で持つ（担当・進捗・点検）

**タスク**: T-259 / T-260 / T-261 / T-262 /
**実装**: `extensions/nimbus/src/core/taskSync.ts`（判断）, `extensions/nimbus/src/taskStore.ts`（読み書き）,
`extensions/nimbus/src/tasks/TaskService.ts`（配線）, `media/board.js`（表示） /
**テスト**: `src/test/taskSync.test.ts`, `src/test/taskStore.test.ts`,
`nimbus/tests/gui/cases/41-task-registry.mjs` /
**土台**: [session-registry](session-registry.md)

## なぜ

板（カンバン）の状態は `TaskService` のメモリと Memento（`globalState`）にしか無かった。
Memento はウィンドウごとに読み込まれるので、**別のウィンドウで足したタスクが見えない**。
セッションの台帳（T-247）と同じ問題が、板にもそのまま在った。

並列で走らせることが Nimbus の狙いである以上、板は「その窓のメモ」ではなく
「全員が見る 1 枚」でなければ意味がない。

## 置き場所と書きかた（T-259）

`<globalStorage>/tasks/<taskId>.json` に 1 件ずつ。進捗は
`<globalStorage>/tasks/<taskId>.progress.jsonl` に**追記だけ**。
どちらもセッションの台帳と同じ形で、理由も同じ —
**1 つのファイルに全部入れると、同時に書いた分が黙って消える**
（[実測](../testing/parallel-load.md)）。

突き合わせは 5 秒ごと。ファイルを正として、**`updatedAt` の新しいほうを勝たせる**。
どちらが正しいかを機械が決められない以上、最後に触ったほうを採るのがいちばん驚きが少ない。

「消された」と「まだ書いていない」は取り違えると事故になる（消えたことにして
作ったばかりのタスクを捨ててしまう）。前回の突き合わせでディスクに在った ID を覚えておき、
**在ったものが消えていれば削除、無かったものは新規**として扱う。

## 担当を残す（T-260）

タスクを開始したウィンドウを `ownerWindowId` に残す。板が横断になった以上、
「別の窓が走らせている」ことが分からないと二重に開始できてしまう。
担当セッションが生きているかは、セッションの台帳の心拍で見る（T-247）。

## 進捗を追記する（T-261）

タスクの中に、起きたことを 1 行ずつ足していく。

| 種別 | いつ | 例 |
| --- | --- | --- |
| `note` | 作ったとき | 作成（nimbus/fix-login） |
| `start` | 開始したとき | 開始（セッション 3f2a…） |
| `file` | 書き込み系のツールを使ったとき | /w/app/lib/main.dart |
| `turn` | ターンが終わったとき | 直しました。テストは通っています |
| `done` | 完了したとき | 完了（WIP 8a91…） |

板のカードには**最新の 1 行だけ**出す。全部は「Nimbus: タスクの進捗を見る」で開く。
途中で止まったときに「どこまで何をしたか」が残っていることが目的なので、
書けなかったことで作業は止めない。

## 点検（T-262）

板の「点検」ボタン（コマンド: `nimbus.checkTasks`）で、止まっているタスクを洗い出す。

| 出る理由 | 判定 |
| --- | --- |
| `owner-gone` | 作業中・承認待ちなのに、担当セッションがもういない |
| `no-progress` | 走っていることになっているが、30 分なにも記録されていない |
| `never-started` | 待機のまま 30 分動いていない |
| `done-but-left` | 完了なのに worktree が残っている |

**直しはしない。** 出すところまでで、どうするかは人が決める。
機械が勝手に「完了」にしたり worktree を消したりすると、生きている作業を巻き込む。

## 決めなかったこと

- **ファイル監視で即時に反映する**のはやらない。板は人が見るものなので 5 秒で足り、
  監視は「自分の書き込みで自分が起こされる」ループの始末が要る（複雑さに見合わない）
- **タスクの本文（prompt）を後から編集できるようにする**のはここでは扱わない。
  横断で持つようになった以上、編集の衝突をどう見せるかを先に決める必要がある
