# セッションをたどり直す

やり取りを、**間隔つき**で並べ直す（T-206）。

## 何を解決するのか

記録をそのまま読むと、**間が抜け落ちる**。「ここで 8 分止まっていた」「ここは 3 秒で 3 ファイル
触った」は、時間の情報が無いと分からない。詰まった場所を探すときに効くのは、中身より**間隔**。

## 振る舞い

コマンド「セッションをたどり直す」（`nimbus.openReplay`）。

- 直近のセッションを時刻順に並べ、**前のステップからの間隔**を各行に添える
- **止まっていたところ（3 分以上空いた場所）を先に出す**
- 間隔は読める形にする（`即` / `45 秒後` / `10 分後`）
- 本文は 800 字で切る（長いまま並べると読めなくなる）
- 時刻の無い記録は並べない（間隔が出せないため）

**再生ボタンは付けない。** 実際に待たされても意味がなく、見たいのは「どこで止まっていたか」。

## 設計

- `extensions/nimbus/src/core/replay.ts` — 並べ直しと間隔の計算（VS Code 非依存）
- `extensions/nimbus/src/replay.ts` — 記録の読み込みとコマンド

- [x] 時刻の無い記録を並べない
- [x] 3 分以上空いたところを「止まっていた」として先に出す
- [x] 間隔を読める形にする
- [x] 長い本文を切り詰める
- [ ] 画面確認（自分の記録で開く・未実施）

単体テスト: `extensions/nimbus/src/test/replay.test.ts`（8 件）

## 決めなかったこと・やらないこと

- **実時間での再生** — 待たされるだけで、分かることは増えない
- **複数セッションの同時再生** — 並べても混ざるだけ。1 本ずつ見る
