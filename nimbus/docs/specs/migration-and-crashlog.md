# 他ツールからの移行・ワンクリック導入・実機ログ

## 何を解決するのか

**移行**（T-068）— Cursor / Copilot から移ってくる人にとって、いちばん高い壁は**書き直し**。
指示書は書式が違うだけで、中身はそのまま使えることが多い。

**ワンクリック導入**（T-071）— 他の人の環境をそのまま試したい。

**実機ログ**（T-074）— クラッシュログを貼っても、そのままでは長すぎて文脈を食うだけ。
欲しいのは「**どこで落ちたか**」で、それは**自分のコードのフレーム**にしか無い。

## 振る舞い

### 他のツールから取り込む（T-068）

コマンド **「Nimbus: 他のツールから設定を取り込む」**（`nimbus.importFromOtherTools`）。

| 元 | 先 |
| --- | --- |
| `.cursorrules` / `.cursor/rules` | `CLAUDE.md` |
| `.github/copilot-instructions.md` | `CLAUDE.md` |
| `.windsurfrules` | `CLAUDE.md` |

- **置いてあるものだけ**を候補にする
- **中身は変換しない**（Markdown はどのツールでも Markdown）。置き場所を合わせるだけ
- **既存を書き換えず、末尾に足す。** 見出しに出どころと日付を書くので、
  あとから「これは Cursor から持ってきたもの」と分かる
- 同じ日に二度取り込んでも重ねない

### ワンクリック導入（T-071）

コマンド **「Nimbus: URL から配布物を入れる」**（`nimbus.installFromUrl`）。

- **`https` だけ**を受け付ける。`http:` や `file:` を通すと、
  「リンクを押しただけ」で意図しないものが入る経路になる
- 取ってきたものは**手元のファイルと同じ検査**を通す（T-043 の読み込みと同じ道）

### 実機ログ（T-074）

コマンド **「Nimbus: クリップボードのクラッシュログを調べてもらう」**（`nimbus.pasteCrashLog`）。

- Dart / Flutter・JS / TS・Swift / Kotlin / Java / Python / Ruby / Go のスタックトレースを読む
- **自分のコードのフレームだけ**を先に出し、ライブラリとランタイムは畳む
- **全文は渡さない。** 長い全文を渡すと文脈を食うだけで、読むべき場所は結局その中の数行
- 自分のコードのフレームが 1 つも無ければ、**無いと言う**（無いものをあるように見せない）
- 「まず上の行を開いて読み、原因の見当を述べてください。直すのはその後です」まで書く

## 設計

- `extensions/nimbus/src/core/importSettings.ts` — 候補の判定・追記・URL の検査。VS Code 非依存
- `extensions/nimbus/src/core/crashLog.ts` — スタックトレースの解析。VS Code 非依存
- `extensions/nimbus/src/extension.ts` — コマンド

### `dart:` の誤判定

自分のコードかどうかを見るのに `dart:` を「ライブラリの印」として使ったところ、
**`login_page.dart:42` の中の `dart:` に当たって**、自分のファイルをライブラリと
誤判定した。直前が単語文字とドットでないときだけ拾うよう直してある（テストで固定）。

## 決めなかったこと・やらないこと

- **書式の変換はしない。** Cursor の MDC ヘッダなど独自の記法はそのまま残す。
  機械的に読み替えると、意図が変わったことに気づけない
- **URL から直接展開しない**（T-071）。ブラウザで開いて保存させ、
  中身を見てから T-043 の読み込みで入れてもらう。押しただけで入るのは危ない
- **クラッシュログのファイルドロップは付けていない。** クリップボードで足りる。
  画像のドロップ（T-040）とは経路が違うので、混ぜていない
