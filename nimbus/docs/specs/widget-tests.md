# Widget テスト / ゴールデンテストの生成

開いている Dart から、Widget テストとゴールデンテストの雛形を作る（`tasks.md` T-193）。

## 何を解決するのか

**「テストを書いて」と頼むだけなら Claude Code 単体でできる。**エディタの上に乗る意味は、
Claude が持っていない事実をこちらが持っていることにある。

- いまどのファイルを開いているか
- その package の名前（`pubspec.yaml`）と、モノレポならどれが自分の package か
- Dart / Flutter の規約でテストをどこに置くべきか
- **その widget のコンストラクタが実際にどんな引数を取るか**

引数を取り違えた雛形は、そのままでは通らない。通らない雛形は結局書き直しになるので、
「それらしいものを出す」ことに価値は無い。

## 振る舞い

エディタの右クリック（`.dart` のときだけ）または `Nimbus: Widget テストの雛形を作る`。

1. 開いているファイルから `StatelessWidget` / `StatefulWidget` を継承したクラスを探す
2. 複数あれば選ばせる（引数の一覧を説明に出すので、目当てのものを選べる）
3. 「Widget テストだけ」か「見た目の比較（ゴールデン）も作る」かを選ぶ
4. `lib/a/b.dart` → `test/a/b_test.dart` に書き出して開く

**既にテストがあるときは、絶対に上書きしない。**「開く」だけを出す。
書いたテストが消えるのが一番困るので、ここは確認ではなく禁止にしてある。

### 引数の埋めかた

型から「とりあえず通る値」を作る。

| 型 | 入れる値 |
| --- | --- |
| `String` | `'テキスト'` |
| `int` / `num` | `0` |
| `double` | `0.0` |
| `bool` | `false` |
| `List<...>` / `Map<...>` | `const []` / `const {}` |
| `VoidCallback` / `Function` | `() {}` |
| `Widget` | `const SizedBox()` |

**分からない型は埋めない。**`null /* TODO: UserRepository を渡す */` を残す。
それらしい値を入れて「通ったつもり」にさせるほうが害が大きい。

`key` は雛形に出さない（Flutter 側の作法で、テストからは渡さない）。

### 読み取りの範囲

Dart の完全なパーサは持たない（持つべきでもない）。雛形を作るのに足りるだけを読む。

- コメント・文字列の中の `class` には引っかからない
- 名前つき `{...}` と位置引数の両方を読む。`required` を見る
- `this.foo` は型が書かれていないので、同じクラスの `final String foo;` から型を補う
- 総称型のカンマで引数を割らない（`Map<String, int> x` は 1 つ）
- **読み切れないものは黙って諦める。** 中途半端に埋めるより「引数はご自身で」が安全

## 設計

- `extensions/nimbus/src/core/widgetTests.ts` — 読み取りと雛形づくり（VS Code 非依存・単体テスト 13 件）
- `extensions/nimbus/src/flutterTests.ts` — エディタ側（開いているファイル・package の特定・書き出し）

モノレポでは**いちばん近い `pubspec.yaml`** を package の根として扱う。
ワークスペースの先頭フォルダを根と決め打つと、複数 package のリポジトリで壊れるため。

## 決めなかったこと・やらないこと

- **テストの中身を書く** — 「何を確かめるか」は人と Claude の仕事。雛形は
  `expect(find.byType(X), findsOneWidget)` と TODO までに留める。
  中身まで自動で埋めると、読まれないテストが増えるだけになる
- **`golden_toolkit` などの外部パッケージ前提** — 標準の `matchesGoldenFile` だけを使う。
  依存を増やす判断は利用者のもの
- **解析サーバ（LSP）を使った厳密な読み取り** — 正確にはなるが、Dart の解析サーバが
  立ち上がっていない場面でも雛形は作れてほしい。正規表現で足りる範囲に留めた
  （T-098 の LSP ツールが安定したら、そちらに寄せる余地はある）
