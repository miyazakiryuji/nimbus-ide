# デバッガ連携（T-104）

原因特定の精度を決めるのは「**実行時の実際の値**」が見えるかどうか。ソースを何度読ませても
「この変数が null になっている」は分からない。Nimbus はデバッグアダプタが繋がっている
IDE のフォークなので、止まっている場所のコールスタックと変数の値をそのまま渡せる。

素の Claude Code には無い情報で、`tasks.md` の選ぶ基準 2 に真っすぐ当てはまる。

## 何が入るのか

MCP サーバー `nimbus_debug`（ツール名は `mcp__nimbus_debug__*`）。

| ツール | 何を返すか |
| --- | --- |
| `debug_stack` | 停止中のコールスタック（`#0` から順に・場所つき） |
| `debug_variables` | その位置で見えている変数の名前・型・値（スコープごと） |

停止していないときは「ブレークポイントを置いて止めてからもう一度呼んでください」と返す。
取れなかったことを黙って空で返さない。

## 実装

- `extensions/nimbus/src/core/debugState.ts` — DAP の応答を読めるテキストにする（純関数）
- `extensions/nimbus/src/debugTools.ts` — `vscode.debug` と DAP の `customRequest`
- `extensions/nimbus/src/extension.ts` — `buildOptions()` で全セッションに渡す
- テスト: `extensions/nimbus/src/test/debugState.test.ts`

停止判定には `vscode.debug.activeStackItem` を使う。**止まっているときだけ立つ**ので、
「セッションはあるが走っている」を弾く判定を兼ねられる。

## 決めたこと

**読むだけ。式の評価（`evaluate`）は入れない。** 式は副作用を持ちうる
（`user.delete()` を評価できてしまう）のに、`mcp__nimbus_` で始まるツールは
承認を通らずに実行される（`permissions.ts`）。**「値を見る」と「コードを走らせる」を
同じ扱いにはしない。** 入れるなら、承認を通す経路を先に用意する。

**`expensive` なスコープは開かない。** グローバル全体のような重いスコープを展開すると、
デバッグアダプタが数秒止まることがある。

**フレームは 20 まで、変数は 1 スコープ 40 まで、値は 300 文字で切る。**
深い再帰や巨大なオブジェクトを丸ごと渡しても読めないし、文脈を溶かす。

**値は 1 行に均す。** 改行を含むオブジェクトがそのまま入ると、変数 1 つで画面が埋まる。

**引数を省いたときは、利用者がデバッグビューで選んでいるフレームを見る。**
人が見ている場所と、エージェントが見る場所を揃える。

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `nimbus.debug.exposeState` | `true` | デバッガの状態を読めるツールとして渡す |

## 確認すること

- [ ] ブレークポイントで止めて `debug_stack` を呼ぶと、スタックが場所つきで返る
- [ ] `debug_variables` が、その位置のローカル変数を値つきで返す
- [ ] `frame` を指定すると、そのフレームの変数に切り替わる
- [ ] 止まっていないときは「止めてから呼んでください」と返る
- [ ] デバッグビューでフレームを選んでから引数なしで呼ぶと、選んだフレームが出る
- [ ] 巨大なオブジェクトを持つ変数でも出力が破綻しない
- [ ] `nimbus.debug.exposeState` を `false` にするとツールが渡らない
