# 作業の様子を GIF にする

画面を撮りためて、貼れる 1 枚にする（T-223）。

## 何を解決するのか

「こう動いた」を伝えるのに、文章とスクショ 1 枚では足りないことがある。
かといって画面録画を渡すと、相手は再生ボタンを押さないといけない。
**GIF は貼れば動く** — Issue にも、チャットにも、そのまま置ける。

## 振る舞い

コマンド「作業の様子を GIF にする」（`nimbus.exportGif`）。

- 長さ（10 / 20 / 30 / 60 秒）と細かさ（10 / 5 / 2 fps）を選ぶ
- 撮る前に、**枚数とできあがりの大きさの見込み**を出す
- 撮っている間は画面を触ってよい（止める操作もできる）
- 撮り方は**ホットリロードと同じ設定**（`nimbus.hotReload.screenshotCommand`）。撮り方を 2 つ持たない

### 枚数を先に見積もる

GIF は 1 枚ずつ画像を持つので、30 秒 × 10 fps は 300 枚になる。**貼れないほど
大きいファイルができ、それに気づくのは作り終えたあと**。だから先に計算する。

- 上限は **120 枚**（横 800 px で 1 枚 100 KB として約 12 MB。GitHub の添付は 10 MB まで）
- 超えるときは **長さを守り、滑らかさを落とす**。長さを削ると、見せたかった操作の途中で切れる
- **1 fps でも収まらない長さ**（120 秒超）だけは、長さを削る。**削ったと言う**

> 実装中に見つけた誤り: 最初の版は「fps を落とせたか」で分岐していたため、
> 300 秒を頼まれると「1 fps に落としました」と言いながら**実際には 120 秒しか撮らない**のに
> 「300 秒」と答えていた。**枚数で分岐する**ように直し、境目（ちょうど 120 秒 / 121 秒）の
> テストを足した。

### 組み立て

`ffmpeg` に任せる。**色は 1 度作って使い回す**（`palettegen` → `paletteuse`）。
既定の 256 色に落とすだけだと、画面の文字が汚れて読めなくなる。

`ffmpeg` が無ければ、**撮ったフレームは消さずに**、そのまま打てるコマンドを出す。
撮り直しをさせない。

## 設計

- `extensions/nimbus/src/core/gifExport.ts` — 枚数の見積もりと `ffmpeg` の引数（VS Code 非依存）
- `extensions/nimbus/src/gifExport.ts` — 撮影と組み立て

## 受け入れ条件

- [x] 長さと細かさを選べる
- [x] 撮る前に枚数と大きさの見込みを出す
- [x] 上限を超えたら滑らかさを落とし、落としたと言う
- [x] 1 fps でも収まらない長さは、長さを削って、削ったと言う
- [x] 撮れた枚数で答える（頼まれた枚数ではなく）
- [x] `ffmpeg` が無ければ、撮ったものを残して手順を出す
- [ ] 画面確認 — **自動化しない**。画面を録るコマンドの設定が要り、実際に数十秒録ることになる

単体テスト: `extensions/nimbus/src/test/gifExport.test.ts`（10 件）

## 決めなかったこと・やらないこと

- **自前の GIF 符号化** — `ffmpeg` のほうが色が良い。持たない
- **動画（mp4）** — 貼って動くのが GIF の値打ち。動画は再生操作が要る
- **撮り方の実装** — ホットリロードの設定を使う。撮り方を 2 つ持たない
