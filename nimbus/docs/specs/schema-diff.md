# マイグレーションを起こす

スキーマの差分から `ALTER TABLE` を起こし、壊す操作を先に見せる（T-125）。

## 何を解決するのか

スキーマファイルを直したあと、**同じ変更を手で `ALTER TABLE` に書き直す**。
この写経で間違えると、本番のデータが消える。しかも間違いは、流すまで分からない。

## 振る舞い

コマンド「マイグレーションを起こす」（`nimbus.openMigrationPlan`）。

- `.sql` を選び、**Git に入っている版（HEAD）といまの版**を見比べる
- 出すもの
  - **先に読む — 戻せない変更** — 列や表が消えるもの、**型が変わるもの**。
    危なさの判定は [sql-safety](sql-safety.md) と同じ物差し（`inspect`）を使う
  - **手順** — `足す → 型を変える → 消す` の順。途中で止めても戻せるように
- **`NOT NULL` を既定値なしで足すときは、その場で言う** — 既存の行があると失敗する。
  手元の空のテーブルでは通り、本番で落ちる、いちばん多い落とし穴
- **走らせない。** 出すのは手順だけ

**SQL パーサは持ち込まない。** 表・列・型・`NOT NULL`・`DEFAULT` だけを見る。
索引・制約・トリガーは見ないので、**「これで全部」とは書かない**（報告の末尾に明記する）。

## 設計

- `extensions/nimbus/src/core/schemaDiff.ts` — 読み取り・差分・整形（VS Code 非依存）
- `extensions/nimbus/src/schemaDiff.ts` — ファイル選択と HEAD の取得

## 受け入れ条件

- [x] `CREATE TABLE` から表と列を読む（`DECIMAL(10, 2)` のカンマで割らない）
- [x] 表の制約（`PRIMARY KEY` など）を列として数えない
- [x] 足す・型を変える・消す をすべて拾う
- [x] 流す順は 足す → 変える → 消す
- [x] 消す変更と型の変更を「戻せない」に入れ、手順より先に出す
- [x] `NOT NULL` を既定値なしで足すときに注意を出す
- [x] 「これで全部とは限らない」と書く
- [ ] 画面確認（実際のスキーマで試す・未実施）

単体テスト: `extensions/nimbus/src/test/schemaDiff.test.ts`（11 件）

## 決めなかったこと・やらないこと

- **流すこと** — 生成物をそのまま流すための道具ではない。見落としを減らすためのもの
- **索引・制約・トリガー** — 見ない。中途半端に拾うと「全部見た」と誤解される
