# 組織ポリシーとプラグイン API

対応するタスク: T-212（権限管理・企業導入向け）・T-092（Nimbus 自体のプラグイン API）。

どちらも「**外から Nimbus の振る舞いを変える**」話で、向きが逆。
片方は組織が**狭める**ため、もう片方は他の拡張が**足す**ため。
どちらも「どこまで許すか」を最初に決めないと、あとから塞げなくなる。

---

## T-212 組織ポリシー

会社で入れるとき、いちばん困るのは「**設定でいくらでも緩められる**」こと。
`nimbus.policy.profile` も `permissions.alwaysAllow` も利用者が書き換えられるので、
「本番に触るときは全部確認する」と決めても、**その場で外せてしまう**。

### 上限として扱う

設定 `nimbus.managedPolicy` に置かれたものを**上限**にする。
利用者の設定は「それより狭くする」ぶんだけ効き、**広げる方向は効かない**。

| 書けるもの | 効きかた |
| --- | --- |
| `allowedProfiles` | 一覧に無いポリシーを選べない。選ばれていたら**一覧の先頭へ落とす** |
| `enforceBlockProtectedReads` | 秘匿ファイルの遮断を外せない |
| `forbidAlwaysAllow` | 自動許可を一切認めない |
| `allowedAlwaysAllow` | 認めたルールだけ残す（利用者が減らすぶんには触らない） |
| `enforceAudit` | 監査ログを止められない |
| `requiredProtectedPaths` | 必ず遮断する。**`!` で打ち消してあっても外す** |
| `contact` | 制限の問い合わせ先（利用者に見せる） |

**置かれていなければ何も変わらない。** 既定は無管理。

### 読む場所を 1 か所に決めた

`nimbus.managedPolicy` は **`"scope": "machine"`** にしてあり、
読むのは**ユーザー設定の値だけ**（`inspect().globalValue`）。

**ワークスペース設定を見てはいけない。** 見ると、
`.vscode/settings.json` を含むリポジトリを開かせるだけで制限を外せる。
読む場所が散ると、そのうち 1 か所が漏れるので `src/managedPolicySource.ts` に集めた。

### 黙って変えない

制限が効いて選択が変わったときは、**必ず理由をログに出す**。
起動時にも、効いている制限を一覧で出す。

「なぜか設定が戻る」が一番たちが悪い。**見えない制限を作らない。**

### 拒否ではなく、狭める

使えないポリシーが選ばれていたら、**エラーで止めずに一覧の先頭へ落とす**。
止めると何も動かないが、落とせば決められた範囲で動く。

## T-092 プラグイン API

`activate()` の戻り値を公開面にする。

```ts
const nimbus = vscode.extensions.getExtension('nimbus.nimbus')?.exports as NimbusApi | undefined;
context.subscriptions.push(
  nimbus!.registerContext('acme.tools', { kind: 'context', id: 'branch', label: 'ブランチの決まり' },
    () => 'main へ直接 push しない')
);
```

### 足せるのは 2 つだけ

| 種類 | 何ができるか |
| --- | --- |
| `context` | セッションへ渡す前提を足す（**読ませるもの**） |
| `action` | コックピットから呼べる指示を足す（**作らせるもの**） |

**権限の判断には触らせない。** `core/risk.ts` / `core/secrets.ts` /
`core/permissionRules.ts` に手を入れる口は開けない。
ここを開くと、**拡張を 1 つ入れただけで承認の意味が消える**。

### 決めたこと

- **名前は必ず拡張 ID で namespace を切る**（`acme.tools/branch`）。
  誰が足したものか分からないと、動きがおかしいときに切り分けられない
- **`id` を `nimbus` で始めさせない** — 本体のものと紛れる
- **1 拡張 20 件まで** — 無制限にすると一覧が使えなくなる
- **断るときは例外にする。** 黙って無視すると、拡張を書いている人が気づけない
  （Nimbus の中は見られないので、理由まで文に入れる）
- **1 拡張 16KB まで**。超えたら切り、**切ったことを本文に書く**（黙って切ると嘘になる）
- **2 秒で返らない拡張は諦める。** 1 つが返らないせいで送信が止まらないようにする。
  転んでも Nimbus は止めないが、**ログには必ず残す**
- **文脈には出どころを添える。** 妙な前提が入ったとき、どの拡張を外せばいいかが分かる

### 版

`version: 1`。増やすときは上げる（使う側が分岐できるように）。

## 確認すること

- [x] 管理設定が無ければ、判断が一切走らない
- [x] 使えないポリシーが一覧の先頭へ落ち、理由が付く
- [x] 遮断・監査は、設定で切られていても組織の指定が勝つ
- [x] `!` で打ち消された遮断パスが外れる
- [x] 自動許可は**狭める方向に触らない**（利用者が減らしても「変えた」と言わない）
- [x] 拡張 ID・`id`・`label` の不正をすべて理由つきで断る
- [x] 同じ `id` の二重登録を断り、別の拡張なら同じ `id` を通す
- [x] 上限を超えた登録を断る（他の拡張のぶんは数えない）
- [x] 長すぎる文脈を切り、切ったと本文に書く
- [ ] 画面確認: `nimbus.managedPolicy` をユーザー設定に置き、ポリシー切り替えが制限されることを見る
- [ ] 画面確認: 実際に別の拡張から `registerContext` して、前提が渡ることを見る

## やっていないこと

- **設定画面への表示。** いまは起動時のログにしか出していない。
  `describeManagedPolicy()` が一覧を返すので、設定ビューに載せるのは配線だけ
- **入れ子の設定説明の取り込み。** `nimbus.managedPolicy` の子項目の説明は
  `package.nls.json` に取り込まれない（`nls-extract.mjs` は 1 階層しか見ない）。
  英語を配ると決めたときに直す
