# スキル・サブエージェント・コマンドを書く支援

## 何を解決するのか

スキル・サブエージェント・スラッシュコマンドは、先頭の YAML frontmatter を 1 文字間違えると
**黙って読み込まれない**。動かないことにも気づけないし、気づいても理由が分からない。
書いたあとに試す手段も無く、実際のセッションで使ってみるまで分からない。

対応する tasks.md の項目: T-030（フロントマター補完つきエディタ）/ T-031（プレビュー実行）。

## 振る舞い

### 補完と検証（T-030）

対象は置き場所で決まる:

| 場所 | 種類 | 必須 |
| --- | --- | --- |
| `**/skills/<name>/SKILL.md` | スキル | `name` `description` |
| `**/agents/<name>.md` | サブエージェント | `name` `description` |
| `**/commands/<name>.md` | コマンド | `description` |

- **frontmatter の中でだけ**補完を出す（本文では出さない）
- **既に書いたキーは候補に出さない** — 重複キーは後勝ちで事故る
- 必須のものを上に出し、**値の例まで入れる**（キーだけ出しても、何を書くかで手が止まる）
- 開いたときと保存したときに検証し、**足りないものを名指しする**。
  「読み込まれません」だけでは直せない
- `description` が短すぎるときは**警告**（止めはしない）。
  `description` は「どんなときに使うか」を読んで呼び出しが決まるので、短いと呼ばれない
- 本文が空のものはエラー（frontmatter だけでは何もしない）

### 試し打ち（T-031）

コマンド **「Nimbus: いま開いているスキル／サブエージェントを試す」**（`nimbus.previewSkill`）。
`.claude/` 配下の Markdown を開いているときは右クリックからも出る。

- **読み込まれない状態では走らせない。** 必須が欠けていたら、その旨を出して止める
  （読み込まれない状態で試しても何も分からない）
- 渡す内容を聞いて、**使い捨てのセッション**で走らせる
- **`plan` モードで走らせる。** 試し打ちのつもりでファイルが変わるのが一番困る
- 応答を Markdown で開く（渡した内容とモードも書く）

## 設計

- `extensions/nimbus/src/core/frontmatter.ts` — 種類の判定・補完候補・検証。VS Code 非依存
- `extensions/nimbus/src/authoring.ts` — 補完プロバイダ・診断・試し打ち
- `extensions/nimbus/src/extension.ts` — 登録

## 決めなかったこと・やらないこと

- **値の補完はしない**（`allowed-tools` にツール名の候補を出す、など）。
  ツールの一覧はセッションからしか分からず、書いている最中に無いことが多い
- **YAML の完全な検証はしない。** 必須キーと本文の有無まで。
  完全な検証には YAML パーサが要るが、そこまでの表現力を使っていない
- **試し打ちの結果を保存しない。** 繰り返し確かめたくなったら T-165（回帰テスト）の仕事
