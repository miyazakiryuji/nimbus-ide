# 送信したプロンプトを直す（T-363）

**送ってしまった指示を、送り直せるようにする。** 打ち間違い・言い足りなさに気づいたとき、
いまは新しい発言で言い直すしかなく、間違った指示で書き換わったファイルはそのまま残る。

利用者依頼（2026-08-31）: 「送ったプロンプトを修正出来ない。GitHub Copilot みたく、ワンクリックで
修正をできるようにしたい。もちろん、修正が出来るということは、そのプロンプトで修正された内容は
もとに戻るという警告がでるということです。これは GitHub Copilot を参考に作成してください」

**Copilot に合わせる**（利用者の判断 2026-08-31）— 本文だけでなく**添付とモデルまで復元する**。

## Copilot の実装（推測ではなく、同梱の upstream ソースから読んだもの）

Nimbus は Code - OSS のフォークなので、Copilot Chat 側の「Edit Request」の実装が
`src/vs/workbench/contrib/chat/` にそのまま入っている。**そこを読んで写した。**

| 段階 | Copilot の挙動 | 出どころ |
| --- | --- | --- |
| **入口** | 設定 `chat.editRequests` = `inline`（既定）/ `hover` / `input` / `none`。`inline` では**発言そのものがクリックできる**（ホバーで「Click to Edit」） | `chat.shared.contribution.ts:812-817` / `chatListRenderer.ts:3923-3956` |
| **押した瞬間** | **壊さない。** `setCheckpoint(id)` で印を付けるだけ（以降のターンが「消える予定」に見える）。入力欄に**本文・添付・モデル**を戻す | `chatWidget.ts:1855-1935` |
| **添付の戻しかた** | `request.attachedContext` ＋ `element.variables` を重複排除して戻す。**workspace 変数と、自動で足されたプロンプトファイルは戻さない**（利用者が付けたものだけ） | `chatWidget.ts:1871-1893` |
| **モデル** | `requestModelByIdentifier(currentElement.modelId)` でその発言のときのモデルへ戻す | `chatWidget.ts:1919-1921` |
| **送信** | ここで初めて壊す。`restoreSnapshotWithConfirmationByRequestId` が確認を出してから巻き戻す | `chatEditingActions.ts:354-425` |
| **確認を出す条件** | **その発言以降で実際に変更されたファイルがあるときだけ。** 0 件なら黙って通す（`shouldPrompt = 変更ファイル > 0 && config('chat.editing.confirmEditRequestRemoval')`・既定 true） | 同 `:380-381` |
| **確認の文面** | 1 ファイルなら**ファイル名を名指し**、複数なら「**N 件のファイル**への変更を元に戻します」。消える依頼が 1 件か複数かでも言い分ける（4 通り） | 同 `:383-396` |
| **取り消し** | `finishedEditing()`。セッション切り替え・Escape で**非破壊に**抜ける | `chatWidget.ts:1999` |
| **クリックを無視する場面** | リンクの上／テキストを選択しているとき／コードブロックの中で選択しているとき | `chatListRenderer.ts:3929-3951` |

**いちばん大事なところ**: **鉛筆を押した時点では何も壊れない。** 壊れるのは送信を押したとき。
だから「編集を始めたけどやめた」で何も失われない。

## Nimbus での決めごと

### 入口

- 利用者の発言（`.turn.user`）**そのものを押すと編集に入る**（Copilot の `inline` と同じ）。
  ホバーで「押すと直せます」のツールチップを出す
- **押しても編集に入らない場面**は Copilot に合わせる — リンクの上・**テキストを選択しているとき**・
  コードブロックの中。とくに選択は T-339 で直したばかりなので、ここを壊さない
- 走っている最中は**入口を出さない**（初版）。`interrupt()` はツールの書き込み完了までは保証しないので、
  止め切る前に巻き戻すとファイルが壊れる。停止してからなら直せる

### 編集に入ったとき（壊さない）

- 本文・**添付**・**モデル**を入力欄へ戻す。添付は利用者が付けたものだけ（自動で足したものは戻さない）
- それ以降のターンに「消える予定」の印を付ける（薄くする）。**この時点では消さない**
- Escape・別のセッションへ移動・面を閉じる、で**非破壊に**抜ける

### 送信したとき（ここで初めて壊す）

順番を守る。**止め切ってから測り、測ってから確認し、確認してから壊す。**

1. セッションが走っていれば止め、`awaiting-input` 相当になるまで待つ
2. `dryRun` で影響を測る（`rewindFiles(uuid, dryRun: true)`）
3. **確認を出す** — 消える発言の数・戻すファイルの数・`+N / -M`。
   **戻すファイルが 0 件なら確認を出さない**（Copilot と同じ）
4. 確認が取れたら巻き戻す
5. **完全に成功したときだけ**、会話を切り詰めて新しい本文を送る

### 失敗したときと、途中で止まったとき

- `dryRun` が失敗 → **編集状態を保ったまま**理由を出す。会話は消さない
- 巻き戻しが失敗 → **会話を消さない・新しい指示も送らない。** 理由を出して編集状態に留まる
- 巻き戻しは成功したが送信に失敗 → 本文を下書きへ逃がし、「巻き戻し済み・未送信」と分かる形で残す
- **`skippedLinks`（SDK が安全のため戻さなかったもの）が 0 でなければ、成功と呼ばない** —
  「一部戻せませんでした」として名指しで出す。`dryRun` にはこの値が返らないので、
  事前の見積もりと実結果がずれうる

### 直せる発言・直せない発言

**見た目が利用者の発言であることだけでは足りない。** 次を全部満たすものだけを直せる。

- 実際に利用者が送った発言（合成メッセージ `isSynthetic` は不可）
- SDK の `userMessageId`（チェックポイント）が結び付いている
- まだ処理されていないキュー内の発言ではない

直せない発言には**鉛筆を出さないだけでなく、理由を言う** — 「この発言は戻る先が残っていません」。
黙って押せないボタンは、壊れているのと同じ。

**表示用の `user-text` と、SDK 由来の `checkpoint` は別のイベント**（`events.ts` / `normalize.ts`）。
本文や時刻が近いことで結び付けると、**同じ文を 2 回送ったときに壊れる**。
1 つの利用者ターンの id として明示的に結ぶこと。

**送信前に Nimbus が足している文（API シグネチャ・grounding）は、利用者の原文と分ける。**
編集欄へ戻すのは利用者が書いたものだけ。

### 並行セッションとの兼ね合い（Nimbus 固有）

Copilot には無い事情。**セッション A のチェックポイントは、セッション B が後から入れた変更を知らない。**

- `dryRun.filesChanged` を `SessionFilesTracker` と突き合わせ、
  **他のセッションが触っているファイルが混ざっていたら名指しで警告する**
- `SessionFilesTracker` はツール呼び出しからの推定であって、内容のハッシュまでは見ていない ＝
  完全な鍵ではない。警告までに留め、止めるかどうかは利用者に決めてもらう
- VS Code 側の**未保存のバッファ**も見る。ディスクを戻しても、古いバッファが後から上書きしうる

## 実装（初版・2026-08-31）

**入口と非破壊まで入れた。** 走行中の停止・添付とモデルの復元は次の波。

- `core/checkpoints.ts` の `pairUserTurns()` — 画面の発言と戻り先を**並び順で明示的に結ぶ**。
  本文で突き合わせると、同じ文を 2 回送ったときに取り違える（モジュールテスト 2 本で固定）
- `media/cockpit.js` の `makeEditable()` — 利用者の発言そのものを押せるようにする。
  リンク・コード・**文字を選んでいるとき**は編集に入らない（T-339 を壊さない）
- `extension.ts` の `editRequest()` — 走行中は断る / 戻り先が無ければ**理由を言う** /
  `dryRun` で測る / **戻すファイルがあるときだけ**確認 / 成功したときだけ本文を戻す
- 守りは GUI ケース 68（入口・選択中は入らない・押しても会話が消えない）と
  モジュールテスト（対応付け）

**まだ入っていない**（仕様には書いてある）:
- 添付とモデルの復元（`Checkpoint` が本文しか持っていないので、器から作る必要がある）
- 会話の切り詰め（`rewindFiles` はファイルしか戻さない・T-364 で文言は正した）
- 走行中の「停止して直す」（いまは断るだけ）
- 並行セッションとの重なりの警告
