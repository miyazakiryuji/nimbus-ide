# どこで壊れたかを絞り込む

二分探索で犯人のコミットを見つける（T-183）。

## 何を解決するのか

`git bisect` は強力だが、始めるまでの手間（good / bad をどう決めるか、何回かかるか）で
使われないまま終わる。**残り回数と次に見る場所を先に出す**ことで、始めやすくする。

## 振る舞い

コマンド「どこで壊れたかを絞り込む」（`nimbus.bisect`）。

- 初回: 壊れていないと分かっている地点を入力する（既定 `HEAD~20`）。そこから HEAD までが候補
- 毎回出すもの
  - 候補のコミット数と、**残り何回で決まるか**（`log2`）
  - 次に確かめるコミットの `git checkout` 行
- 2 回目以降: 「再現しなかった（good）／再現した（bad）／やめる」を選ぶと範囲が狭まる
- 範囲が詰まったら「壊れた場所が決まりました」と `git show <hash>` を出す
- 状態はワークスペースに保存する（セッションをまたいでも続きから絞れる）

**git を勝手に動かさない。** チェックアウトは利用者が自分で行う — 走っている他のセッションの
作業ツリーを黙って動かすのは危ないため。

## 設計

- `extensions/nimbus/src/core/bisect.ts` — 次に見る位置・残り回数・収束の判定（VS Code 非依存）
- `extensions/nimbus/src/bisect.ts` — git の呼び出しと状態の保存

## 受け入れ条件

- [x] 次に見るのは範囲の真ん中
- [x] 残り回数を log2 で見積もる
- [x] good / bad で範囲が正しく狭まる
- [x] 範囲が詰まったら犯人を確定して `git show` を出す
- [x] 何度か狭めれば必ず 1 つに決まる
- [ ] 画面確認（実際に絞り込む・未実施）

単体テスト: `extensions/nimbus/src/test/bisect.test.ts`（7 件）

## 決めなかったこと・やらないこと

- **チェックアウトの自動実行** — 並列でセッションが走っているときに作業ツリーを動かすと壊れる
- **`git bisect` そのものの利用** — git 側の状態を持つと、途中で放置したときに戻せなくなる
