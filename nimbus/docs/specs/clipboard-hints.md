# コピーしたエラー文に気づく（T-170）

エラーが出たとき、人はまずエラー文をコピーする。そこから検索したり、エージェントに貼ったりする。
**その「貼る」だけを省く。**

ただしクリップボードは、パスワードも個人情報も通る場所。覗くこと自体を利用者が選べないと
いけないので、**既定は無効**にしてある。

## 振る舞い

`nimbus.clipboard.suggestOnError` を有効にすると:

1. **ウィンドウに戻ってきた瞬間**だけ、クリップボードを見る（常時監視はしない）
2. 中身がエラー文らしければ「コピーした内容がエラーのようです（12 行）。調べますか？」と聞く
3. **「調べる」**でコックピットへ投入。**「今後は聞かない」**でその場で無効に戻せる

**通知に中身は出さない。** 行数だけを見せる。

## 実装

- `extensions/nimbus/src/core/clipboardHints.ts` — エラーらしさの判定と文面（純関数）
- `extensions/nimbus/src/clipboardHints.ts` — ウィンドウの焦点とクリップボード
- テスト: `extensions/nimbus/src/test/clipboardHints.test.ts`

## 決めたこと

**既定は無効。** タスクの但し書きは「オフにできること」だったが、**オンにできること**の側にした。
クリップボードを読む機能は、既定で有効にしてよいものではない。

**常時監視しない。** VS Code にはクリップボードの変更イベントが無い。定期的に読むこともできるが、
それは「ずっと覗いている」のと同じ。**ウィンドウに戻ってきた瞬間**に 1 回だけ読む。

**迷ったら反応しない。** 目印（`Traceback` / `XxxError:` / `panic:` / `error[E0308]:` など）が
あるか、スタックトレースとして 2 段以上読めるときだけ。関係ないコピーのたびに聞かれると、
通知ごと切られる。

**同じ内容で二度聞かない。** 見たものは覚えておく。

**短すぎる・長すぎるものは相手にしない。** 1 語のコピーや、ファイル丸ごとの貼り付けは対象外。

## 確認すること

- [ ] 既定では、何をコピーしても何も起きない
- [ ] 有効にしてスタックトレースをコピーし、ウィンドウに戻ると聞かれる
- [ ] 通知にエラーの中身が出ない（行数だけ）
- [ ] 「調べる」でコックピットに投入される
- [ ] 「今後は聞かない」で設定が無効に戻る
- [ ] 普通の文をコピーしても聞かれない
- [ ] 同じ内容のまま戻ってきても、二度は聞かれない

## 残っていること

- 「コピーした瞬間」ではなく「戻ってきた瞬間」（VS Code にイベントが無いため）
- エディタ内でのコピーと、外部アプリでのコピーを区別していない
