# 命名と重複

同じ概念に別の綴りが使われている箇所と、そっくりな実装を見せる（T-178 / T-137）。

## 何を解決するのか

どちらも「間違ってはいないが、増えると効いてくる」たぐいのもの。人は気づけないし、
**エージェントは周りに揃えるのが得意なので、揺れた状態を見せると揺れを増やしてしまう**。

## 振る舞い

コマンド「命名と重複を見る」（`nimbus.openCodeHealth`）。

- ワークスペースのソースを最大 400 ファイル読む（`node_modules` / `out` / `dist` /
  `build` / `.dart_tool` / `vendor` は除外）
- **命名** — 宣言されている名前を語に割り、並びが同じものを 1 つの概念として集める。
  綴りが 2 通り以上あるものだけを、多い順に出す（どちらに寄せるかの材料になる）
  - `getUserName` と `get_user_name` は同じ概念
  - **定数（`MAX_SIZE`）と変数（`maxSize`）は別の慣習**として扱う。混ぜると `PNG` と `png` の
    ような正しい組が延々と挙がり、指摘そのものが読まれなくなる
- **重複** — 連続する 6 行が**完全に一致する**塊だけを出す。似ているだけのものは出さない
  （誤検知のほうが害が大きい）。半分以上が中身の無い行（閉じ括弧・コメント・import）なら数えない
- 直すかどうかは人が決める。出力にもそう書く

### 危ない書き方（T-202）

エージェントが書くコードは**動くように書かれる**。動けばいいなら、検証を切るのも、文字列を
繋いで SQL を作るのも早い。そこを人が毎回読むのは続かないので、機械で拾う。

| 見るもの | 代わりに |
| --- | --- |
| 証明書の検証を切っている | 検証したまま繋ぐ。自己署名なら、その証明書だけ信頼する |
| 組み立てた文字列をシェルに渡す | `execFile` に配列で渡す（シェルを通さない） |
| 文字列を繋いだ SQL | プレースホルダとパラメータ |
| MD5 / SHA-1 | SHA-256。パスワードなら bcrypt / argon2 |
| `Math.random()` | 鍵・トークンには `crypto.randomUUID()` |
| `eval` / `new Function` | 実行しない形（JSON など） |
| `http://` | `https://`。相手が非対応なら記録に残す |

- **断定しない。** 実際に危ないかは文脈による（テスト用かもしれない）。「なぜ危ないか」と
  「代わりに何を使うか」を添えて、判断は人に渡す
- **当てられても困らない用途は拾わない** — `checksum` の `md5`、`jitter` の `Math.random()` など
- テストや例のファイル、コメント行は見ない
- 出力ではいちばん上に置く。読みにくさより先に見たいため

### 層の逆流（T-138）

- **`core/` が `vscode` を取り込んでいたら違反**として挙げる。これは Nimbus 自身の約束で、
  破ると「拡張ホストなしで検証できる」というテスト戦略が成り立たなくなる
- 違反には**なぜ駄目なのかを 1 文**で添える。理由が無いと直せない
- 違反が無ければ、その節ごと出さない

### 重いところ（T-136）

- ファイルごとに**分岐の数・いちばん深い入れ子・中身のある行数**を数え、重い順に並べる
- 分岐は `if` / `for` / `while` / `case` / `catch` / `&&` / `||` / 三項演算子
- コメントと空行は数えない
- **数字は良し悪しの判定ではない**と出力に明記する。同じ物差しで比べるためのもの

### 古くなっているコメント（T-210）

コードは直っているのにコメントが直っていない、は静かに効く。**読む人は本文よりコメントを
信じる**し、エージェントも同じで、古い前提を正として次を書いてしまう。

- `@param` に書かれているのに**引数に無い**名前を挙げる。逆（書かれていない引数）は普通に
  あるので言わない
- コメントの中のファイル参照が**存在しない**場合を挙げる。末尾一致で照合する
  （相対パスで書かれることが多く、厳密に解決すると誤検知だらけになる）
- **コメント行だけを見る。** ソース中の正規表現や文字列にも `@param` は現れるので、
  素通しにすると自分自身を指摘する（実データで出た）
- `.md` への参照は突き合わせない。`CLAUDE.md` のようにコード以外の場所にあるものが多く、
  相手がいないのに「見つかりません」と言ってしまう（これも実データで出た）
- **文章の意味は見ない。** そこまで判定しようとすると誤検知が増え、指摘ごと読まれなくなる

### 使われていない export（T-112）

- どこからも `import` されていない `export` を挙げる
- **2 つに分ける** — 分けないと、外し忘れの `export` に本当の死骸が埋もれる
  - **どこでも使われていない** — 消す候補
  - **自分のファイルの中でしか使っていない** — 死んではいないが `export` を外せる
    （「必要になるまで公開しない」というコーディング規約に沿う）
- `extension.ts` / `index.ts` / テストは入口として扱い、挙げない（外から呼ばれるため）
- 名前だけで突き合わせる。同じ名前がどこかで使われていれば「使われている」と見なす
  （誤って「死んでいる」と言うほうが害が大きい）
- `import { type Skill }` のインライン修飾子も読む。**見落とすと型の import がすべて
  「使われていない」に化ける**（実データで 136 件出て気づいた）

## 設計

- `extensions/nimbus/src/core/codeHealth.ts` — 命名と重複の判定（VS Code 非依存）
- `extensions/nimbus/src/core/deadCode.ts` — 使われていない export の判定（VS Code 非依存）
- `extensions/nimbus/src/core/structure.ts` — 複雑度と層の判定（VS Code 非依存）
- `extensions/nimbus/src/core/commentCheck.ts` — 古いコメントの判定（VS Code 非依存）
- `extensions/nimbus/src/core/vulnScan.ts` — 危ない書き方の判定（VS Code 非依存）
- `extensions/nimbus/src/codeHealth.ts` — ファイル収集とコマンド

構文解析はしない。言語ごとにパーサを持つと保守できないため、行の並びと識別子の綴りだけで見る。

## 受け入れ条件

- [x] camel / snake / Pascal を同じ概念として集める
- [x] 定数と変数を混ぜない
- [x] 綴りが 1 通りしか無いものは出さない
- [x] 行が完全に一致する塊だけを出す（1 行違えば別物）
- [x] import だけの塊を数えない
- [x] 使われていない export を「死骸」と「export を外せるだけ」に分ける
- [x] 入口（extension / index / テスト）を挙げない
- [x] `core/` からの `vscode` 取り込みを違反として挙げ、理由を添える
- [x] 分岐・入れ子・行数を数え、重い順に並べる
- [x] 引数から消えた `@param` と、存在しないファイル参照を挙げる
- [x] コメント以外の行を見ない／`.md` を突き合わせない
- [x] 危ない書き方を拾い、断定せず代わりの手を書く
- [x] 当てられても困らない用途（checksum の md5 など）を拾わない
- [ ] 画面確認（コマンドから開く・未実施）

単体テスト: `codeHealth.test.ts`（10 件）・`deadCode.test.ts`（9 件）・`structure.test.ts`（7 件）・`commentCheck.test.ts`（10 件）・`vulnScan.test.ts`（11 件）
実データでの確認（2026-08-13）: この拡張の 122 ファイル・識別子 1972 件に対して命名の指摘は 0 件、
重複は 8 件（ツリービューの定型と、記録の読み込み）を検出した。**自分が書いた重複も見つかった。**
使われていない export は、分類前 94 件 → 本当の死骸 2 件・`export` を外せるだけ 92 件。
ここでも**自分が書いた未使用の型**（`ClaudeMdFile`）が挙がったので消した。
層の違反は 0 件（`core/` は VS Code に依存していない）。古いコメントは、誤検知を潰す前は
43 件出ていたが、上の 2 つの除外を入れて 7 件（すべて説明用の例示）まで減った。重いところの上位は
`extension.ts`（分岐 253・1304 行）で、配線が 1 か所に集まっていることが数字に出た。

## 決めなかったこと・やらないこと

- **自動で直すこと** — 共通化は設計判断。機械が勝手にやると、意味の違うものまでまとめる
- **似ているだけの検出（類似度）** — しきい値の調整に終わりが無く、誤検知が増える
