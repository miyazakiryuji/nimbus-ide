# ふりかえり（週次ダイジェスト・成長ログ）

過去の記録から「何をしたか」を数えて Markdown で開く（T-207 / T-047）。

## 何を解決するのか

何を作ったか・どこに時間を使ったかは、やっている最中には見えない。週の終わりに数字で
見られると、次の週の決め方が変わる。**推測はしない** — 記録に無いことは出さない。

## 振る舞い

コマンド「ふりかえりを開く」（`nimbus.openDigest`）。

- 期間を選ぶ（直近 7 日／直近 30 日／今日）
- 開いているフォルダに対応する記録（`~/.claude/projects/…`）の**直近 40 本**を読む
- 出すもの
  - 出した指示の数・返ってきた応答の数
  - 動いていた日（日付を並べる）と、**いちばん長く続いた連続日数**（T-096）
  - よく使ったツール（多い順・上位 5 件）
  - よく触ったファイル（多い順・上位 5 件。プロジェクト相対に縮める）
- Markdown の新規ドキュメントとして開く（ファイルには保存しない）
- **時刻を持たない記録は数えない。** 期間で切れないものを混ぜると数字が嘘になる
- 記録が無い期間は「この期間の記録がありません」とだけ書く
- 8MB を超える記録は飛ばす

**評価は書かない**（「よく頑張りました」等）。数字を並べるだけにして、判断は見た人に任せる。

## 設計

- `extensions/nimbus/src/core/digest.ts` — 集計と Markdown 化（VS Code 非依存）
- `extensions/nimbus/src/digest.ts` — 記録の読み込みとコマンド
- `extensions/nimbus/src/core/transcripts.ts` — 記録の解析（[claude-md](claude-md.md) の提案機能と共用）

## 受け入れ条件

- [x] 期間内の指示・応答・稼働日を数える
- [x] 期間より前のもの、時刻を持たないものを数えない
- [x] ツールとファイルを多い順（同数なら名前順）に出す
- [x] パスをプロジェクト相対に縮める
- [x] 記録が無い期間はその旨だけを書く
- [x] 連続して動いた日数の最大を数える
- [ ] 画面確認（コマンドから開いて表示を見る・未実施）

単体テスト: `extensions/nimbus/src/test/digest.test.ts`（8 件）
実データでの確認（2026-08-13）: 直近 7 日で指示 39 件・応答 793 件・稼働 3 日、
よく使ったツールは Bash / Edit / Write の順、という結果を得た。

## 決めなかったこと・やらないこと

- **ファイルに保存すること** — 見て捨てるもの。残したければ利用者が保存すればいい
- **コストの集計** — 使用量は [usage](usage.md) が持っている。二重に持たない
- **「詰まったところ」の推定** — 記録から機械的に判断できない。推測は書かない
