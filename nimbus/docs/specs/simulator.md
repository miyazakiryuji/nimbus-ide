# シミュレータ操作

**タスク**: T-073 / **実装**: `extensions/nimbus/src/core/simulator.ts`（判定）,
`extensions/nimbus/src/simulator.ts`（VS Code 層） / **テスト**: `src/test/simulator.test.ts`

## なぜ

「実装できました」と「画面が動きました」の間には距離がある。
型が通ってもテストが通っても、**押したら落ちる**ことはいくらでもある。

## タップを座標で代行しない

`simctl` に座標タップの口は無く、座標を打つ道は**画面が変わるたびに壊れる**。
Flutter には `integration_test` があるので、**要素の名前で押す**形に落とす。
そのほうが壊れにくく、**資産として残る** — 一度テストになれば、次からは人が押さなくていい。

## 1. 画面を撮って渡す

`xcrun simctl io <udid> screenshot` で撮り、パスをセッションへ渡す。
起動していない端末は先に `simctl boot` する。macOS 以外では、その旨を伝えて終わる。

**「動いていますか」ではなく「何が見えますか」から入る。** 先に「動いているはず」と言うと、
それに合う説明が返ってくる。期待どおりかの判断は、見えているものを書いたあと。
「画像から読み取れないことは読み取れないと言ってください」を必ず添える。

端末の一覧は `simctl list devices --json`。使えないものは落とし、**起動中を先に**出す（すぐ撮れるので）。
ランタイム名は `com.apple.CoreSimulator.SimRuntime.iOS-18-2` → `iOS 18.2` に直す。

## 2. 流れをテストに起こす

人が書いた流れを 1 行 1 手順で読む。

```
タップ: ログイン
入力: メールアドレス = a@example.com
確かめる: ホーム
待つ
設定
```

**書き方を覚えさせない。** 頭の言葉が無い行は「押す」と読む（流れを書くとき、いちばん多いのが押す操作）。
行頭の番号・記号（`1.` `- ` など）は落とす。「待つ」だけの行に相手はいない。

| 頭の言葉 | 出るもの |
| --- | --- |
| `タップ` / `押す` / `tap`（既定） | `tester.tap(find.text(...))` + `pumpAndSettle()` |
| `入力` / `enter` | `tester.enterText(find.widgetWithText(TextField, ...), ...)` |
| `確かめる` / `出る` / `expect` | `expect(find.text(...), findsOneWidget)` |
| `待つ` / `wait` | `pumpAndSettle(const Duration(seconds: 2))` |

**見えている文字で探す**（`find.text`）。Key を振る方が堅いが、まだ振られていないことのほうが多いので、
まず動く形を出す。直すのは人（またはエージェント）の仕事 — 下書きのヘッダにそう書いてある。

Dart の文字列に落とすとき `'` `\` `$` を必ずエスケープする（`$` を忘れると文字列補間になって壊れる）。

## 出るもの

| コマンド | すること |
| --- | --- |
| `nimbus.captureSimulator`（シミュレータの画面を撮って渡す） | 端末を選ぶ → 起動 → 撮る → 見えているものを言わせる |
| `nimbus.writeFlowTest`（確かめたい流れをテストに起こす） | 選択範囲か入力から手順を読み、`integration_test` の下書きを開く |

## 確認項目

- [ ] 起動中の端末が一覧の先頭に出る
- [ ] `isAvailable: false` の端末が一覧に出ない
- [ ] macOS 以外で、エラーではなく案内が出る
- [ ] 頭の言葉が無い行が「押す」になる
- [ ] `1. タップ: ログイン` の行頭の番号が落ちる
- [ ] 「待つ」だけの行が手順として残る
- [ ] `it's $x` のような文字が Dart の文字列として壊れない
- [ ] 撮った画面を渡す文が「何が見えているか」から始まっている
