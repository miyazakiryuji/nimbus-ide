# 依存を足す前に見る

入れる瞬間に、判断材料を短く出す（T-118）。

## 何を解決するのか

依存はいちど入ると抜けない。**入れる瞬間だけが安く止められる場所**なのに、その瞬間は
いちばん急いでいる（動かしたいから足している）。だから材料は**その場で・短く**出す。
調べに行かせた時点で読まれない。

## 振る舞い

コマンド「依存を足す前に見る」（`nimbus.auditDependency`）。

- パッケージ名を入れると、`npm view` で事実を取る
- 出すもの（当てはまるものだけ）

  | 見るもの | しきい値 |
  | --- | --- |
  | 最終更新から時間が経っている | 1 年以上 |
  | 使っている人が少ない | 週 1000 未満 |
  | さらに引っ張る依存が多い | 20 個以上 |
  | 作者が非推奨と言っている | 理由ごと出す |
  | 似た役割のものが既に入っている | `package.json` と名前で突き合わせ |
  | ライセンスの記載が無い | — |

- **良し悪しは決めない。** 締切や代替の有無によって、これで問題ないこともある。
  「知らずに入れるのと、知って入れるのは別」なので、事実だけ置く
- 取れなかったときは、その旨を出して終わる（npm が無い／名前が違う／ネットに出られない）

**ネットに出るのは `npm view` だけ。** Nimbus 自身は外へ何も送らない。

## 設計

- `extensions/nimbus/src/core/depAudit.ts` — 判定と表示（VS Code 非依存）
- `extensions/nimbus/src/depAudit.ts` — `npm view` の呼び出しと既存依存の読み込み

## 受け入れ条件

- [x] 最終更新・利用者数・依存数・非推奨・ライセンスを見る
- [x] 似た名前の既存依存を見つける（自分自身は除く）
- [x] 良し悪しを決めないと明記する
- [x] 気になる点が無ければ、そう書く
- [ ] 画面確認（実際のパッケージで試す・未実施）

単体テスト: `extensions/nimbus/src/test/depAudit.test.ts`（10 件）

## 決めなかったこと・やらないこと

- **入れる操作そのもの** — `npm install` は人が打つ。見せるところまで
- **点数化** — 「85 点」のような数字は、根拠の無い安心を与える
