# 監査ログ・時系列ビューア・アンビエント表示

## 何を解決するのか

**監査**（T-050）— 「誰がどのエージェントに何をさせたか」を後から辿れないと、企業では使えない。

**時系列**（T-015 / T-184）— 「なぜこうなったか」を追うには、**畳んでいない生の並び**が要る。
`activityView` は同じ ID をまとめるので、「何回起きたか」「間に何が挟まったか」が消える。

**アンビエント**（T-056）— いま何をしているかが**視界の端**で分かると、
画面を見張らずに済む。

## 振る舞い

### 監査ログ（T-050）

- 残すのは意味のあるものだけ — セッション開始・指示・ツール実行と結果・ターン終了・
  エラー・サブエージェント・フック・コンパクション。
  表示用の細かいもの（`assistant-text` / `thinking` / `status`）は残さない
- 置き場所は `globalStorage/audit/YYYY-MM-DD.jsonl`（日付ごとの JSONL）
- 時刻は **ISO 8601**。機械で読める形にする
- **必ずサニタイザを通してから書く。** 監査ログは人に見せる前提のものなので、
  ここに資格情報が残ると、いちばん流出しやすい形になる
- 書けなくてもセッションは止めない（ログに理由だけ残す）
- コマンド **「Nimbus: 今日の監査ログを開く」**（`nimbus.showAuditLog`）
- 設定 `nimbus.audit.enabled` で切れる

### 時系列ビューア（T-015 / T-184）

サイドバー Nimbus の **「時系列（デバッグ）」**（既定は折りたたみ）。

- **畳まない。** 流れてきた順に、新しいものを上から並べる
- 先頭に「内訳」（種類ごとの件数）。何が多いか分かると、絞る先が決まる
- **失敗した行はアイコンで拾える**
- 300 件で打ち切り、新しいほうを残す

Inbox の T-015（デバッグモード）が求めていたのはこの面。
`activityView`（畳む）と役割が違うので、別のビューにしてある。

### アンビエント表示（T-056）

ステータスバーに、**走っている間だけ**いまのツールと対象を出す。

`$(sync~spin) Nimbus · Edit login.ts · ███░░ 25% · $0.1234`

止まっているときは出さない（動いていないのに出ていると、止まっていることに気づけない）。

## 設計

- `extensions/nimbus/src/core/audit.ts` — 監査 1 行への変換と時系列の組み立て。VS Code 非依存
- `extensions/nimbus/src/timelineView.ts` — 時系列の表示
- `extensions/nimbus/src/extension.ts` — 追記・ステータスバー

## 受け入れ条件

- [x] 表示用の細かいイベントは監査に残さない（単体テスト）
- [x] ツール実行は「何に対して」を残す（単体テスト）
- [x] 失敗を失敗として拾う（単体テスト）
- [x] 時刻を ISO で残す（単体テスト）
- [x] 時系列は畳まず、同じツールが 2 回なら 2 行出る（単体テスト）

## 決めなかったこと・やらないこと

- **監査ログをリポジトリに置かない。** `globalStorage` に置く。
  リポジトリに入れると、公開したときに会話がまるごと出る
- **利用者名は記録しない。** 記録するのは「どのセッションが」まで。
  誰が使ったかは OS のアカウントの話で、Nimbus が持つ情報ではない
- **時系列に `assistant-text` を出さない。** 会話はコックピットで読むもので、
  ここは「何が起きたか」を追う面
- **ログの検索・絞り込みは付けていない。** JSONL なので `jq` で足りる。
  画面が要るほど溜まってから考える
