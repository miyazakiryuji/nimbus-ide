# 並列セッションの見える化（誰が何を触っているか）

## 何を解決するのか

Nimbus が狙うのは「1 人の Claude を速く回す」ことではなく、**複数のエージェントで
同時に同じプロジェクトを開発できること**。そうすると、**同じファイルを 2 つのセッションが
触る**のは避けられない。避けられない以上、起きる前に見せる。
コンフリクトになってから解くより、書く前に知るほうが安い。

対応する tasks.md の項目: T-011（同じファイルを触っているセッションを検出して知らせる）/
T-012（いま誰が何をしているかの俯瞰）。

## 振る舞い

### 衝突の予告（T-011）

- 書き込み系ツール（`Write` / `Edit` / `MultiEdit` / `NotebookEdit`）が提案された時点で、
  **他のセッションが同じファイルを触っていないか**を見る
- 触っていれば通知を出す。**相手が書いたか、読んだだけかで言い方を変える**
  - 書いている: 「`x.ts` は ログイン画面の修正 も編集しています。競合します」
  - 読んだだけ: 「`x.ts` は … も読んでいます。書き換えると相手の前提が古くなります」
- **読みだけの衝突も知らせる。** 読んだ内容が古くなるのも事故のうち
- 同じ「セッション × ファイル」の組み合わせでは**一度だけ**鳴らす（鳴らし続けない）
- セッション名は、タスクとして走っていれば**タスク名**を出す（UUID では誰か分からない）

### 俯瞰（T-012）

「セッションの中身」ビューに **「他のセッション」** グループが出る。

- **並列で走らせているときだけ出す**（1 本しか動いていないなら邪魔なだけ）
- セッションごとに、触ったファイルを新しい順に 10 件まで
- 行には「編集 / 読み」と時刻。クリックでエディタに飛ぶ
- 最後に動いたセッションが上

## 設計

- `extensions/nimbus/src/core/sessionFiles.ts` — `SessionFilesTracker`。VS Code 非依存
- `extensions/nimbus/src/activityView.ts` — 「他のセッション」グループ
- `extensions/nimbus/src/extension.ts` — 記録・通知・名前の解決

`activity.ts` はアクティブな 1 セッションを畳むもので、こちらは**全セッション横断**。
記録はイベントの絞り込み（アクティブなセッションだけを表示に流す処理）**より前**に置く。
後ろに置くと、他のセッションの動きが 1 つも記録されない。

### 一度でも書いていれば「書いた」を保つ

同じセッションが `Write` のあとに `Read` すると、素直に上書きすると「読んだだけ」に
戻ってしまう。衝突の重さは下がらないので、書いた事実のほうを保つ。

## 受け入れ条件

- [x] 自分だけが触っているファイルを衝突にしない（単体テスト）
- [x] 他のセッションが編集していれば競合として知らせる（単体テスト）
- [x] 読んだだけの相手には言い方を変える（単体テスト）
- [x] 一度でも書いていれば「書いた」を保つ（単体テスト）
- [x] ファイルを触らないツールは覚えない（単体テスト）
- [x] 終わったセッションは忘れる（単体テスト）
- [x] 俯瞰は最後に動いた順、ファイルも新しい順（単体テスト）
- [ ] 画面確認: 2 つのタスクを並列で走らせ、同じファイルを触ると通知が出る

## 決めなかったこと・やらないこと

- **書き込みを止めない。** 止めると、正当に同じファイルを直したい場面まで塞がる。
  知らせるところまでにして、判断は利用者に残す
- **worktree をまたいだ検出はしていない。** 並列タスクはそれぞれ別の worktree で走るので、
  実体としては別ファイル。ただし**同じ論理パス**を触っていればマージ時に必ず衝突するため、
  パス文字列で突き合わせている（worktree 名の差は無視していない＝現状は同一 worktree 内で効く）
- **セッションの一覧ビューは作らない。** 既存の「タスク」板がその役目を持っている
