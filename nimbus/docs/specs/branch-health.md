# ブランチのようす

作業ブランチがどれだけ離れたか、衝突しそうかを見る（T-134 / T-219）。

## 何を解決するのか

長く置いたブランチはいつか必ず衝突する。**衝突してから知る**のがいちばん高くつくので、
「どれだけ離れたか」と「両側で同じファイルを触っているか」を先に見せる。

## 振る舞い

コマンド「ブランチのようすを見る」（`nimbus.openBranchHealth`）。

- 比べる先は設定 `nimbus.git.baseBranch`。空なら `main`（無ければ `master`）
  - **フォークでは `main` が upstream になっていることがある。** そのままだと
    「688 コミット遅れている」のような比べても意味の無い数字が出る（このリポジトリで実際に出た）
- 出すもの
  - 進んでいるコミット数 / 取り込めていないコミット数
  - **両側で触られているファイル**（衝突の実体）
  - ブランチ名が規則に合っているか
- 危険度の判定
  - **同じファイルを両側で触っていれば、離れ具合に関わらず「衝突しそう」**。それが衝突の実体
  - 触っていなければ、20 コミット以上離れたときだけ「少し離れています」
  - 危ないときは取り込む手順（`git pull --rebase`）まで書く
- ブランチ名の既定の規則: `main` / `nimbus` / `nimbus/<話題>`。合わないときだけ節を出す

## 設計

- `extensions/nimbus/src/core/branchHealth.ts` — 判定と Markdown 化（VS Code 非依存）
- `extensions/nimbus/src/branchHealth.ts` — git の呼び出しとコマンド

## 受け入れ条件

- [x] `rev-list --left-right --count` の出力を読む（読めない出力では 0 にする）
- [x] 両側で触られているファイルを重複なく出す
- [x] 同じファイルを触っていれば、離れ具合に関わらず危ないと判定する
- [x] ブランチ名の規則を判定し、合わないときだけ節を出す
- [x] 比べる先を設定で変えられる
- [x] 画面確認: コマンドから開いて中身が出る
      — GUI ケース `26-analysis-commands.mjs`（実際の git 作業ツリーで開き、中身が出ることを見る）

単体テスト: `extensions/nimbus/src/test/branchHealth.test.ts`（8 件）

## 決めなかったこと・やらないこと

- **自動で取り込むこと** — 取り込む判断は人がする。ここは知らせる場所
- **常時監視** — 開いたときに見るだけ。裏で回して通知すると、通知そのものが無視される
