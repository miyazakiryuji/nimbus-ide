# スナップショットの更新レビュー（T-181）

スナップショット（ゴールデン）テストは、**通すために更新できてしまう**。
落ちたから撮り直した、がそのまま通ると、テストは何も守らなくなる。
エージェントに任せるほどこの穴は開きやすい。

だから「何が更新されたのか」を、レビューの前に**名指しで**出す。

## 振る舞い

コマンド **「スナップショットの更新をレビューする」**（`nimbus.reviewSnapshots`）:

```
スナップショットが 2 件変わっています
- 更新 src/__snapshots__/a.test.ts.snap: renders header 1
- 追加 test/goldens/home.png（画像のため中身は比較できません）
```

- **「差分を開く」** — テキストは HEAD との差分エディタ、画像はそのまま開く
- **「説明させる」** — 変わったスナップショットを名指しして、
  **なぜその出力になったのかを説明させる**指示をコックピットへ送る

## 実装

- `extensions/nimbus/src/core/snapshotReview.ts` — 判定・差分の読み取り・文面（純関数）
- `extensions/nimbus/src/snapshotReview.ts` — `git diff --name-status` と差分エディタ
- テスト: `extensions/nimbus/src/test/snapshotReview.test.ts`

## 決めたこと

**扱うのは慣習的なパスだけ。** `__snapshots__/` / `*.snap` / `golden(s)/` / `*.golden` /
`*.approved.txt` / `*_golden.png`。ここを広げすぎると、ただの画像アセットの変更まで拾う。

**画像は「中身は比較できません」と書く。** 読めないものを読めたつもりにさせない。
差分エディタでも意味が無いので、画像はそのまま開く。

**投入する文は「直して」ではなく「説明して」から始める。** 撮り直しが正しいこともある。
そのうえで「意図した変更でないものは、スナップショットではなく**実装の方**を直してください」と続ける。

**変わった名前を出す。** Jest / Vitest の `exports[\`name\`]` を差分から拾う。
「a.snap が変わりました」だけでは、レビューのしようがない。

## 確認すること

- [ ] スナップショットを更新した状態でコマンドを叩くと、ファイルと名前が出る
- [ ] 画像のゴールデンでは「中身は比較できません」と出る
- [ ] 「差分を開く」でテキストは差分エディタ、画像は通常のエディタで開く
- [ ] 「説明させる」でコックピットに説明を求める指示が送られる
- [ ] スナップショットを触っていないときは「更新はありません」と出る

## 残っていること

- Dart の `matchesGoldenFile` のような、名前が本文にしか出ない形式では名前を拾えない
- 画像の差分（ピクセル比較）は出さない。VS Code の画像差分に載せる線は今後
