# スニペット化（T-177）

一度うまく書けた形を、次も同じようにエージェントに書かせるのは、時間もお金も無駄。
**エディタ側に置けば補完で出る。** Nimbus はエージェントの操縦席であると同時にエディタなので、
「エージェントに頼まない」という選択肢を持てるのが強み。

## 振る舞い

範囲を選んで右クリック →**「選択範囲をスニペットとして保存」**（`nimbus.saveSnippet`）:

1. パターンの名前と、補完で打つ言葉（prefix）を入れる
2. `.vscode/<言語 ID>.code-snippets` に保存する
3. 「開く」で保存先を確認できる

保存先はワークスペースの中なので、**そのままリポジトリに入れてチームで共有できる**。

## 実装

- `extensions/nimbus/src/core/snippets.ts` — エスケープ・字下げ落とし・マージ（純関数）
- `extensions/nimbus/src/snippets.ts` — 選択範囲の取得とファイル書き込み
- テスト: `extensions/nimbus/src/test/snippets.test.ts`

## 決めたこと

**`$` `}` `\` を必ず逃がす。** スニペット構文で意味を持つので、そのまま置くと
`${x}` が意図しないプレースホルダとして解釈され、貼った瞬間に形が崩れる。
テンプレートリテラルを含むコードでは必ず踏む。

**共通のインデントを落とす。** 深い階層で選んだコードが、ぶら下がったまま保存されないように。

**同じ名前は上書きする。** 同じ名前で違う中身が 2 つあっても選べない。上書きしたことは伝える。

**壊れた JSON は作り直す。** 書き足せないまま失敗するより、作り直して保存を通す
（元の内容は失われるが、`.vscode/` は git に入っているので戻せる）。

**プレースホルダ（`${1:...}`）は自動で作らない。** どこを可変にすべきかは人が決める。
勝手に置くと、消す手間の方が大きい。

## 確認すること

- [ ] 範囲を選んで右クリックすると項目が出る（選んでいないときは出ない）
- [ ] 名前と prefix を入れると `.vscode/<言語>.code-snippets` ができる
- [ ] その prefix を打つと補完に出る
- [ ] テンプレートリテラル（`${x}`）を含む範囲でも、貼った形が崩れない
- [ ] 同じ名前で保存し直すと上書きされ、その旨が出る

## 残っていること

- プレースホルダ化の支援は無い（上の判断のとおり）
- 言語 ID ごとに 1 ファイル。複数ルートのワークスペースでは最初のフォルダに置く
