`src/sessionSide.ts`（右半分）, `src/cockpit/CockpitViewProvider.ts`・`media/cockpit.js`（タブの列）,

**テスト**: `src/test/sessionTabs.test.ts`, `src/test/sessionSide.test.ts`,

## なぜ

並列で走らせるほど、画面は「どのセッションの話か」で迷いやすくなる。
サイドバーの幅では会話が折り返しだらけで、切り替えるたびに文脈を作り直すことになる。

## 全画面（T-269 ①）

コマンド「Nimbus: コックピットを全画面にする」でタブとして開き、
**サイドバー・パネル・補助バーを畳んで会話だけ**にする。もう一度押すと戻る。

- **アクティビティバーは残す。** 帰り道まで消すと、戻りかたを探すことになる
- 畳めなかった面があっても全画面自体は成立させる（閉じるコマンドの失敗で止めない）
- **全画面にしたら右半分（変更差分）も出す**（T-292）。ただし、そのセッションがまだ
  ファイルを書いていないときは黙って出さない — 全画面にするたびに
  「まだ書いていません」と言われるほうが邪魔になる

### 入口（T-289 / T-290 / T-292 / T-293）

全画面は**サイドバーごと畳む**ので、`view/title` に置いた入口は全画面にした瞬間に消える。
`editor/title`（`activeWebviewPanelId == nimbus.cockpitTab`）にも同じものを置く。

| 面 | 出すもの |
| --- | --- |
| サイドバー（`view/title`） | `+` 新しいセッション / 走っているセッションを見る / 全画面 …… `...` に 右半分・タブで開く |
| 全画面（`editor/title`） | `+` 新しいセッション / 走っているセッションを見る / 右半分 / 全画面をやめる |
| 会話の上のタブ列 | 右端に `+`（列は 2 本以上のときだけ出るので、**ここだけに置かない**） |

### 「+」はセッションを足す（T-310 = 旧 T-303）

以前は**いまのセッションを閉じて作り直す**実装で、押してもタブが増えず手応えが無かった。

- 押すと**下書き**（まだ 1 通も送っていないセッション）が 1 枚増え、タブに
  `新しいセッション`（状態は「あなたの番」）として出る。最初の 1 通を送った時点で本物になる
- いまのセッションは**閉じない**。走っているものは走ったまま、タブから戻れる
- **見えているなら面を前へ出さない**（`reveal()` が `isVisible()` を先に見る）。
  全画面のタブで押したときに、閉じているサイドバーが背後で開いていた
- 下書きのタブを押すと、下書きの間で前面が切り替わる（中身が無いので面は白紙のまま）

守りは `src/test/cockpitMenus.test.ts`（並びとアイコンの有無を固定）。
作法は CLAUDE.md「コマンドを足したら、入口も足す」。

## セッションのタブ（T-269 ②③）

会話の上に、ファイルタブのような列が出る。**2 本以上あるときだけ**出す
（切り替える先が無い列は場所を取るだけ）。

| 状態 | 記号 | 借りたトークン |
| --- | --- | --- |
| 許可待ち | `!` | `list.warningForeground` |
| 作業中 | `●` | `progressBar.background` |
| あなたの番 | `?` | `editorInfo.foreground` |
| 完了 | `✓` | `testing.iconPassed` |
| 中断 | `■` | `descriptionForeground` |
| エラー | `✕` | `list.errorForeground` |

**絵文字は使わない**（T-302）。一度 🟡🔵🟢 を添えたが、テーマの色に従わないうえ、
他がすべて SVG（codicon の代わり）なのでそこだけ質感が変わった
（design-philosophy「Color comes from the theme」「Sameness signals sameness」）。
色つきの印が要るところは、**テーマトークンで塗った丸の SVG** を webview 側で描く。

- **状態は 1 つに混ぜる。** `SessionStatus` は「許可待ち」を持っていないので、
  承認の待ち行列と合流させる。**許可待ちが最優先**（走っている最中に承認へ入ることがあり、
  そのとき見たいのは「止まっている」ほう）
- **色だけに頼らない。** 記号を必ず添える（色覚の違いと、モノクロのスクリーンショット）
- **並びは始めた順で固定。** 状態で並べ替えると、押そうとした瞬間に動いて押し間違える
- **通し番号を先頭に置く**（T-301）。3 本並ぶと 1 本 86px ほどで、名前に使えるのは 30px 程度。
  頼んだ文を先頭から機械的に削ると、どのタブも同じ書き出し（「この」「テストを」）になって
  **見分けがつかない**。番号は 1〜2 文字なので幅が無くても残る
- **名前は意味の切れ目で切る**（T-301）。句読点・コロンの手前までを短い見出しにして 10 文字まで。
  全文は指を置いたときに出す
- **縮められるようにする**（T-300）。`min-width: 0` が無いとタブは中身の幅で居座り、
  実測で 3 本開くと列が 567px（サイドバーは 299px）に伸びて**前面のタブが画面外**へ隠れた。
  折り返しも止める — 日本語は文字単位で折り返すので「あなたの番」が縦 1 列に積まれた。
  それでも溢れるときは、前面のタブを見える位置まで送る
- 「ゆあに聞く」はタブに出さない。切り替える先ではないし、本数が狂う

### 状態が読み取れること（T-298）

「完了 / 進行中 / あなたの番が読み取れない」という声が出た。原因は 3 つあった。

- **1 本のときは列ごと出さない**ので、普段の 1 本では状態がどこにも出ていなかった
  → 前面のセッションの状態を、列とは別に**入力欄の下の帯**へ出す（列が無くても読める）
- **記号が小さく、色もトークン任せ**でパッと見で読めなかった
  → 色つきの丸を足し、**記号・丸・言葉・色の 4 つが同じことを言う**形にした（T-295 と同じ約束）
- **状態の言葉がツールチップにしか無かった**
  → 帯には常に言葉で出し、**前面のタブにも言葉を出す**（他のタブは記号と丸のまま。幅が要るため）

守りは `src/test/sessionTabs.test.ts`（4 つが揃っていること）と
GUI ケース 49（`--with-claude`・言葉が出ていること）/ 52（普段の実行・置き場が消えていないこと）。

### 切り替えたときに会話が消えないこと

`retained`（表示用のイベント列）は「前面のセッションのぶん」という約束で、20 か所以上がそれを
前提に読んでいる。そこで**別に控えを持つ** — 全セッションぶんを
`archived`（1 本 500 件・12 本まで）に貯め、切り替えのときに `retained` へ移し替える。
控えの上限は、並列で長く回したときにメモリを食い潰さないため。

## タブの操作（T-311 / T-313 / T-316）

タブはエディタのタブと同じ作法に寄せる。**指を置くと操作が現れ、休んでいるときは静か**。

- **ピン（T-311）** — 押すと先頭に残る。並びとしるしだけで、停止・後片付けの対象からは外さない
  （「ピンしたから守られている」と思わせると、止めたはずが走っている事故を生む）
- **名前（T-313）** — タブをダブルクリックすると、その場が入力欄になる。空にして Enter で
  自動の見出し（最初に頼んだこと）へ戻る。コマンド「Nimbus: セッションの名前を変える」からも。
  T-292（タブ名がプロンプト全文で見分けられない）の答え
- **閉じる（T-316）** — ×。走っている・許可待ちのときだけ確認を出し、終わっているものは黙って閉じる
  （毎回聞くと × が「押すと聞かれるボタン」になる）。worktree と書き込んだファイルは残る。
  答え待ちの承認は拒否で片付ける

**番号は席順ではなく名札。** ピンで並び替えても、途中のタブを閉じても、残りの番号は変わらない。
番号の台帳（`sessionNumbers`）を workspaceState に持ち、下書き → 本物のときは引き継ぐ。
「2 番のセッション」という言い方が、操作のたびに壊れないためにある。

タブ要素は `<button>` ではなく `<div role="tab">`。**ボタンの中にボタンや入力欄は置けない**
（HTML の決まりで、入れ子の操作はブラウザが外へ追い出す）ため、ピン・×・名前の書き換えを
中に住まわせるにはこの形が要る。キーボードの道（Enter / Space で切り替え）は自分で敷いてある。

### 開き直したときの復元（T-314）

タブ列は snapshot に含め、**作る場所は `currentTabs()` の 1 か所だけ**にする。
以前は snapshot 側に別実装の `buildTabs` 呼び出しがあり、下書きもピンも知らなかったので、
全画面で面を開き直すと**サイドバーには見えている列が全画面では消える**
（複数開いても 1 本に見える）という食い違いが起きていた。

### 決めなかったこと・知られている段差

- **アクティブでないタブのダブルクリックは、1 回目で切り替えになる**（クリックで列が
  作り直され、2 回目のクリックが別の要素に落ちるため）。もう一度ダブルクリックすれば
  名前を変えられる。列を作り直さない差分更新にすれば解けるが、いまはしない
- 下書きのピン・名前変更はできない（送った時点で ID が変わり、迷子になるため）

## 右半分（T-270）

全画面にすると**変更差分が既定で出る**（T-292）。選び直すときは
コマンド「Nimbus: 右半分に出すものを選ぶ」（面のタイトルの `$(split-horizontal)`）で、
**どちらか 1 つ**を右のエディタグループに出す。2 つ並べると会話が細って読めなくなる。

| 出すもの | 中身 |
| --- | --- |
| コマンドの出力 | そのセッションが動かした `Bash` の**写し**（読み取り専用の端末） |
| 変更差分 | そのセッションが**書いた**ファイルを、`git show HEAD:` と比べた差分 |

- **webview の中に描き直さない。** 端末も差分エディタもワークベンチが本物を持っている。
  写しを作ると検索も折り返しも配色も別物になり、「本物のつもりで見て違う」が起きる
- 端末は `Pseudoterminal` の**写し**。打ち込みは受け取らない（打ってもセッションには届かない）
- 差分の左側は `nimbus-head:` スキームで `git show HEAD:<path>` を読む。
  HEAD に無い（新規作成）なら空を返し、全部足した差分として出す
- 読んだだけのファイルは差分に出さない（差分が出ないので、開いても空になる）
- **セッションを切り替えたら右も追従する。** 追従しないと、左右で別のセッションを見ることになる
