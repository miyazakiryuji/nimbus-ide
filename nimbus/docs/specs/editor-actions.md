# エディタから直接頼む（T-171 / T-172）

「この関数をリファクタして」と頼むのに、ファイル名と行番号を打ち直す必要は無い。
選択範囲もカーソル位置の関数も、IDE はすでに知っている。
**知っていることを人に入力させない** — エディタの上に乗る価値の一つ。

## 振る舞い

**右クリック（T-171）** — エディタで選択して右クリック →「Nimbus に頼む」。
何も選んでいなければカーソル行を対象にする。

**コードレンズ（T-172）** — 関数・メソッド・クラス・コンストラクタの上に
「$(cloud) Nimbus に頼む」が出る。押すと、その関数の範囲が対象になる。

どちらも同じ入口に入り、4 つから選ぶ:

| 選択肢 | 何をするか |
| --- | --- |
| 説明して | 何をしているコードか、なぜこう書かれているか |
| リファクタして | 振る舞いを変えずに整理する（何をどう変えるかを先に説明させる）|
| テストを書いて | 既存の書き方に合わせてテストを足す |
| 自由に指示する | 場所を指したまま、自分で書く |

送られる文はコックピットにそのまま出る。

## 実装

- `extensions/nimbus/src/core/editorActions.ts` — 文面の組み立て（純関数）
- `extensions/nimbus/src/editorActions.ts` — 選択範囲の取得と `CodeLensProvider`
- `extensions/nimbus/src/extension.ts` — コマンド登録とプロバイダ登録
- テスト: `extensions/nimbus/src/test/editorActions.test.ts`

## 決めたこと

**場所を先に、コードを後に置く。** 場所さえ渡っていれば、Claude は必要なぶんを自分で読みに行ける。
コードを貼るのは「まず目を通させる」ためで、全部渡すためではない。

**貼るのは 200 行まで。** ファイル丸ごとを選ばれても文脈を溶かさない。
切ったときは「残り N 行はファイルを読んでください」と明示する。

**コードレンズは種類を絞る。** 関数・メソッド・クラス・コンストラクタだけ。
変数や import の上にまで出すと、レンズが多すぎて誰も読まなくなる。

**「リファクタして」は振る舞いを変えない依頼として書く。** この製品自身の
[CLAUDE.md](../../CLAUDE.md)（既存の機能を壊さない）と同じ姿勢を、頼み方の既定に入れておく。

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `nimbus.editor.codeLens` | `true` | 関数の上に「Nimbus に頼む」を出す |

## 確認すること

- [ ] 選択して右クリック →「Nimbus に頼む」が出る
- [ ] 4 つの選択肢が出て、選ぶとコックピットに指示が送られる
- [ ] 何も選ばずに実行するとカーソル行が対象になる
- [ ] 関数の上にコードレンズが出て、押すとその関数が対象になる
- [ ] 変数や import の上にはレンズが出ない
- [ ] 「自由に指示する」で入力した文が先頭に来る
- [ ] 200 行を超える選択で「残り N 行」が付く
- [ ] `nimbus.editor.codeLens` を `false` にするとレンズが消える（設定変更で即座に）

## 残っていること

- レンズは 1 種類（「頼む」）だけ。「テストへ飛ぶ」「参照を見る」のような複数レンズは出していない
- 選択範囲を**書き換える**導線（インライン適用）は無い。返事はコックピットに出る
