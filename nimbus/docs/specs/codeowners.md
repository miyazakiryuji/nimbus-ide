# コードオーナーへの通知

**タスク**: T-221 / **実装**: `extensions/nimbus/src/core/codeowners.ts`（判定）,
`extensions/nimbus/src/codeowners.ts`（VS Code 層） / **テスト**: `src/test/codeowners.test.ts`

## なぜ

触ったファイルに持ち主がいるなら、**誰にレビューを頼むかはもう決まっている**。
それを `CODEOWNERS` を目で追って探すのは人の仕事ではない。しかも読み違えると別の人に投げてしまい、
気づくまでレビューが止まる。

## こちらからは投げない

**誰に頼むかを出すところまでで止める。** メンションは相手の時間を取るので、
送る判断は人が持つ。Nimbus がやるのは「PR の説明に貼れる形にして写す」まで。

## 読み方

GitHub の `CODEOWNERS` の書式をそのまま読む。

- 置き場所は `.github/CODEOWNERS` → `CODEOWNERS` → `docs/CODEOWNERS` の順に探し、**先に見つかったものだけ**を使う
- `#` から行末はコメント。空行と、持ち主のいない行は落とす
- パターンは gitignore と同じ考え方 — 先頭の `/` はリポジトリの根から、末尾の `/` はディレクトリ配下、
  `*` は `/` を跨がない、`**` は跨ぐ
- **最後に一致した規則が勝つ**。`* @team/core` を先頭に置き、下へ行くほど細かくする書き方に合わせる

## 触ったファイル

1. `git diff --name-only HEAD` — まだコミットしていないぶん
2. それが空なら `origin/main...HEAD`（`origin/master` / `main` / `master` の順に試す）— ブランチが積んだぶん

手元が汚れているときは手元を、綺麗ならブランチ全体を見る。どちらも無ければ「触ったファイルはありません」。

## 出るもの

| コマンド | すること |
| --- | --- |
| `nimbus.notifyCodeOwners`（レビューを頼む相手を出す） | 持ち主ごとにファイル数を集計して通知。「一覧を写す」で PR に貼れる形をクリップボードへ |
| `nimbus.showOwnersOfActiveFile`（このファイルの持ち主を見る） | 開いているファイル 1 つの持ち主を 1 行で |

集計は**担当ファイルの多い順**、同数なら名前順。持ち主のいないファイルは件数だけ添える
（誰のものでもない場所を触ったことは、それ自体が情報なので隠さない）。

## 確認項目

- [ ] `*` と細かい規則が両方当たるとき、**下に書いた方**の持ち主が出る
- [ ] `/docs/` のようなディレクトリ規則が、その配下のファイルに当たる
- [ ] `*.dart` がどの階層のファイルにも当たる（先頭の `/` が無いので）
- [ ] `/lib/ui/**` が `lib/ui/a/b.dart` に当たり、`lib/other.dart` には当たらない
- [ ] 行末コメント（`@bob   # Flutter は bob`）が持ち主に混ざらない
- [ ] `CODEOWNERS` が無いリポジトリで、エラーではなく案内が出る
- [ ] 「一覧を写す」で貼り付けられ、6 件以上のときは「他 N 件」に畳まれている
