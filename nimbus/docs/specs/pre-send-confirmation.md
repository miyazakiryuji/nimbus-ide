# 着手前の確認（曖昧な指示を止める）

## 何を解決するのか

曖昧なまま走らせると、エージェントは**自分で前提を埋めて**動き出す。埋めた前提が違っていたと
分かるのは、たいてい何十ファイルも書き換えたあと。走らせる前に、足りていないものを名指しで聞く。

## 振る舞い

コックピットで送信したとき、指示に足りていないものがあれば確認ダイアログを出す。

- **「このまま送る」** — 指摘を承知で走らせる
- **「書き直す」** — 送信を取りやめる。Esc で閉じた場合も送らない（答えなかったものを送信に倒さない）

止めるのは次のいずれかに当たるとき。

| 引っかかる条件 | 聞くこと |
| --- | --- |
| 指示が 12 文字未満で対象も無い | 何を・どこで・どうなれば完了か |
| 「いい感じに」「よしなに」「適当に」 | 完成したと判断できる条件 |
| 「全部まとめて直して」など範囲が全部 | 対象をファイル／ディレクトリで区切る |
| 「バグ」「エラー」「動かない」 | 再現手順と実際の出力 |
| 「きれいに」「整理」「リファクタ」 | 何が困っているのか |
| 上のいずれかに当たり、かつ対象が書かれていない | 対象のファイル名か探す手がかり |

**止めない**のは次のとき（うるさい仕組みは無視されるようになるため、判定は保守的にしてある）。

- 対象が具体的なとき — ファイル名・`コード引用`・`関数名()`・パス・URL・`#123`・`T-001`
  （ただし**バグ報告だけは対象があっても再現手順を聞く**。対象が分かっても再現できなければ動きようがない）
- 質問・相談のとき（「〜ですか」「どう思う」「教えて」）
- 会話が続いているとき（前のやり取りに文脈がある）
- 設定 `nimbus.dialogue.confirmVaguePrompt` が `false` のとき

## 設計

- 判定: `extensions/nimbus/src/core/clarify.ts`（VS Code 非依存・単体テストあり）
- 表示: `extension.ts` の `checkBeforeSending()`。資格情報の検査（`safety.scanBeforeSend`）と
  同じ入口に並べ、**曖昧さ → 資格情報**の順に見る

## 決めなかったこと・やらないこと

- **指示を自動で書き換えない。** 何を頼むかは利用者の領分で、勝手に補うと「頼んだつもりのないこと」が走る
- **学習・記憶はしない。** 「この人はいつも短く書く」を覚えると、止めるべきときに止まらなくなる
