# コードから仕様書を起こす（T-080）

ドキュメントが無いコードは、読むたびに読み直すことになる。かといって
「仕様書を書いて」と丸投げすると、**それらしい嘘**が出てくる — コードから読み取れないこと
（なぜそうしたか）まで、もっともらしく書かれてしまう。書かれた瞬間に、それが根拠になる。

**だから頼み方を固定する。事実と推測を分けて書かせる。**

## 振る舞い

ファイルを開いて **「このコードから仕様書を起こす」**（`nimbus.reverseSpec`）:

1. `nimbus/docs/specs/<kebab-case>.md` を置き場所に決める
2. **既にあれば「直す」、無ければ「起こす」**として頼む
3. 言語サーバーのアウトライン（構造）を添えてコックピットへ送る

送る指示に必ず入るもの:

- **コードから読み取れる事実だけ**を書く
- 読み取れないこと（なぜこの設計にしたか）は **「理由は記録されていない」**と書く
- どうしても書きたい推測は **「推測:」と明記**する
- 振る舞いは「何ができるか」で書く。実装の手順をなぞらない
- （既存を直すときのみ）**既にある記述を消さない。** 食い違う箇所だけ直し、理由を残す

## 実装

- `extensions/nimbus/src/core/reverseSpec.ts` — 置き場所と頼み方（純関数）
- `extensions/nimbus/src/reverseSpec.ts` — アウトラインの取得と送信
- テスト: `extensions/nimbus/src/test/reverseSpec.test.ts`

## 決めたこと

**この機能の本体は「頼み方」。** 書くのは Claude で、Nimbus がやるのは
**外してはいけない一文を毎回入れること**と、置き場所を決めること。

**型は既存の仕様書に合わせる**（`specTemplate`）。この製品の仕様書はすべて
「振る舞い / 決めたこと / 確認すること / 残っていること」で書かれているので、
逆生成でも同じ形にする。並べたときに読めることが大事。

**既存を消させない。** 逆生成は「足す」操作。人が書いた記述を、コードから読み取れないという
理由で消されると、いちばん価値のある部分が失われる。

**アウトラインが取れない言語では、その節を出さない。** 空の見出しは害にしかならない。

## 確認すること

- [ ] ファイルを開いて実行すると、置き場所が `nimbus/docs/specs/<名前>.md` で出る
- [ ] 既に仕様書があるときは「直す」として頼まれる
- [ ] 送られる指示に「事実だけ」「理由は記録されていない」「推測:」が入っている
- [ ] アウトラインが取れる言語では構造が添えられる
- [ ] アウトラインが取れない言語でも落ちない

## 残っていること

- 対象は 1 ファイルだけ（ディレクトリ単位の逆生成はしていない）
- 書き込みは Claude 側。Nimbus はファイルを作らない（承認の経路に乗せるため）
