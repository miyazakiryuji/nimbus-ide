# 指示の出しかた

言い直しが起きやすい形／起きにくい形を、記録から出す（T-065 / T-067）。

## 何を解決するのか

「うまく伝わらなかった」は、そのときは相手（エージェント）のせいに見える。でも記録を並べると、
**言い直しが起きやすい指示の形**と**起きにくい形**が分かれて見える。

## 振る舞い

コマンド「指示の出しかたを見る」（`nimbus.openPromptStats`）。

- 記録（`~/.claude/projects` の直近 60 本）から、自分の指示だけを時系列に並べる
- **直後（10 分以内）に言い直しが来たか**を見る。言い直しの合図は「違う」「そうじゃ」
  「やり直」「じゃなくて」など
- 出すもの
  - 言い直しの割合
  - **形による違い** — ファイル名や記号を含む／含まない、短い（60 字未満）／長い
  - 言い直しがいちばん多い時間帯（3 件以上あるときだけ）
- **10 件に満たないうちは傾向を出さない。** 少ないうちに出すと、たまたまを法則だと思ってしまう
- 最後の指示は数えない（そのあとが無いので判定できない）

**測っているのは「言い直しが起きたか」だけ。** うまくいったかどうかは記録に出ないので、
この数字は「伝わりやすさ」の目安であって、成果の評価ではない — と出力にも書く。

### 詰まりやすい場所（T-066）

同じところで何度も言い直しているなら、そこは**指示が通りにくい場所**。

- 指示に出てくるファイル名ごとに、言い直しの件数を数える
- **件数で足切りする（3 回以上出てきた場所だけ）。** 率で並べると、1 回中 1 回（100%）の
  たまたま失敗した場所が最上位に来る
- **理由は推測しない。** 「コードが難しいから」などと書くと、それが原因だと思われる。
  代わりに「次に試すこと」（前提を先に書く／範囲を狭めて頼む）を出す

## 設計

- `extensions/nimbus/src/core/promptStats.ts` — 判定と集計（VS Code 非依存）
- `extensions/nimbus/src/core/frictionSpots.ts` — 詰まりやすい場所の集計（VS Code 非依存）
- `extensions/nimbus/src/promptStats.ts` — 記録の読み込みとコマンド
- 記録の読み込みは [`digest`](digest.md) と共用（`core/transcriptFiles.ts`）

## 受け入れ条件

- [x] 直後の言い直しを拾い、離れていれば別の話題として扱う
- [x] 最後の指示を数えない
- [x] 具体的な指示（ファイル名・記号・タスク ID）を見分ける
- [x] 形ごとの言い直し率を出す
- [x] 数が少ないうちは傾向を出さない
- [x] 成果の評価ではないと明記する
- [x] 言い直しが集まっている場所を件数順に出し、少ない場所は出さない
- [x] 理由を推測せず、次に試すことを書く
- [x] 画面確認: コマンドから開く
      — GUI ケース `34-report-commands.mjs`（記録が無くても開くこと。中身は各 `core/*` の単体テストで見る）

単体テスト: `promptStats.test.ts`（7 件）・`frictionSpots.test.ts`（6 件）

## 決めなかったこと・やらないこと

- **成功／失敗の判定** — 満足したかは記録に出ない。測れないものを測ったことにしない
- **他人との比較** — 比べても直しかたが分からない。自分の中の違いだけを見る
