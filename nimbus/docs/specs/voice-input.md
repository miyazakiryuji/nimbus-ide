# 声で指示する

手が離せないときに「テスト通しといて」だけ言う（T-055）。

## 何を採らなかったか

**ブラウザの音声認識（`webkitSpeechRecognition`）は使わない。** Electron では
音声サービスに繋がらず、**黙って動かない**。動かないものを「実装した」にするのが
いちばん質が悪い。

代わりに **入っていれば使う**（GIF の `ffmpeg` と同じ形）。録るのは `ffmpeg`、
文字にするのは手元の書き起こしツール。**どちらも外に送らない。**

## 振る舞い

コマンド「声で指示する」（`nimbus.dictateInstruction`）。

1. 録る場所を選ぶ（1 つしか無ければ聞かない）
2. 15 秒だけ録る
3. 手元のツールで文字にする
4. **聞こえた内容を見せて、送るかどうかを聞く**

要るもの（無ければ入れかたを出して終わる）:

| | 何に使うか | 入れかた |
| --- | --- | --- |
| `ffmpeg` | 録音 | `brew install ffmpeg` |
| `mlx_whisper` / `whisper` / `whisper-cli` | 書き起こし | どれか 1 つ |

書き起こしツールは**入れた意図が明らかな順**に選ぶ（`mlx_whisper` を入れている人は、
それを使いたくて入れている）。

### 録る場所を決め打ちにしない

**実機で確かめて分かったこと**: このマシンでは装置 `0` が仮想オーディオ（BlackHole）で、
実際のマイクは `1` だった。`:0` 決め打ちだと**別のものを録る** — 喋っても何も入らず、
「聞き取れませんでした」だけが続いて、原因が分からない。

そのため一覧を読み、**名前でマイクを選ぶ**（ループバックらしい名前は避ける）。
選べないときは、あるものを使う（勝手に諦めない）。

### 確認なしに送らない

**聞き間違いは必ず起きる。**「テスト通して」が「テスト消して」になりうる。

- どんな内容でも、**聞こえた文を見せてから**送る
- **取り消しの利かない言葉**（消す・強制・戻す・外に出す・本番）が入っていたら、
  何が引っかかったかを言い、モーダルで聞く
- 「直してから送る」も出す（言い直すより速いことがある）

## 設計

- `extensions/nimbus/src/core/voiceInput.ts` — 装置と道具の選択・引数・確認文（VS Code 非依存）
- `extensions/nimbus/src/voiceInput.ts` — 録音・書き起こし・確認

## 受け入れ条件

- [x] 入っている書き起こしツールを見つけて使う
- [x] 無ければ入れかたを出して終わる
- [x] 録る場所を一覧から選ぶ（既定はマイク・決め打ちにしない）
- [x] 時刻の印を落として 1 つの指示にする
- [x] 聞き取れなければ、それらしい文をでっち上げない
- [x] 確認なしに送らない。危ない語があれば強く聞く
- [x] 録音が実際に動くことを実機で確認（16 kHz モノラル / 1 秒で 25 KB）
- [ ] **書き起こしの実行確認（未実施）** — この環境に書き起こしツールが入っていない。
      入れれば通るが、入れるかどうかは利用者が決めること
- [ ] 画面確認（未実施）

単体テスト: `extensions/nimbus/src/test/voiceInput.test.ts`（14 件）

## 決めなかったこと・やらないこと

- **音声をどこかへ送って認識させる** — 手元で完結させる。指示には社外に出せない語が混ざる
- **常時待ち受け（ホットワード）** — 常にマイクを開くことになる。要るときだけ開く
- **書き起こしツールの同梱** — 数百 MB のモデルが要る。入れるかは利用者が決める
