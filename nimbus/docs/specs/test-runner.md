# テストランナー連携（T-039 / T-108）

テストが落ちたとき、人は出力を目で追って「**どのテストが**」「**どこで**」「**なぜ**」を
組み立て直している。VS Code の Test Explorer はその 3 つを**構造として**持っているので、
そのまま渡せば読み解く手間が消える。ターミナルの出力（[T-169](terminal-capture.md)）より正確で短い。

テストランナー拡張が何であっても（Jest / Vitest / pytest / Dart / Go …）同じ形で取れるのが要点。
**フォークにした旨味が一番出る場所**（`tasks.md` 選ぶ基準 2）。

## 振る舞い

1. Test Explorer でテストを走らせ、**失敗して終わる**
2. 「テストが 3 件失敗しました」という通知が出る
3. **「セッションに投入」**を押すと、コックピットが開いて、
   落ちたテストの名前（スイートから辿った形）・ファイルと行・メッセージが送られる
4. 通知を閉じてしまっても、コマンドパレットの
   **「直近に失敗したテストをセッションに投入」**（`nimbus.sendLastTestFailure`）で拾い直せる
5. 「今後は知らせない」を押すと設定が切り替わる

## 実装

- `extensions/nimbus/src/core/testFailures.ts` — 木を歩いて失敗を取り出し、文にする（純関数）
- `extensions/nimbus/src/testWatcher.ts` — `vscode.tests.onDidChangeTestResults` の口
- `extensions/nimbus/src/extension.ts` — `TestWatcher` の生成とコマンド登録
- テスト: `extensions/nimbus/src/test/testFailures.test.ts`

## 決めたこと

**`testObserver`（提案 API）を使う。** テスト結果を読む API は安定版に無い。組み込み拡張なので
`enabledApiProposals` で有効にできる（`extensions/nimbus/package.json` と `tsconfig.json`）。
ただし**提案 API はいつか消える**ので、`onDidChangeTestResults` が無いときは
購読せずに黙って何もしない。拡張の有効化そのものを壊さないことを優先する。

**失敗した末端だけを報告する。** スイートも「失敗」として立つので、そのまま拾うと
「session」「session › イベントを正規化する」が二重に並ぶ。中に失敗を含む節は飛ばす。

**名前は親から辿って組み立てる。** `session › イベントを正規化する`。
テスト名だけでは、同名のテストが複数あるプロジェクトで特定できない。

**行は 1 起点に戻す。** VS Code の `Range` は 0 起点だが、エディタの表示と `Read` の出力は 1 起点。
モデルから見える面はそちらに揃える（[lsp-tools](lsp-tools.md) と同じ判断）。

**400ms 待ってから読む。** 実行中にも結果の配列が更新されることがあるので、落ち着いてから 1 回だけ出す。
同じ実行（`completedAt`）は二度知らせない。

**上限は 10 件・1 件あたりメッセージ 3 つ・1,200 文字。** 100 件落ちたときに全部渡しても読めない。
落とした分は「…他 N 件は省略しました」と明示する。

**通知は警告で出す。** 情報通知は数秒で消えるので、押す前に消えたら「ワンクリック」にならない。

## 回帰の検知（T-108）

**「もともと落ちている」と「いま壊した」はまったく別の話。** 混ぜて渡すと、直近の変更と
関係ないテストの修正を始めてしまう。

- 実行のたびに「**通った末端テストの名前**」を覚えておく（スイートは数えない。
  中の 1 つが落ちればスイートも落ちるので、比較の単位にならない）
- 次の実行で、そこに載っていたテストが落ちたら**回帰**として印を付ける
- 回帰は**上限で切られる前に先頭へ回す**。10 件目以降に埋もれたら意味がない
- 通知の見出しも変わる — 「前回通っていたテストが 1 件落ちました（失敗は全部で 3 件）」
- 投入する文の冒頭でも「うち N 件は**前回まで通っていた**もので、直近の変更が壊した可能性が高い」と言う

比較の基準は**そのウィンドウを開いている間**だけ持つ（永続化しない）。
最初の 1 回は基準が無いので、回帰は出ない。

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `nimbus.tests.captureFailures` | `true` | 失敗したテストを知らせる |
| `nimbus.tests.maxFailures` | `10` | 投入する失敗の件数 |

## 確認すること

- [ ] Test Explorer からテストを走らせて落とすと通知が出る
- [ ] 「セッションに投入」でコックピットが開き、名前・場所・メッセージが送られる
- [ ] 全部通ったときは通知が出ない
- [ ] スイートとテストが二重に並ばない
- [ ] 同じ実行で通知が二度出ない
- [ ] 11 件以上落ちたとき「…他 N 件」が付く
- [ ] 通知を閉じたあと `nimbus.sendLastTestFailure` で投入できる
- [ ] 「今後は知らせない」で通知が止まる
- [ ] 通ったテストをわざと壊すと「前回通っていたテストが 1 件落ちました」と出る（T-108）
- [ ] 元から落ちているテストには「前回は通っていました」が付かない
- [ ] 回帰が 11 件目以降にあっても、上限で切られずに先頭に出る
- [ ] `testObserver` が無効な状態でも拡張が正常に有効化される（ログに 1 行残るだけ）

## 残っていること

- **CI 連携は入っていない。** 「CI が赤くなったらログを取りに行く」は T-131 として別に立っている
- カバレッジ（`getDetailedCoverage`）は使っていない（T-109）
- 落ちたテストを**選んで**投入する UI は無い（今は上位 N 件をまとめて渡す）
