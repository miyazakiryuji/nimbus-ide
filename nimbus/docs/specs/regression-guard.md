# 直したものが戻らないようにする

**タスク**: T-274 / **実装**: `nimbus/scripts/regression-guard.mjs`,
`nimbus/scripts/doctor.mjs`（台帳照合）/ **規約**: [CLAUDE.md](../../../CLAUDE.md)「直したら、戻らないようにする」

## なぜ

回帰は実際に起きている。T-091（UI の多言語化）は一度直したあとに戻り、`3d3be9a5a81` で直し直した。
**戻ったことに誰も気づかないまま出荷される**のが、いちばん高くつく壊れかた。

原因は 3 つに分かれるので、対策もその 3 つに当てる。

| 原因 | 対策 |
| --- | --- |
| 並行セッションが古い前提でファイルを書き直す | 直した不具合には**回帰テストを 1 本足す**（T 番号を書く） |
| 直した振る舞いにテストが無く、壊れても緑のまま | 修正のたびに**固めた `.app` でフル実行**する |
| upstream 追従でコアの Nimbus ブロックが落ちる | 台帳照合を**赤で落ちる検査**にする |

## テストに T 番号を書く

守りがあるかどうかは、テストの本文（見出しコメントで足りる）に `T-123` が出てくるかで見る。

```bash
node nimbus/scripts/regression-guard.mjs           # 守りの無い完了を新しい順に
node nimbus/scripts/regression-guard.mjs --all     # 全部
node nimbus/scripts/regression-guard.mjs --strict  # 1 件でもあれば終了コード 1
```

見るのは**板の完了行**と、`extensions/nimbus/src/test/*.test.ts` /
`nimbus/tests/gui/cases/*.mjs` の中の T 番号。1 行にまとめて片付けた番号の組は、
**どれか 1 つが守られていれば足りる**とする（1 件の修正に 1 本で足りるため）。

**番号を書くのは、テストを消してよいか後から判断するため。** 何を守っているか分からないテストは、
邪魔になった日に消される。

## 台帳照合を赤にする（doctor §6）

`nimbus/docs/core-changes.md` に載っている＝ upstream のファイルへ Nimbus の変更を入れた、ということ。
**差分が消えているなら、その変更が落ちている。** 画面は動いてしまうので、警告では見落とす。

- 判定は「基点から**まったく触られていない**」で行う。Nimbus が新しく足したファイル（`A`）は
  upstream への変更ではないので数えない（数えると全部が赤になる）
- ディレクトリの記載（末尾が `/`）は、その下の何かが触られていれば足りているとみなす

## 決めなかったこと

- **全部の完了に回帰テストを要求する**のはやらない。仕様書だけの完了（調査・方針）に
  テストは書けないし、書けないものを赤にすると、赤を無視する習慣がつく
- CI で `--strict` を必須にするのは、棚卸し（T-278）が終わってから決める
