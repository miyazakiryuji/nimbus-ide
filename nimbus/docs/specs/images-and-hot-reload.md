# 画像の投入とホットリロード連携

## 何を解決するのか

**画像**（T-040）— UI の話は、言葉で説明するより 1 枚見せるほうが速い。
Figma のカンプや実機のスクショを貼って「この通りに直して」と言えるようにする。

**ホットリロード**（T-072）— UI の調整は「直す → 見る」を何周できるかで速さが決まる。
人間が毎回シミュレータを見て「まだズレてる」と打ち返しているうちは、その周回が
人間の速さに縛られる。**エージェント自身に見せて**、次の修正へ進ませる。

## 振る舞い

### 画像の投入（T-040）

- コックピットの入力欄に**貼り付け**（`Cmd+V`）、またはウィンドウへ**ドロップ**
- 添えた画像は入力欄の上にチップで並ぶ。**押すと外せる**（貼り間違いを送るしかないのは困る）
- 送信すると、画像 → 指示の順でモデルに渡る（Anthropic API の推奨順）
- **本文が空でも、画像だけで送れる**（「これ見て」で通じる場面がある）
- 受け付けるのは PNG / JPEG / GIF / WebP。1 枚 5MB まで
- **拡張子を信じない。** 先頭のバイト列（マジックナンバー）で種類を決める。
  貼り付け経由では名前が無いこともあり、名前は当てにならない
- 送れないものは**理由を出して**落とす（「大きすぎます（8.2MB・上限 5MB）」など）。
  黙って消すと「貼ったのに無視された」に見える

### ホットリロード連携（T-072）

**既定はオフ。** 設定 `nimbus.hotReload.enabled` を入れると動く。

1. ターンが終わる
2. そのターンで**対象の拡張子**のファイルが変わっていたか見る
   （既定 `.dart` `.swift` `.kt` `.tsx` `.jsx` `.vue` `.css`）
3. `nimbus.hotReload.reloadCommand` を実行（空なら飛ばす）
4. `nimbus.hotReload.screenshotCommand` を実行して 1 枚撮る。`{file}` が出力先に置き換わる
5. 撮れた画像を、次の指示としてセッションへ投入する

投入する指示には**周回数と、止めてよい条件**を書く:

> リロード後の画面です（2 / 3 周目）。意図したとおりになっているかを画像で確認してください。
> ズレていれば直してください。問題なければ「完了」とだけ答えて、それ以上直さないでください。

**上限は必ず効く**（`nimbus.hotReload.maxRounds`・既定 3 周）。
利用者が新しい指示を出すと周回数は 0 に戻る。

設定例（iOS シミュレータ）:

```json
"nimbus.hotReload.screenshotCommand": "xcrun simctl io booted screenshot {file}"
```

設定例（Android）:

```json
"nimbus.hotReload.screenshotCommand": "adb exec-out screencap -p > {file}"
```

## 設計

- `extensions/nimbus/src/core/attachments.ts` — 種類の判定・上限・データ URL の解釈。VS Code 非依存
- `extensions/nimbus/src/core/hotReload.ts` — **回すかどうかの判断だけ**。VS Code 非依存
- `extensions/nimbus/src/hotReload.ts` — コマンドの実行と画像の読み取り
- `extensions/nimbus/media/cockpit.js` — 貼り付け・ドロップの受け取り
- `extensions/nimbus/src/session/SessionManager.ts` — `sendMessage` / `createSession` に
  **任意引数として**画像を足した（既存の呼び出しは無変更で通る）

### 止まらなくなる形を先に潰す

スクショを送る → 直す → またスクショ、は放っておくと止まらない。
止め時を機械が決められない以上、**回数で切る**しかない。そのため:

- 判断（`shouldReload`）を純関数にして、上限で止まることをテストで固定した
- 上限 `0` を「無制限」と読まない（最低 1 周に丸める）
- コマンドは 60 秒で打ち切る（返らないコマンドでセッションを止めない）
- リロードに失敗したら撮らない（リロードできていない画面を撮っても意味がない）

- [x] 中身のバイト列から画像の種類を決める（単体テスト）
- [x] 名前が `.png` でも中身が画像でなければ送らない（単体テスト）
- [x] 空・大きすぎるものを、理由をつけて断る（単体テスト）
- [x] 既定オフ・コマンド未設定では回さない（単体テスト）
- [x] 対象の拡張子が変わったときだけ回す（単体テスト）
- [x] 上限に達したら回さない。上限 0 を無制限と読まない（単体テスト）
- [x] `{file}` を出力先に差し替える（単体テスト）
- [ ] 画面確認: スクショを貼って送り、Claude が内容に触れて答える
- [ ] 画面確認: チップの ✕ で添付を外せる
- [ ] 画面確認: `nimbus.hotReload.enabled` と `nimbus.hotReload.screenshotCommand` を設定して 1 周まわる

## 決めなかったこと・やらないこと

- **PDF・動画は受けない。** 画像 4 形式に絞る。増やすのは要ると分かってから
- **画像の縮小はしない。** 勝手に画質を落とすと「見せたもの」と「見られたもの」が
  食い違う。上限を超えたら断って、利用者に選ばせる
- **ホットリロードを既定オンにしない。** 勝手にコマンドを実行して勝手に送るのは、
  設定を書いた人だけが期待する振る舞い
- **実機ログの取り込み（T-074）はここに含めない。** 画像経路とは別の話
