# 練習用サンドボックス

壊してもいい場所を作る（T-046 / T-213）。

## 何を解決するのか

エージェントに任せるのが怖いのは、**失敗したときに何が起きるか分からない**から。
自分のリポジトリで試すと、怖くて承認を全部拒否することになる。壊れても困らない小さな場所が
あれば、承認・差分・巻き戻しをひととおり試せる。

## 振る舞い

コマンド「練習用のフォルダを作る」（`nimbus.createSandbox`）。

- **置き場は利用者に選ばせる。** 勝手にホームへ置かない — 作った本人がどこにあるか
  分からないフォルダは、消せないまま残る
- 名前は日付つき（`nimbus-sandbox-20260813`）。既にあるときは上書きせず、その旨を出す
- 置くもの
  - `README.md` — 最初にやることを順番で（指示 → 差分を読む → 確かめる）
  - `CLAUDE.md` — そのフォルダでの決まりごと
  - `src/greet.mjs` — **わざと壊してある関数**
  - `test.mjs` — いま落ちるテスト
  - `.gitignore`
- 作ったら「開く」で**別ウィンドウ**として開く（いまの作業を閉じさせない）

**直すところがある状態で置く。** 動くだけのサンプルは練習にならない。

## 設計

- `extensions/nimbus/src/core/sandbox.ts` — 中身の組み立て（VS Code 非依存）
- `extensions/nimbus/src/sandbox.ts` — 置き場の選択・書き出し・別ウィンドウ

## 受け入れ条件

- [x] 練習に要る 5 つのファイルがそろう
- [x] テストが最初から落ちる（直すところがある）
- [x] README に最初にやることが順番で書いてある
- [x] 名前が日付つきで、何度作っても混ざらない
- [x] 既にあるときは上書きしない
- [ ] 画面確認（実際に作って開く・未実施）

単体テスト: `extensions/nimbus/src/test/sandbox.test.ts`（6 件）

## 決めなかったこと・やらないこと

- **Flutter のサンプル** — `flutter create` のほうが確実。ここは Nimbus の操作を試す場所
- **同梱して初回起動時に置くこと** — 頼まれてもいないフォルダを作らない
