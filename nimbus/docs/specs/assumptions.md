# 置いた仮定の表示

## 何を解決するのか

エージェントは、足りない情報を**自分で埋めて**進む。埋めること自体は悪くないが、それが本文の
中に紛れると読み飛ばされ、違っていたと気づくのは成果物を見たあとになる。
だから「置いた仮定」だけを抜き出し、本文とは別に目立たせる。

## 振る舞い

コックピットで Claude の応答に仮定が含まれていると、本文の直後に「**置いた仮定**」という
枠が出て、該当の文が箇条書きで並ぶ（注意色の縁で本文と区別する）。

拾うのは次の言い回しを含む文。

- 「〜と仮定して」「〜と想定します」
- 「〜前提として」「〜前提で」
- 「とりあえず／ひとまず／一旦 〜で進めます」
- 「〜とみなして」
- 英語の `assume` / `assuming` / `I'll assume` / `for now ... use`

**拾わない**もの:

- 否定形（「仮定せず、実際の値を読みます」）
- 疑問形（「UTC と仮定してよいですか？」— これは確認であって仮定ではない）
- 普通の説明文

同じ文が繰り返されたら 1 つにまとめ、160 文字を超える文は畳む。

## 設計

- 抽出: `extensions/nimbus/src/core/assumptions.ts`（VS Code 非依存・テスト 12 件）
- 付与: `CockpitViewProvider.post()` が `assistant-text` を見て `assumptions` を添える
- 描画: `media/cockpit.js` の `renderAssumptions()`／`media/cockpit.css` の `.entry.assumption`

`extension.ts` には手を入れていない（複数セッションが同時に触るため、表示の都合は
コックピット側で完結させた）。

## 受け入れ条件

- [x] 仮定を含む応答で、本文とは別に「置いた仮定」が出る
- [x] 否定形・疑問形・普通の説明文は拾わない
- [x] 重複はまとめ、長すぎる文は畳む
- [ ] 画面での確認（GUI テストのケース追加は未実施）

## 決めなかったこと・やらないこと

- **モデルに追加で問い合わせない。** 費用と待ち時間が増えるうえ、「仮定を述べよ」と指示すると、
  本来なら聞き返すべき場面でも仮定して進むようになる（T-185 と逆向きに働く）
- **仮定を承認・却下させない。** それは承認インボックス（ツール実行前）の役目で、
  ここは「気づける」ところまでを担う
