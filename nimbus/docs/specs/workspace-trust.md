# 信頼していないフォルダでの振る舞い

## 何を解決するのか

Claude はフォルダの中でコマンドを実行し、ファイルを書き換える。中身を確認していないフォルダで
それを走らせてはいけない。一方で、**安全のために製品ごと消えてしまうと利用者は理由に気づけない**。

## 振る舞い

信頼していないフォルダ（VS Code の制限モード）では:

- **画面は開く。** アクティビティバーの Nimbus も、各ビューもそのまま出る
- **Claude は実行しない。** 送信・ゆあへの質問・タスク作成のいずれも、実行前に断る
- 断るときは理由と一緒に「このフォルダを信頼する」ボタンを出す。押すと VS Code の信頼設定が開く

信頼したあとは、通常どおり動く（再起動は不要）。

## 設計

- `package.json` の `capabilities.untrustedWorkspaces.supported: "limited"`
- `extension.ts` の `requireTrust()` を、実行の入口 3 か所（`send` / `askYua` / `newTask`）で通す

## なぜ `false` をやめたか

`supported: false` だと VS Code が**拡張ごと無効化**する。結果としてアクティビティバーから
アイコンが消え、利用者には「フォルダを開いたら Nimbus が無くなった」ように見える。
理由も直しかたも画面に出ないので、壊れたと受け取られる（実際にその報告を受けた）。

安全性は「実行しない」ことで担保できる。**見えなくする必要はない。**

## 受け入れ条件

- [x] 制限モードでもアクティビティバーに Nimbus が出る（GUI テスト 22）
- [x] 制限モードの表示が画面に出ている（同）
- [ ] 制限モードで送信すると信頼を求めるダイアログが出る（GUI ケース未追加）

## 決めなかったこと・やらないこと

- **信頼を自動で与えない。** 「一度信頼したら以後すべて」も含めて、判断は利用者に残す
- **読み取りだけ許す、のような中間状態は作らない。** Claude Code は起動時点で
  プロジェクトの設定やファイルを読むため、線を引く場所として分かりにくい
