# Command completion（ドットから IDE アクション）

## 何を解決するのか

IDE の操作にたどり着く道が「ショートカットを覚えている」か「コマンドパレットを開く」しかない。
前者は覚えられないし、後者は**キャレットを手放してモーダルへ移る**ので、書いている流れが切れる。
IntelliJ IDEA 2025.3 の command completion と同じく、エディタでドットを打つだけで
アクションに届くようにする。

## 振る舞い

### 出しかた

エディタでコードを書いている途中に `.` を打つ。補完候補として IDE のアクションが並ぶ。
選ぶと**打った `.` と、その後に入力した文字が消えて**、アクションが実行される。
テキストは何も挿入されない（`.` を打つ前の状態に戻ってからアクションが走る）。

### 何が出るか

| 入力 | 出るもの |
|---|---|
| `.` だけ | **エディタのコンテキストメニュー**の項目 |
| `.` のあとに文字 | **コマンドパレット全体**からあいまい一致（上限 12 件） |

`.` だけのときにコンテキストメニューを使うのは、VS Code が既に
「キャレット位置のコードに対して何ができるか」として整理してくれている一覧だから。
文字を打ち始めたら特定の何かを名指ししているので、そこで全体に広げる。

### 出さない場面

ドットはコードでも日常的に使うので、**行き過ぎない**ことを優先している。

- 直前が `.` のとき（`0..10` のような範囲・スプレッド）
- ドットと文字の連なりが途切れているとき（`a.b(c` のようにキャレット直前が単語でない）
- ドットからの文字数が 30 を超えたとき（もう普通にコードを書いている）
- 一致するアクションが 0 件のとき（通常の補完を邪魔しない）

### 対象

全スキームのテキストモデル。言語を問わず使える。

## 設計

| ファイル | 役割 |
|---|---|
| `contrib/commandCompletion/common/commandCompletion.ts` | `findCommandTrigger`（ドットと入力語の切り出し）と上限値 |
| `contrib/commandCompletion/browser/commandCompletion.contribution.ts` | `CompletionItemProvider` の実装と登録 |
| `contrib/commandCompletion/test/common/commandCompletion.test.ts` | トリガ判定のテスト（3 件） |

起動経路は `sessions.common.main.ts` の `// Command completion` セクション。

補完項目は `insertText: ''` と、ドットから現在位置までを覆う `range` を持つ。
実行は `CompletionItem.command` に委ねる。**「文字を消してからコマンドを走らせる」を
補完の仕組みだけで実現している**ので、独自の編集操作は書いていない。

`incomplete: true` を返し、文字を打つたびに問い合わせ直す（対象メニューが切り替わるため）。

### 配色について

独自 CSS なし。通常の補完ウィジェットに乗るので、テーマ（T-001 の Claude 配色）に従う。
アクションであることは `CompletionItemKind.Event` のアイコンで示す。

## 受け入れ条件

- [ ] エディタで `.` を打つとコンテキストメニュー相当のアクションが候補に出る
- [ ] 選ぶと `.` が消え、テキストが増えないままアクションが実行される
- [ ] `.` のあとに文字を打つとコマンドパレット全体から絞り込まれる
- [ ] `0..10` と打っても候補が出ない
- [ ] 長い識別子を書いていても割り込まない
- [ ] 通常のコード補完（メンバー補完）を潰していない
- [ ] Nimbus Dark / Light の両方で候補の見た目が破綻しない

確認記録は `../testing/command-completion.md`。

## 決めなかったこと・やらないこと

- **オン／オフの設定は今は足さない** — まず既定で使ってみて、邪魔になるか見てから。
  邪魔になる場面（`0..10` など）は判定側で先に潰してある
- **AI アクションや Postfix テンプレートは混ぜない**（IntelliJ 2026.1 は混ぜている）—
  まず IDE アクションだけで有用性を確かめる
- **ドット以外のトリガ文字は足さない** — 誤爆の面が広がる
