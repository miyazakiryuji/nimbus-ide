# 使い始めの準備（迷わせない）

## 何を解決するのか

**実際に利用者が Claude Code の繋ぎかたで迷った。** 原因は機能ではなく導線だった。

- 初回の案内が**存在しなかった**（`firstRun` の分岐が 1 つも無い）
- セットアップウィザードはあるが、**コマンド名を知っている人しか辿り着けない**（人間工学 E4）
- Claude Code が見つからないときの案内は、*送ろうとして初めて*トーストで出る。
  しかも中身は「設定 `nimbus.claudeCodeExecutable` にパスを指定してください」──
  **設定名を告げるだけで、その場では直せない**

つまり、詰まる場所（コックピット）と直す場所（設定画面）が離れていて、
しかも詰まったことに気づくのが**送ったあと**だった。

## 振る舞い

### 詰まる場所に、直す手段ごと出す

コックピットの空の面に「**使い始める前に**」を出す。頼みかたの案内より**先**に出す ──
送れない状態で「Enter で送ります」だけ読ませても迷わせるだけなので。

```
使い始める前に
あと 2 件で送れるようになります。

  ⚠ Claude Code
    見つかりません。入れるか、置いてある場所を指定してください。
    [ 場所を指定する ] [ 入れかたを見る ] [ もう一度さがす ]

  ⚠ 信頼
    信頼していないフォルダでは実行しません。画面は開けますが、送っても走りません。
    [ このフォルダを信頼する ]
```

**残り件数を数字で出す。** 「準備が要ります」だけだと、あと何をすれば終わるのか決められない。

### 見るもの

| 項目 | 止めるか | 何を見ているか |
| --- | --- | --- |
| Claude Code | **止める** | `resolveClaudeExecutable()`。リモートに繋いでいるときは「**繋いだ先**に要る」と言う |
| フォルダ | **止める** | 開いていなければ、Claude が動く場所が無い |
| 信頼 | **止める** | 信頼していないと、画面は開けても送っても走らない（T-241） |
| 認証と課金 | 止めない | 一度動かすまで分からない。分かったら課金モードを出す |

フォルダを開いていないときは、信頼を聞かない（順番として意味がない）。

### 押したら直るところまで

**設定名を教えるのをやめる。** 押した先で完了するようにした（T-244 / 人間工学 E1）。

| ボタン | 何が起きるか |
| --- | --- |
| 場所を指定する | ファイル選択 → **ユーザー設定**へ書く → その場で使えるか確かめて答える |
| 入れかたを見る | 公式手順を開く / 入れるコマンドをターミナルへ出す（**実行はしない**） |
| もう一度さがす | 探し直して、結果を必ず言う（何も出ないと押せたのか分からない） |
| フォルダを開く | フォルダを開く |
| このフォルダを信頼する | 信頼の面を開く |

書き先を**ユーザー設定**にしているのは、実行ファイルの場所がマシンの話だから。
ワークスペースに書くと、別のフォルダを開いたときにまた迷う。

### 気づける場所を 2 つ持つ

- **場所で引く**: コックピットの面。ステータスバーに `⚠ Nimbus — 準備 1 件（信頼）`
  （足りているときは出さない）
- **名前で引く**: コマンド「Nimbus: はじめの準備を開く」ほか 3 本

片方だけだと、名前を知らない人か、面を開いていない人のどちらかが取り残される（人間工学 E4）。

### 直したら、その場で消える

設定の変更・信頼の付与・フォルダの追加を拾って配り直す。
開いたまま直したときに、card がその場で消えないと「効いたのか」が分からない。

## 設計

- 判断は `src/core/readiness.ts`（vscode 非依存・モジュールテスト 8 件）。
  操作は `src/setupActions.ts`
- **webview のボタンは、許したコマンドしか走らせない**（`ALLOWED_ACTIONS`）。
  画面から任意のコマンドを呼べる状態にはしない
- 課金モードは `session-init` が返る `apiKeySource` で確定する。
  それまでは `unknown` として**止めない**（動かしてみないと分からないものは、止める理由にならない）

## 受け入れ条件

- [x] 送る前に、足りないものがコックピットに出る（GUI ケース 50・`--untrusted`）
- [x] 残り件数が数字で出る（同）
- [x] ボタンを**押すと実際に画面が応える**（同 — 信頼の面が開く）
- [x] コマンド「準備をもう一度さがす」が**必ず答えを返す**（同）
- [x] リモートに繋いでいるときは「繋いだ先に要る」と言う（モジュールテスト）
- [x] フォルダを開いていないときは信頼を聞かない（モジュールテスト）
- [x] 許していないコマンドは画面から走らせられない（モジュールテスト）
- [ ] **Claude Code が無いとき**の見えかたは、入っている環境では作れないので確認していない。
      判断はモジュールテストで見ていて、描画とボタンは信頼の経路と同じ実装を通る

## 決めなかったこと・やらないこと

- **勝手に入れない。** `npm install -g` を代わりに走らせることはしない。
  ターミナルへ出すところまでで、走らせるかは利用者が決める（人間工学 E3）
- **認証を代行しない。** `claude login` は Claude Code 側の領分で、
  Nimbus が肩代わりすると、どこで認証したのかが分からなくなる
- **初回だけのツアーは作らない。** 一度きりの案内は、二度目に困った人を助けない。
  足りないときは**いつでも**出る形にした
