# Flutter の確認（文言・読み上げ）

出す前に気づきたいことを Dart のソースから拾う（T-194 / T-195）。

## 何を解決するのか

どちらも「動くので気づかない」たぐいのもの。日本語のまま出荷される文言も、読み上げに何も
渡らない画像も、動作としては正しく見える。**気づく機会がどこにも無い**のが問題。

## 振る舞い

コマンド「Flutter の確認（文言・読み上げ）」（`nimbus.openFlutterLint`）。

- ワークスペースの `.dart` を最大 400 件読む。`build` / `.dart_tool` / 各プラットフォームの
  フォルダと、生成物（`*.g.dart` / `*.freezed.dart`）は見ない
- 拾うもの

  | 種類 | 条件 |
  | --- | --- |
  | 直書きの文言 | `Text('…')` に**日本語**が含まれ、同じ行に国際化の呼び出しが無い |
  | 読み上げに渡らない画像 | `Image.*(` に `semanticLabel` が無い |
  | 名前の無いボタン | `IconButton(` に `tooltip` が無い |

- **拾わない条件を優先する。** 誤検知が続くと、この手の指摘は読まれなくなる
  - `l10n` / `AppLocalizations` / `S.of` / `intl` / `tr(` が同じ行にあれば触らない
  - 英語だけの文字列は拾わない（識別子と見分けがつかない）
  - コメント行は見ない
  - **引数は複数行に散るので、続く 6 行もあわせて見る**（`IconButton(\n  tooltip: …` を誤って
    「無い」と言わないため）
- 直書きが見つかったら、`.arb` に足す形（重複を畳んだ JSON）も出す。**キーは人が決める**

## 設計

- `extensions/nimbus/src/core/flutterLint.ts` — 判定（VS Code 非依存）
- `extensions/nimbus/src/flutterLint.ts` — ファイル収集とコマンド

`analyzer` は持ち込まない（同梱物が増える）。行の見た目で拾い、迷ったら拾わない。

## 受け入れ条件

- [x] 日本語の直書きを拾い、国際化済みの行は拾わない
- [x] 英語だけの文字列・コメント行を拾わない
- [x] `semanticLabel` / `tooltip` が無いものを拾う
- [x] 引数が複数行に散っていても誤検知しない
- [x] `.arb` の候補を重複なく出す
- [x] 画面確認: 実際の Flutter プロジェクトで開き、置いた問題を拾う
      — GUI ケース `35-flutter-commands.mjs`（食い違いのある `pubspec` と直書き文言のある `.dart` を置いて開く。Flutter SDK は要らない）

単体テスト: `extensions/nimbus/src/test/flutterLint.test.ts`（10 件）

## 決めなかったこと・やらないこと

- **自動で `.arb` へ書き出すこと** — キーの付け方は設計。機械が付けると後で読めなくなる
- **タップ領域の大きさの判定** — レイアウトを実際に組まないと分からない。静的には測れない
