# セッションの台帳（持ち主・横断の上限・続きから・場所の重なり）

**タスク**: T-247 / T-250 / T-251 / T-252 / T-253 /
**実装**: `extensions/nimbus/src/core/sessionRegistry.ts`（判断）,
`extensions/nimbus/src/sessionStore.ts`（読み書き）, `extensions/nimbus/src/extension.ts`（配線） /
**テスト**: `src/test/sessionRegistry.test.ts`, `src/test/sessionStore.test.ts` /
**計測**: [parallel-load](../testing/parallel-load.md)

## なぜ

`session/SessionManager.ts` はセッションを `Map` で持っている。この `Map` は
**そのウィンドウ（＝拡張ホスト）の中にしか無い**。ウィンドウごとに別の SessionManager が立つので、

- 落ちたら、走っていたセッションは誰からも見えなくなる（`session_id` は Claude 側に残っているのに）
- 同じセッションを 2 つのウィンドウから触れてしまう
- 「今いくつ走っているか」がウィンドウの中でしか数えられず、上限 2 のはずが 4 つ走る
- 同じフォルダを別のウィンドウが編集していても気づけない

Nimbus の狙いは「複数のエージェントで同時に同じプロジェクトを開発すること」なので、
この 4 つは**そのうち起きる問題**ではなく、**並列にした時点で必ず起きる問題**になる。

## 置き場所 — 1 セッション 1 ファイル

`<globalStorage>/sessions/<sessionId>.json` に 1 件ずつ書く。

全部を 1 つの JSON に入れると、書くたびに「全部読んで全部書き直す」ことになり、
**同時に書いた分が黙って消える**。実測で、4 プロセスから 200 件ずつ書いて **半分が消えた**
（[計測](../testing/parallel-load.md)）。ファイルを分ければ書き手が重ならないので、そもそも競合しない。
横断で見たいときはディレクトリを読む。

書くときは別名で書いてから `rename` する。書いている途中に他のウィンドウが読んでも、
尻切れの JSON を掴まない（`rename` は不可分）。

## 持ち主 — 心拍で持つ

ロックを「取ったら離すもの」にすると、落ちたときに離されず、**誰も触れない記録**が残る。
そこで心拍で持つ。持ち主は 5 秒ごとに時刻を書き直し、**20 秒途切れたら手放したと見なす**。

| | 意味 |
| --- | --- |
| 心拍が生きている・自分 | このウィンドウのもの。ふつうに操作できる |
| 心拍が生きている・他人 | **触らせない**。二重に触ると片方の前提が壊れる |
| 心拍が切れている | 持ち主なし。「続きから」で引き取れる |

閉じるときは心拍を過去に倒して手放す（`release()`）。次に開いたとき、20 秒待たずに続きから戻せる。

## 同時実行の上限は 1 か所で数える（T-251）

上限の設定は `nimbus.tasks.maxConcurrent`（既定 2）のまま**増やさない**。数え方だけを変えた。

- **数えるのは台帳**。板（カンバン）から起きたものも、コックピットから直に始めたものも、
  別ウィンドウのものも、同じ 1 つの数に入る
- 数えるのは `starting` / `running` だけ。**入力待ちは数えない**（人間の番なので枠を占めない）
- 心拍が切れた記録は数えない（プロセスが死んでいるなら走っていない）
- 板が使ってよい枠は「上限 − 板の外で走っている数」。板の外が増えると板の枠が減る
- 上限に達したら**始めずに理由を出す**。コックピットで断られたときは、打った文を Outbox へ預ける

いま何本走っているかはステータスバーのツールチップに出る。一覧は
コマンド「Nimbus: 走っているセッションを見る」（`nimbus.showSessions`）。

## 落ちた・閉じたあとの復帰（T-252）

開いた直後に、**持ち主のいない・終わっていない・鍵（`claudeSessionId`）がある**記録を探し、
あれば「続きから」を出す。開いているフォルダの配下のものだけを候補にする
（別プロジェクトの続きを出しても選べない）。

続きから開くときは **Nimbus 側の ID を引き継ぐ**。ID を採り直すと、同じ作業の記録が
台帳にもイベントにも二重に残る。

自動確認（`NIMBUS_SMOKE`）のときは黙る — 画面に出す知らせが GUI 操作の邪魔になる。

## 作業場所の重なり（T-253）

セッションを始めるとき、生きている他のセッションと作業ディレクトリが重なっていたら知らせる。
同じフォルダ・親子関係のどちらも重なりとして扱う（`/w/app` と `/w/app2` は重ならない）。

**止めはしない。** 意図してやることもある。起きること（片方が読んだ内容が黙って古くなる）と、
避けかた（worktree を切る）を添えて、判断は人に返す。ボタンからそのままタスクを作れる。

## 監査ログも追記だけにする（T-250）

同じ壊れかたが監査ログ（`extension.ts` の `appendAudit`）にもあった。
読んで書き直す方式だったので、**4 プロセスから 800 行書いて 3 行しか残らなかった**。
`appendFile`（`O_APPEND`）に変えて 800/800 に。ファイルが育っても 1 行の追記は遅くならない。

## 決めなかったこと

- **書き込みを 1 か所へ直列化するキュー**は作らない。書き手を分ければ競合しないので、
  直列化する対象がそもそも無い（増やすと遅くなるだけ）
- **面の畳み直しの間引き**は入れない。2,000 件でも 1 回 0.1ms で、間引く価値が無いと測って分かった
  （[計測](../testing/parallel-load.md)）
