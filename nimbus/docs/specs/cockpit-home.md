# コックピットのタブ（束）と Home

**タスク**: T-314 / **すり合わせ**: 2026-08-25 に利用者と合意 /
**実装**: `src/core/sessionGroups.ts`（判断）・`src/groupStore.ts`（読み書き）・
`media/cockpit.js` / `cockpit.css` / `CockpitViewProvider.ts` / `extension.ts`（配線） /
**テスト**: `sessionGroups.test.ts`（10 件）・`groupStore.test.ts`（4 件）・GUI ケース 54 / 57

## 合意した形

1. **タブ = Nimbus のセッションを入れる自由な束。** フォルダやタスク板とは結合しない。
   好きに作って、好きなセッションを入れる
2. **サイドバーの縮小版コックピットが Home。** タブごとの束で全セッションと状態が見え、
   セッションを押すと**その場で会話に切り替わる**（家アイコンで Home へ戻る）
3. ~~狭いサイドバーでは、セッションの列を並べない~~ **改訂（T-338・2026-08-27）:
   狭い面でもセッションの列を出す。** 畳んだ結果、いつも見えていたタブが消え、
   1 日に何十回の切り替えが想起頼みの ≡ の奥に落ちて「タブを切り替えられない」と
   報告された（人間工学 E1/E4 — 頻度が入口の段を決める・名前を知らない人が辿り着けるか）。
   タブは縮む（T-291）ので狭くても並ぶ。**≡ は列の先頭に住み**、Home（束の俯瞰と
   「続きから」）の入口として残る。帯（home-bar）は「前回のセッションが N 本」の
   案内専用になった。広い面の 2 段（上にタブ列、下にセッション列）はそのまま
4. **タブもセッションも改名できる。** セッションの改名は T-313（別セッション実装中）の
   受け持ちで、ここでは**重複させない**。タブの改名がこちら
5. **セッションの列は、横一列ではなく左の縦レール**（T-341・2026-08-29 改訂）。
   横一列は**幅を全員で分け合う**ので、本数が増えるほど 1 枚が痩せる — 実測の画面で
   4 本開くと 1 枚 75px、名前に残るのは 30px＝2 文字（「4 基…」「5 新…」）。
   3 項で「縮んでも並ぶ」としたが、**縮んだ先で名前が読めなくなっていた**。
   縦なら 1 行まるごとが名前の場所になり、本数が増えても 1 枚の幅は痩せない。
   前面の印は下線から**左の縦線**へ。≡ は列の頭、＋ は列の末尾。
   1 本しか無いときは列を出さず、**≡ の入口だけ残して幅を返す**（3 項の決めごとは守る）

```
┌─ 縮小版（サイドバー）= Home ─────────┐      ┌─ 会話（T-341 以後）─────────────────┐
│ ▾ ■ 作業                      [+]   │      │ ≡           │                      │
│     ▶ 調査する            作業中    │  ⇄   │ • 1 調査する │ （会話）             │
│ ▾ ■ ログイン改修          ✎  [+]   │      │ ▌2 実装する │                      │
│     ! 実装する          許可待ち    │      │ • 3 見直し   │                      │
│ ［新しいタブ］                      │      │ +           │                      │
└─────────────────────────────────────┘      └─────────────┴──────────────────────┘
                                              ← 200〜300px →   ▌= 前面（左の縦線）
広い面（エディタタブ・全画面）: 上に [■作業][■ログイン改修]（タブ＝束の列）、
                                左に セッションの縦レール
```

**幅の決めかた**（T-341）: レールの**既定**は `clamp(200px, 40%, 300px)`。下限 200px は
「一覧として読める幅」（利用者指示「cmux 並みに」）で、名前に 180px 前後が残り日本語で 15 字ほど入る。
コックピット自体の既定幅もコアで 300px → 560px に広げた（台帳 #28）。
**既に幅を覚えている環境には効かない** — 新しいプロファイルと「ビューの位置をリセット」で効く。

**境目は掴んで動かせる**（T-342・利用者依頼 2026-08-29）。既定の分け前が誰にとっても正しいことは
ないので、決めるのは利用者に渡す。VS Code の sash と同じ作法にそろえた:

- 見た目 4px・当たり判定は左右へ 2px ずつ広げる（4px は指で当てにくい）。指を置くと少し待ってから
  線が出る（すぐ光ると通り道で点滅する）
- 掴んだあとは **pointer capture** で面の外へ出ても追いかける（境目から外れた瞬間に止まると掴み直しになる）
- **列 150px・会話 200px は必ず残す。** どちらかが消えると、そこに何があったか分からなくなる
- **ダブルクリックで既定へ戻す**（引きすぎたときの戻り道）。←→ でも動かせる（Shift で 3 倍）
- **覚えるのは面ごと**（`vscode.setState`）— サイドバーと全画面では適切な幅が違うので、
  拡張側の 1 つの設定に寄せるとどちらかが必ず外れる
- 列を畳んでいる（セッション 1 本）ときは境目も出さない。掴んだ先に何も無い面を作らない

## 横断の一覧も束で畳む（T-316）

「走っているセッションを見る」（`nimbus.showSessions`）も、同じ束（`groups.json` は
**globalStorage** なので**別のウィンドウのぶんも同じ束に入る**）で畳んで見せる。

- 束の順は「既定 → 作った順」。中身の無い束は出さない。束が 1 つだけなら見出しを出さない
- **束の中は許可待ちが先頭**（一覧を開く動機は「この仕事はいまどこで止まっているか」）。
  見出しにも `許可待ち N` を出す
- 許可待ちの判定はこのウィンドウの承認キュー（別ウィンドウの待ちは台帳に無いので数えない —
  数えられないものを数えたふりをしない）
- 並びの判断は `core/sessionGroups.ts` の `listByGroup`（テスト済み）
- **親子（分岐の由来）は持たない** — セッションの分岐（T-036）が入ったときに、
  そのタスクと一緒に足す（無い機能の記録だけ先に増やさない）

## 決めたこと

- **既定タブ「作業」**にどの束にも入っていないセッションが入る。タブという概念が増えても、
  既存のセッションが行き場を失わない（後方互換）。既定タブは**消せない・改名できない** —
  消せると「未所属」という 2 つ目の行き場が要る
- **タブを消しても、中のセッションは既定タブへ戻る。** 束は持ち主ではない。
  畳んだらセッションごと消える、は軽い操作に載せる結果として重すぎる（人間工学 E3）
- **タブ名**: 空白だけは断る・30 文字を超えたら**切らずに断る**（黙って切ると
  「付けた名前と違う」が起きる）・同名は許す（禁止すると「作業 2」を強いる）
- **空のタブも Home に出す。** 作った直後に見えないと「作れたのか」が分からない（T-244）

## 永続化（groups.json）

台帳（1 セッション 1 ファイル）と違い、**1 ファイル**。タブの定義と所属は
作る・改名・入れ替えのときにしか変わらず、書き込みの性格が違う。

- 形: `{ groups: [{id,name,createdAt,order}], members: {sessionId: groupId} }`
- 置き場所: 台帳と同じ `globalStorage/idris.nimbus/`
- 書きかたは台帳と同じ **別名 → rename**（不可分）。同一ウィンドウ内の連続更新は
  **読み→変換→書きを直列化**して互いの上書きを防ぐ（テストで固定）。
  ウィンドウをまたぐ同時書きは後勝ちを受け入れる — 賭けているのはタブ名と所属だけで、
  セッション本体は台帳にある（負けても取り返しがつく）
- 壊れた JSON は**形として通る分だけ拾う**。定義の消えたタブへの所属は既定タブとして扱う
  （groups.json が半端でも Home が開かなくなることはない）
- 消えたセッションの所属は掃除する（`pruneMembers` — 台帳の `sweep()` と同じ発想）

## UI 配線

- **狭い⇄広いは幅だけで決める**（CSS の 520px 境界）。同じ webview がサイドバーでも
  エディタタブでも全画面でも、置かれた場所にふさわしく振る舞う
  - 狭い: セッション列を出さず **≡ の行**（≡ ＋ 前面セッションの丸・番号・名前）。
    ≡ で Home（束一覧）と会話が入れ替わる
  - 広い: 上段にタブ（束）列、下段に**そのタブのセッション列**。タブ列は束が 2 つ以上の
    ときだけ出す（1 つなら従来と同じ見た目 = 後方互換）
- Home の行は**タブ列と同じ材料**（丸・記号・番号・名前・状態の言葉）で描く。
  読み手の頭を切り替えさせない
- 名前の入力・移動先の選択は**拡張側の InputBox / QuickPick**。webview に入力 UI を
  増やさない（検証 `normalizeGroupName` を 1 か所に寄せる）
- タブの操作: Home の見出しの ✎（改名）と ×（閉じる）・［＋ 新しいタブ］。
  広い面はタブのダブルクリック（改名）・×・＋。**× に確認は出さない** —
  中のセッションは「作業」へ戻るだけで消えない（T-316 の × と同じ言い分け）
- セッションの「移す」は Home の行に置く。**下書きには出さない**（下書き → 本物で
  ID が変わるので、所属が迷子になる）
- Home の開閉は provider が覚え、面を開き直したときに戻す

## 下書きは、手を離しただけでは消えない（T-343）

「まだ始まっていないセッション」は拡張が**下書き**として持ち、最初の 1 通を送った時点で本物になる。
そのとき下書きのタブは畳んで本物へ番号を引き継ぐ（T-316）。

**この畳みは `activeSessionId` と `activeDraftId` の同時成立から推測して動く。**
だから「別のセッションを前面にした」経路では、その前に `activeDraftId` を外す責任が
前面を変える側（`switchSession` / `resumeRecord` / 一覧から再開）にある。
外し忘れると、**押してもいない下書きが消える** — 実際に起きた（利用者報告 2026-08-29）。
下書きが 2 本のうち 1 本だったので、消えた結果セッションが 1 本になり、
列は 2 本以上でしか出ないため**列ごと画面から消えた**（実測 2 → 0）。

推測で動く場所は、押した結果を数えて守る（GUI ケース 64）。

## 決めなかったこと・やらないこと

- **タブの並び替え UI は初回では作らない**（`order` は持っているので、要るなら足すだけ）
- **タブごとの一括操作（全部止める等）は載せない** — 束は見るための単位で、
  操作の単位にすると誤爆が束単位になる
