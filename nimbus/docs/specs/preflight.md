# 出す前に

出す直前に確かめることを、決めた順で見る（T-215）。

## 何を解決するのか

事故は、知らなかったから起きるのではない。**確かめる順番を決めていないから**起きる。
「テスト通したっけ」「コミットしてない変更あったかも」を、出すたびに思い出している。

## 振る舞い

コマンド「出す前に見る」（`nimbus.openPreflight`）。最初に、どこまで見るかを聞く。

- **確かめずに分かることだけ** — Git の状態と、変更した行。すぐ終わる
- **テストとビルドも走らせる** — 時間がかかる。**黙って重いものを走らせない**

見るもの:

| | 見るもの | 止める / 知らせる |
| --- | --- | --- |
| ブランチ | 出す先と同じか | 知らせる |
| コミットしていない変更 | `git status` | **止める**（出したものと手元が食い違う） |
| push していないコミット | `@{u}..HEAD` | **止める**（手元にしかない変更は出た先に入らない） |
| テスト / ビルド | 走らせたときだけ | 落ちていれば**止める** |
| `.only(` | 変更した行 | **止める**（他のテストが走っていない） |
| 消し忘れ | `debugger` / `console.log` / `FIXME` / `XXX` | 知らせる |
| 版 | 前回のタグから上がったか | 知らせる |

**走らせていない確認を `ok` にしない。** 「まだ見ていない」と「見て問題なかった」は違う。
一緒にすると、チェックリストが「押すだけのボタン」になる。

**全部を赤くしない。** 赤いのが普通になると、誰も読まなくなる。だから止めるのは
「出したものが意図と違う」ものだけで、消し忘れは知らせるに留める。
