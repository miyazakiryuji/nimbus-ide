# 画面の置きかた（サイドバー・パネル・コマンド）

## 何を解決するのか

機能が増えるたびにサイドバーへ 1 段足していったら 13 段になり、**どれも見なくなった**。
常に見えているべきものと、必要なときだけ開くもの、原因を追うときだけ見るものを分ける。

## 振る舞い

### サイドバー（アクティビティバーの雲アイコン）— 常用の 5 段

| ビュー | 既定 | なぜここか |
| --- | --- | --- |
| コックピット | 開いた状態 | 主戦場。ここで指示を出す |
| 承認待ち | 畳む | **止まっていることに気づけないと困る**（置き場所は検討中・T-263） |
| レビュー | 出さない | 出てきた変更を見る。常用の段を絞るため外した（T-255） |
| 文脈 | 出さない | 何が渡っているかを確かめる。同上（T-255） |

レビューと文脈は**消していない**。コマンド「Nimbus: レビューを開く」「Nimbus: 文脈を開く」で開く。

### 下部パネル「Nimbus 診断」— 原因を追うとき

セッションの中身 / 時系列（デバッグ）/ 使用量 / MCP サーバー。
コマンド **「Nimbus: 診断パネルを開く」** で開く。

### アクティビティバー「Nimbus タスク」（一覧の雲アイコン）— 走っているものを見るとき

タスク板。**サイドバーの一段ではなく専用のアイコンに独立させた**（T-256）。
並列で走っているものは、この製品の肝のひとつで、畳まれた一段では狭い。

板の列は **To Do / In Progress / Needs Approval / In Review / Done** と英語で揃える（T-257）。
一部だけ日本語に残すと 1 枚の板に 2 つの言語が混ざって読みにくい。

### アクティビティバー「Nimbus 設定」（歯車の雲アイコン）— 設えを触るとき

スキル / CLAUDE.md / 設定 / ゆあに聞く。**常用サイドバーの段には出さない。**
ヘルプは「迷ったときの入口」なので、設えを触る部屋にまとめた（T-265）。
アイコンを押すか、次のコマンドで開く（開くとこのコンテナに切り替わる）。

- 「Nimbus: スキル一覧を開く」
- 「Nimbus: CLAUDE.md を開く」
- 「Nimbus: 設定ビューを開く」

以前はこの 3 本を常用サイドバーに `visibility: hidden` で置いていた。
しかし**コマンドで一度開くと段として居座り、常用 5 段の枠を食い直す** — T-239 で直したことが、
開いた瞬間に戻っていた。別のコンテナへ移すと、何度開いても常用の段は増えない。
アイコンとして常に見えるので、コマンド名を知らない人でも辿り着ける（人間工学 E4）。

アイコンは雲を家族マークとして残し、下半分だけを替えてある。
24px の単色マスクでは、**細い斜線（雨）・丸い塊（歯車）・太い横棒（一覧）くらい
質感が違わないと見分けがつかない**。

### アクティビティバー「Nimbus デバッグ」（虫雲アイコン）— 詰まったとき

エージェントが詰まったときの 3 問だけを出す面 ── *何が失敗したか* /
*同じところを回っていないか* / *何を渡して何が返ったか*。
診断パネルと分けたのは**頻度が違う**から。全部を眺めるのは時々だが、
「何が失敗した」は詰まっているあいだずっと見る（人間工学 E1）。

**失敗が出るとアイコンにバッジが出る**ので、面を開いていなくても気づける。
アイコンは雲＋虫（雨＝Nimbus / 歯車＝設定 / 一覧＝タスク と質感で分ける）。
中身は [debug-view](debug-view.md)。

### 標準のデバッグは出さない（T-246 → T-249）

VS Code 標準の「実行とデバッグ」は、**アクティビティバーに出さない**。
Claude 用の入口は上の「Nimbus デバッグ」が引き受けた（T-249）ので、
標準側を並べて出す理由はもう無い。

**消したのではなく隠しただけ。** F5・ブレークポイント・デバッグコンソール・⇧⌘D は
今までどおり動き、デバッグ中はサイドバーも開く。アイコンが出なくなるだけで、
戻すときは除外の集合から外せばよい。

登録ごと消さないのは、ビューの登録先が無くなると `openPaneComposite` まで巻き添えになるため。
画面を見ただけでは「隠した」と「壊した」の区別がつかないので、GUI ケース 39 は
**アイコンが無いこと**と**⇧⌘D で開けること**の両方を見る。

## 設計

- 置き場所は `extensions/nimbus/package.json` の `contributes.viewsContainers` と `contributes.views` だけで決まる。
  **プロバイダの登録（`extension.ts`）は変えていない** — ビュー ID は同じままなので、置き場所を動かしても実装は無関係
- 開くコマンドは `nimbus.showSkills` / `showClaudeMd` / `showSettings` / `showHelp` / `showDiagnostics`

### 実測でわかったこと

- **webview のビューは `visibility: hidden` にすると `<viewId>.focus` でも出てこない。** ツリービューは出る。
  そのため「ゆあに聞く」（webview）だけは `collapsed`（畳んだ状態）で置いている
- **アクティビティバーに Nimbus のコンテナが 2 つ並ぶと、`/NIMBUS/i` での判定が壊れる。**
  「NIMBUS 設定」にも当たるため、GUI テストのヘルパーが「常用のほうが開いている」と誤認する。
  サイドバー全体の文字列ではなく**見出しだけ**（`.part.sidebar .title-label`）を名前で突き合わせる
- コマンドの表示名に全角括弧を入れると、コマンドパレットの検索で当たりにくい。
  開くためのコマンド名は括弧なしの短い日本語にしてある

## 受け入れ条件

- [x] サイドバーに出るのは常用の 5 段＋ヘルプだけ（GUI テスト 04）
- [x] 診断系がパネルに並ぶ（GUI テスト 15）
- [x] スキル・CLAUDE.md・設定が「Nimbus 設定」に並び、コマンドからも開ける（GUI テスト 05 / 14 / 31）
- [x] その 3 本が常用サイドバーの段に出てこない（GUI テスト 04）
- [x] 標準のデバッグがアイコンとして出ず、それでも ⇧⌘D で開ける（GUI テスト 39）
- [x] タスク板が専用アイコンで開く（GUI テスト 09）
- [x] レビュー・文脈・ヘルプが常用サイドバーの段に出ず、コマンド／設定側から開ける（GUI テスト 04 / 10 / 11 / 18）
- [x] 板の列が英語で揃っている（単体テスト `tasks.test.ts`）
- [x] ヘルプが畳んだ状態で置かれ、開くとゆあ用の入力欄になる（GUI テスト 11）

## 決めなかったこと・やらないこと

- **ビューを消さない。** 使わない人には見えない方がよいが、必要な人には要る。置き場所を変えるだけにする
- **拡張の分割はしない。** 同梱拡張が増えるとビルド構成と `packagedDependencies` も分かれる。
  今回の困りごと（見た目が渋滞している）は置き場所で解ける
