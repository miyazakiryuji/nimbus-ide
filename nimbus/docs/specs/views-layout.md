# 画面の置きかた（サイドバー・パネル・コマンド）

## 何を解決するのか

機能が増えるたびにサイドバーへ 1 段足していったら 13 段になり、**どれも見なくなった**。
常に見えているべきものと、必要なときだけ開くもの、原因を追うときだけ見るものを分ける。

## 振る舞い

### サイドバー（アクティビティバーの雲アイコン）— 常用の 5 段

| ビュー | 既定 | なぜ常設か |
| --- | --- | --- |
| コックピット | 開いた状態 | 主戦場。ここで指示を出す |
| タスク | 畳む | 並列で走っているものを俯瞰する |
| 承認待ち | 畳む | **止まっていることに気づけないと困る** |
| レビュー | 畳む | 出てきた変更を見る |
| 文脈 | 畳む | 何が渡っているかは常に確認できるべき |
| ヘルプ（ゆあ） | 畳む | 迷ったときの入口。下端に置く |

### 下部パネル「Nimbus 診断」— 原因を追うとき

セッションの中身 / 時系列（デバッグ）/ 使用量 / MCP サーバー。
コマンド **「Nimbus: 診断パネルを開く」** で開く。

### コマンドから開く — たまにしか使わないもの

既定では出さない（`visibility: hidden`）。コマンドパレットから開くと現れ、以後は残る。

- 「Nimbus: スキル一覧を開く」
- 「Nimbus: CLAUDE.md を開く」
- 「Nimbus: 設定ビューを開く」

## 設計

- 置き場所は `extensions/nimbus/package.json` の `contributes.viewsContainers` と `contributes.views` だけで決まる。
  **プロバイダの登録（`extension.ts`）は変えていない** — ビュー ID は同じままなので、置き場所を動かしても実装は無関係
- 開くコマンドは `nimbus.showSkills` / `showClaudeMd` / `showSettings` / `showHelp` / `showDiagnostics`

### 実測でわかったこと

- **webview のビューは `visibility: hidden` にすると `<viewId>.focus` でも出てこない。** ツリービューは出る。
  そのためヘルプ（ゆあ）だけは `collapsed`（畳んだ状態）で置いている
- コマンドの表示名に全角括弧を入れると、コマンドパレットの検索で当たりにくい。
  開くためのコマンド名は括弧なしの短い日本語にしてある

## 受け入れ条件

- [x] サイドバーに出るのは常用の 5 段＋ヘルプだけ（GUI テスト 04）
- [x] 診断系がパネルに並ぶ（GUI テスト 15）
- [x] スキル・CLAUDE.md・設定がコマンドから開ける（GUI テスト 05 / 14 / 31）
- [x] ヘルプが畳んだ状態で置かれ、開くとゆあ用の入力欄になる（GUI テスト 11）

## 決めなかったこと・やらないこと

- **ビューを消さない。** 使わない人には見えない方がよいが、必要な人には要る。置き場所を変えるだけにする
- **拡張の分割はしない。** 同梱拡張が増えるとビルド構成と `packagedDependencies` も分かれる。
  今回の困りごと（見た目が渋滞している）は置き場所で解ける
