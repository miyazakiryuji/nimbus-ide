# 見積もりと、頼みかたの型

## 何を解決するのか

**見積もり**（T-187）— 「何ファイル・何分・何トークンくらいか」を着手前に知りたい。

**比較と相違**（T-188 / T-189）— 複数の方針を比べたい、意見が食い違った。
どちらも**中身を持っているのは会話のほう**なので、Claude に書かせるのが早い。
問題は「どう頼むか」で、頼み方を間違えると比べる前に直し始める。

## 振る舞い

### 見積もり（T-187）

コマンド **「Nimbus: これまでの実績から見積もる」**（`nimbus.estimate`）。

> 直近 3 ターンの中央値: 2 ファイル · 45 秒 · 12k トークン

- **未来は予測しない。** 予測のふりをすると、外れたときに信用を失う。
  このセッションで**実際に起きたこと**しか言わない
- **平均ではなく中央値。** 1 回の長いターンに引きずられない
- **直近 5 ターンだけ**を見る（古い傾向を引きずらない）
- 標本が無いときは「まだ標本がありません」と言う（`0 ファイル` とは言わない）

### 選択肢の比較表（T-188）

コマンド **「Nimbus: 実装方針を比べてもらう」**（`nimbus.compareOptions`）。

型に **「まだ変更はしないでください。選ぶのは私です」** を必ず入れる。
入れないと、比べる前に 1 案目を実装し始める。

### 意見の相違（T-189）

コマンド **「Nimbus: 意見の相違を残す」**（`nimbus.recordDisagreement`）。
自分の考えと Claude の提案を入れると、次を書かせる:

1. 食い違いの核心
2. それぞれが正しくなる条件
3. 後から検証するなら、何を見れば決着がつくか

**「どちらが正しいかを決めつけないでください」を型に入れる。**
決着を急がせると、後から検証できない形で終わる。

## 設計

- `extensions/nimbus/src/core/estimate.ts` — 標本の収集と中央値。VS Code 非依存
- `extensions/nimbus/src/core/dialogue.ts` — 頼みかたの型。VS Code 非依存
- `extensions/nimbus/src/extension.ts` — コマンド

見積もりの標本は T-024（指示ごとの修正）と `turn-result` を突き合わせて作る。
同じ材料から別の出口を作っているだけなので、拾い直していない。

## 決めなかったこと・やらないこと

- **セッションをまたいだ見積もりはしない。** 過去の記録（T-034）から作れなくはないが、
  プロジェクトも指示の粒度も違うものを混ぜると、中央値の意味が薄れる
- **比較表と相違の記録を Nimbus 側でファイルに残さない。** 残すなら ADR（T-060）の仕事
- **見積もりを着手前に自動で出さない。** 毎回出ると読まれなくなる。聞かれたときだけ出す
