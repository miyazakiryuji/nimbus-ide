# 提出前の確認（iOS）

権限の差分とプライバシーまわりを、出す前に見る（T-196 / T-197 / T-201）。

## 何を解決するのか

権限とプライバシーは、**足したことに気づかないまま出すと審査で落ちる**うえ、落ちたときの
手戻りが大きい。差分の中でも特に目立たせる価値がある。

## 振る舞い

コマンド「提出前の確認（iOS / 権限・プライバシー）」（`nimbus.openMobileChecks`）。

- `ios/Runner/Info.plist` を探し、**HEAD の版と比べる**
- 権限（`NS…UsageDescription`）の変化を出す
  - **増えた** — 説明文つきで。説明文が無ければその旨
  - **説明文が空になった** — キーだけ残ると審査で弾かれる。見落としやすいのでここも拾う
  - 消えた
- 機械で確かめられること
  - 権限の説明文がすべて書かれているか
  - `PrivacyInfo.xcprivacy` があるか
  - 版（`pubspec.yaml` の `version:`）が直近のタグから上がっているか
- **「審査に通る」とは書かない。** ファイルから分かることだけを並べ、その旨も明記する

## 設計

- `extensions/nimbus/src/core/mobileChecks.ts` — 解析と判定（VS Code 非依存）
- `extensions/nimbus/src/mobileChecks.ts` — ファイル探索・git・コマンド

XML パーサは持ち込まない（`NS…UsageDescription` の組だけが要るため）。

## 受け入れ条件

- [x] `Info.plist` から権限の説明文を取り出す
- [x] 増えた・消えた・説明文が空になった、を区別する
- [x] 空の説明文があれば提出前チェックで落とす
- [x] プライバシーマニフェストの有無を見る
- [x] 前回の版が分かるときだけ、上がっているかを見る
- [x] 「審査に通る」と断言しない
- [ ] 画面確認（実際の Flutter プロジェクトで開く・未実施）

## 決めなかったこと・やらないこと

- **Android のマニフェスト対応** — 同じ形で足せるが、まず iOS の審査で落ちる側から
- **審査結果の予測** — Apple / Google が決めること。断言すると嘘になる
