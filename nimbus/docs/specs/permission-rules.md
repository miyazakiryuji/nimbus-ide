# 承認ルールの編集

「確認せずに許可する」ルールを、画面から見返して減らす（`tasks.md` T-028）。

## 何を解決するのか

T-038 で「今後この種類は常に許可」を設定に残せるようにした。**残せるようになると、
次に要るのは溜まったものを見返して減らす手段**になる。許可は増える一方だと危ない。

`settings.json` を直接開けば編集はできる。それでも画面を用意するのは、
**書式だけ見せても許可の範囲が伝わらない**ため。`Read` と `Read(*.md)` の違いは
書式からは読み取れるが、「何が素通りするようになるか」は考えないと分からない。

## 振る舞い

`Nimbus: 確認せずに許可するルールを編集する`。

一覧の各行に、**そのルールが何を許すのか**を日本語で添える。

| ルール | 添える説明 |
| --- | --- |
| `Read` | Read を、内容にかかわらず確認せず許可 |
| `Write(*.md)` | 拡張子が .md のファイルへの Write を確認せず許可 |
| `Bash(npm test)` | Bash のうち「npm test」で始まるものを確認せず許可 |

- 行を選ぶと**確認のうえ**消す（「以後この種類は毎回確認します」と伝える）
- 「ルールを足す」で追加。書式を検査し、**範囲が広い／重複している／効果が無い**ことを
  伝えたうえで、足すかどうかは人が決める
- **より広いルールに飲み込まれている行**には「より広い `Read` に含まれています」と出す。
  消したつもりの範囲が消えていない状態を可視化する
- 「読めないもの・重なっているものを片付ける」でまとめて整理できる

**ルールを足すときは必ず「取り返しがつかない操作は毎回確認します」と伝える。**
これを言わないと「ルールを入れれば全部素通りになる」と誤解される。

## 設計

- `extensions/nimbus/src/core/permissionRules.ts` — 言い換えと包含関係の判定（VS Code 非依存・単体テスト 10 件）
- `extensions/nimbus/src/permissionRules.ts` — 一覧・追加・削除の画面

包含関係は**同じ種類どうしでしか判定しない**。`*.md` と `*.ts` に包含関係は無いし、
拡張子とコマンド前方一致は比べられない。コマンドは語の切れ目で見る
（`Bash(git)` は `Bash(git status)` を含むが、`Bash(github)` は含まない）。

## 受け入れ条件

- [x] ルールが何を許すのかを日本語で言う
- [x] 読めないルールを無効として出す（黙って捨てない）
- [x] 広いルールが狭いルールを飲み込んでいることを示す
- [x] 拡張子どうし・ツール違いには包含関係を認めない
- [x] 追加時に 範囲の広さ／重複／効果が無いこと を伝える（止めはしない）
- [x] 「取り返しがつかない操作は毎回確認」を必ず伝える
- [x] 消すときは確認する
- [x] 画面確認 — GUI ケース `21-permission-rules.mjs`（実際の設定で、一覧の言い換えと包含の指摘まで見る）

## 決めなかったこと・やらないこと

- **Claude Code の `settings.json`（`allow` / `deny` / `ask`）を編集する** —
  Nimbus は `settingSources: []` を明示して利用者の `~/.claude` 設定を読み込まない
  （何が文脈に入るかを Nimbus 側で説明できる状態に保つため）。**読み込んでいないものを
  編集しても効かない**ので、ここで扱うのは Nimbus 自身のルールだけにした
- **拒否（deny）側のルール** — 読み取りの禁止は `nimbus.safety.protectedPaths` が持っており、
  その画面編集は T-155 で入っている。二重に入口を作らない
- **ルールの自動整理** — 「片付ける」は人が押したときだけ動く。許可の範囲が黙って
  変わるのは、この設定でいちばんやってはいけないこと
