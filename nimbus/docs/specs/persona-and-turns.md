# 話しかた・状態の色・書く番

## 何を解決するのか

どれも「**エージェントとの距離感**」を決めるもの。

**話しかた**（T-063）— 前置きが長い／説明が足りないは好みの問題で、
既定を押しつけるより選べたほうがいい。

**状態の色**（T-064）— いま動いているのか、止まって待っているのかが、
視界の端で分かるようにする。

**書く番**（T-190 / T-191）— どちらが書くかが曖昧なまま進むと、
直してほしくないところまで直される。

## 振る舞い

### 話しかた（T-063）

コマンド **「Nimbus: 話しかたを選ぶ」**（`nimbus.persona`）。出荷時に 4 つ:

| 名前 | 中身 |
| --- | --- |
| そのまま | **既定。何も足さない** |
| 簡潔 | 前置き・相づち・要約の繰り返しをしない |
| ていねいに説明 | 判断の理由を 1 行ずつ添える（教材向け） |
| ゆあ | 後輩プログラマの口調（ヘルプと同じ） |

- **既定は「そのまま」。** 口調を勝手に変えられるのは好みが分かれる
- **「ゆあ」でも技術的な正確さは崩させない。** 口調の指示に
  「分からないことを分かったふりで埋めないでください」を必ず入れる
- 適用は `systemPrompt` の `append`（preset を置き換えない）。次のセッションから効く

### 状態の色（T-064）

ステータスバーの背景色が状態で変わる。

| 状態 | 色 |
| --- | --- |
| 承認待ち | 警告の背景 |
| エラー | エラーの背景 |
| 作業中 | **変えない** |
| 待機中 | 変えない |

- **新しい配色は足さない**（IntelliJ 由来機能と同じ方針）。
  VS Code の既存トークンを使うので Nimbus Dark / Light のどちらでも馴染む
- **止まっている状態だけを目立たせる。** 動いているのは異常ではないので、
  そこで色を変えると「常に光っている」状態になり、警告として機能しなくなる
- tooltip に状態の日本語（待機中 / 作業中 / 承認待ち / エラー）を出す

### 書く番（T-190 / T-191）

コマンド **「Nimbus: どちらが書くかを切り替える」**（`nimbus.turnMode`）。

- **エージェントが書く** — いつもどおり
- **私が書く（見ているだけ）** — ファイルを変更しない。**聞かれるまで提案もしない**
- **肩越し** — ふだんは黙っている。**明らかに壊れるときだけ**短く指摘する。
  **好みの問題（命名・書き方の流儀）では口を出させない**

いまのセッションへ即座に伝える（次のセッションを待たない）。

## 設計

- `extensions/nimbus/src/core/persona.ts` — ペルソナ表・色の対応・モードの指示文。VS Code 非依存
- `extensions/nimbus/src/extension.ts` — コマンド・ステータスバーの色・`systemPrompt` への追加

ピン留め（T-152）と話しかた（T-063）はどちらも `systemPrompt` の `append` に載るので、
1 か所でまとめて組み立てている。

## 受け入れ条件

- [x] 既定は「そのまま」で、何も足さない（単体テスト）
- [x] 「ゆあ」でも技術的な正確さを崩させない（単体テスト）
- [x] 止まっている状態だけ色を変える（単体テスト）
- [x] 私が書く番では提案もさせない（単体テスト）
- [x] 肩越しでは好みの問題に口を出させない（単体テスト）
- [ ] 画面確認: 承認待ちでステータスバーの色が変わる
- [ ] 画面確認: 話しかたを変えると応答の調子が変わる

## 決めなかったこと・やらないこと

- **ペルソナを利用者が定義できるようにはしていない。** 4 つで足りるかを見てから。
  自由に書けるようにすると、正確さを崩す指示も書けてしまう
- **エディタの配色は変えない**（T-064 の「思考中は青」）。
  作業中の画面の色が変わると、コードが読みにくくなる。ステータスバーに留める
- **書く番をファイルの編集で自動判定しない。** 明示的に切り替える。
  自動だと「いま自分の番だと思っていた」がいちばん困る
