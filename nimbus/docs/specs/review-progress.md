# レビューの進み

大きな変更を分けて見るときに、どこまで見たかを覚えておく（T-160）。

## 何を解決するのか

大きな変更は 1 回では見られない。中断して戻ってきたとき、**どこまで見たかを覚えているのは
人間の仕事ではない**。

## 振る舞い

コマンド「レビューの進みを見る」（`nimbus.openReviewProgress`）。

- 対象は `git diff HEAD` に出るファイル
- 一覧から選ぶと「見た」印が付く／外れる。印を付けたらそのファイルを開く（見ながら進められる）
- 「進みを見る」で Markdown の一覧（✅ 見た／⬜️ まだ／🔄 見たあとに変わった）
- **「見た」はそのときの差分に対して付く。** あとから変わったら、見ていないのと同じに戻す
  （ここを外すと嘘の進捗になる）
- 指紋の元は**そのファイルの差分**。別の場所が変わっただけで「見直し」にしない
- 差分から消えたファイルの印は捨てる（溜め続けない）
- 印はワークスペースに持つので、閉じて開き直しても続きから見られる

## 設計

- `extensions/nimbus/src/core/reviewProgress.ts` — 印の管理と判定（VS Code 非依存）
- `extensions/nimbus/src/reviewProgress.ts` — git・QuickPick・保存

ハッシュは持ち込まない。長さと粗い和で足りる（衝突しても実害は「もう一度見る」だけ）。

## 受け入れ条件

- [x] 印を付ける／外せる
- [x] 見たあとに変わったら、見ていない扱いに戻る
- [x] 同じファイルに 2 度印を付けても 1 つ
- [x] 差分から消えたファイルの印を捨てる
- [x] 進みと、見直しが要るものを数える
- [ ] 画面確認（実際の差分で試す・未実施）

単体テスト: `extensions/nimbus/src/test/reviewProgress.test.ts`（8 件）

## 決めなかったこと・やらないこと

- **行単位の進み** — ファイル単位で足りる。細かくすると管理そのものが仕事になる
- **他の人と共有すること** — レビューは人ごと。共有すると「誰かが見た」で流れる
