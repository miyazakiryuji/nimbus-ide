# ビルドのようす

ビルド時間と成果物の大きさを、前回と比べる（T-217 / T-129）。

## 何を解決するのか

どちらも**少しずつ悪くなる**ので、その日その日では気づけない。前回と比べて初めて分かる。

## 振る舞い

コマンド「ビルドを計って前回と比べる」（`nimbus.measureBuild`）。

- 実行するコマンドは設定 `nimbus.build.command`（例: `flutter build apk` / `npm run build`）。
  プロジェクトごとに違うので、決め打ちにしない
- 成果物の大きさは設定 `nimbus.build.artifact`（プロジェクト相対）。空なら時間だけ
- **落ちたビルドは記録しない。** 失敗した時間を混ぜると次の比較が狂う
- 比べるのは**平均ではなく直近**。平均を取ると悪化が薄まって見えなくなる
- 判定

  | 変化 | 出しかた |
  | --- | --- |
  | 25% 以上遅い / 1MB 以上大きい | 少し悪くなっています（1 回なら誤差） |
  | 50% 以上遅い / 5MB 以上大きい | はっきり悪くなっています（直前の変更を見る） |
  | それ以下 | 目立った悪化はありません |

- 速くなったときも、そう書く
- 記録はワークスペースに 50 件まで（古いものから落とす）

## 設計

- `extensions/nimbus/src/core/buildMetrics.ts` — 比較と Markdown 化（VS Code 非依存）
- `extensions/nimbus/src/buildMetrics.ts` — 実行・計測・記録

## 受け入れ条件

- [x] 最初の記録では比べず、その旨を書く
- [x] 直近と比べる（平均にしない）
- [x] 25% / 50% と 1MB / 5MB で段階を分ける
- [x] 少しの揺れでは騒がない
- [x] 落ちたビルドを記録しない
- [x] 記録を新しい順に決めた数だけ残す
- [ ] 画面確認（実際にビルドして比べる・未実施）

単体テスト: `extensions/nimbus/src/test/buildMetrics.test.ts`（8 件）

## 決めなかったこと・やらないこと

- **自動で毎回計ること** — ビルドは重い。計るのは人が決めたときだけ
- **原因の特定** — 何が重くなったかはビルドツールの領分。ここは「悪くなった」を知らせる場所
