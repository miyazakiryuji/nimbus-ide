# プロジェクト固有の書き方（T-103）

「既存のコードに合わせて」と言っても、**何に合わせるのかを知らなければ守れない。**
インデント・引用符・セミコロン・ファイル名の付け方・テストの置き場所は、
既存のファイルを数えれば分かる。**分かるものは推測させない。**

## 振る舞い

コマンド **「このリポジトリの書き方を数える」**（`nimbus.projectConventions`）:

```
40 ファイルから数えた、このリポジトリの書き方:
- インデント: tab
- 引用符: 'シングル'
- 行末のセミコロン: つける
- ファイル名: camelCase
- テストの置き場所: `test/` の下にまとめる
```

- **「セッションに渡す」** — 「推測ではなく既存のファイルを数えた結果です」と添えて送る
- **「コピーする」** — CLAUDE.md に貼るのは利用者の判断。Nimbus からは書き換えない

## 実装

- `extensions/nimbus/src/core/conventions.ts` — 数え方と文面（純関数）
- `extensions/nimbus/src/conventions.ts` — ファイル集め（`findFiles`）
- テスト: `extensions/nimbus/src/test/conventions.test.ts`

## 決めたこと

**はっきり多いものだけを「流儀」と呼ぶ（6 割以上）。** 半々のものに従わせても、
迷わせるだけで精度は上がらない。**分からなかった項目は書かない。**

**見るのは 40 ファイルまで。** それ以上見ても結論は変わらない。
1 ファイル 200KB を超えるものは飛ばす（生成物で時間を使わない）。

**インデントは、空白なら「いちばん浅いもの」を採る。** 入れ子があるので 2 と 4 が混ざる。

**CLAUDE.md は書き換えない。** 何をルールとして残すかは人の判断。コピーまでを提供する。

**推測はしない。** 「レイヤ構成」「状態管理の流儀」のような、コードを読んで解釈しないと
分からないものは対象にしない。数えられるものだけを数える。

## 確認すること

- [ ] コマンドで、インデント・引用符・セミコロン・ファイル名が出る
- [ ] 書き方が混在しているリポジトリでは、その項目が出ない
- [ ] ソースが無いフォルダでは「見つかりませんでした」と出る
- [ ] 「セッションに渡す」でコックピットに送られる
- [ ] 「コピーする」でクリップボードに入る（CLAUDE.md は書き換わらない）

## 残っていること

- レイヤ構成・状態管理の流儀は数えていない（解釈が要るため。読ませる方が正確）
- 言語ごとの違いを分けていない（TypeScript と Dart が混ざると多数決になる）
- [signature-attachment](signature-attachment.md) のように**毎回自動で添える**形にはしていない
  （毎ターン同じ内容を送ることになるため。CLAUDE.md に置く方が安い）
