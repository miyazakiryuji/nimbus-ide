# チェックポイントの巻き戻しと MCP サーバーの管理

## 何を解決するのか

**巻き戻し**（T-025）— CLI では Esc 2 回で 1 つ前へ戻る。押すまでどこへ戻るか分からず、
戻しすぎても気づけない。「どこまで戻すか」を**選んでから**戻せるようにする。

**MCP**（T-029 / T-042）— MCP は繋がらないときに何も分からないのが一番つらい。
今の `contextView` は名前と status を並べるだけで、そこから手が打てない。
状態・出どころ・エラー・提供ツールを 1 か所に出し、繋ぎ直しをその場でできるようにする。

## 調べたこと — SDK の `Query` に必要なものが揃っている

| API | 使い道 |
| --- | --- |
| `rewindFiles(userMessageId, { dryRun })` | 巻き戻し。`dryRun` で変更されるファイル数と +/- 行数を**先に**取れる |
| `mcpServerStatus()` | サーバーの状態・スコープ・エラー・**提供ツール一覧**（名前・説明・annotations） |
| `reconnectMcpServer(name)` | 繋ぎ直し。セッションを作り直さずに済む |
| `toggleMcpServer(name, enabled)` | 有効・無効の切り替え |
| `setMcpServers(servers)` | 構成の差し替え（追加・削除はこれで行う） |

巻き戻し先に渡す `userMessageId` は **SDK が付けたメッセージ UUID**で、ストリーム上の
`user` メッセージにしか現れない。`normalize.ts` はこれまで `user` メッセージを
（ツール結果以外）捨てていたので、`checkpoint` イベントとして拾うところから作った。

## 振る舞い

### チェックポイント（T-025）

- 巻き戻し候補は**利用者の発言 1 つにつき 1 つ**。合成メッセージ（`isSynthetic`）は候補にしない
- 一覧は**新しい順**（戻したいのはたいてい直近）。番号は古い順に 1, 2, 3… と振る
  ——「3 つ前に戻す」と言えるようにするため
- 長い指示は 60 文字で畳む
- **戻す前に `dryRun` で結果を見せる。** 「2 ファイル · +10 / -4」のように出してから確認を取る
- **「ファイルの変更はありません（会話だけが戻ります）」もはっきり言う。**
  戻したつもりで戻っていないのが一番困る
- 戻せないときは理由（`error`）をそのまま出す。黙って成功にしない

### MCP サーバー（T-029 / T-042）

- 一覧は**困っているものが上**。接続失敗 → 認証が必要 → 接続中 → 接続済み → 無効、同順なら名前順
- 状態は利用者の言葉にする（`needs-auth` ではなく「認証が必要」）
- 行を展開すると サーバー情報 / エラー / **提供ツール一覧**（名前・説明・性質）
- ツールの性質は annotations から「破壊的」「読み取り専用」を出す。
  **破壊的なツールが混ざっていることは、使う前に見えているべき**
- 繋ぎ直しは、**押して意味のある状態のときだけ**出す（接続失敗 / 認証が必要 / 接続済み）。
  押しても何も起きないボタンは、壊れているのと同じ

## 設計

- `extensions/nimbus/src/core/checkpoints.ts` — 候補の組み立てと結果の言語化。VS Code 非依存
- `extensions/nimbus/src/core/mcp.ts` — 並び順・状態の言葉・操作可否。VS Code 非依存
- `extensions/nimbus/src/mcpView.ts` — MCP のツリー表示
- `extensions/nimbus/src/session/normalize.ts` — `user` メッセージから `checkpoint` を拾う
- `extensions/nimbus/src/session/SessionManager.ts` — `rewind()` / `mcpServers()` /
  `reconnectMcpServer()` / `toggleMcpServer()` / `setMcpServers()`

## 決めなかったこと・やらないこと

- **MCP ツールの「エージェント抜きの単体実行」（T-042 の後半）は入れていない。**
  SDK の `Query` にツールを直接呼ぶ API が無く、`@modelcontextprotocol/sdk` で
  別途サーバーへ繋ぎ直す実装になる（接続設定の二重管理になる）。
  T-042 は一覧・スキーマ表示までを済ませ、単体実行は残タスクとして分けた
- **ツールの入力スキーマ（JSON Schema）は出していない。** `mcpServerStatus()` が返すのは
  名前・説明・annotations までで、スキーマは含まれない
- **巻き戻しは「戻す」だけ。** やり直し（redo）は SDK に無い。
  戻す前に確認を必ず挟むのはそのため
