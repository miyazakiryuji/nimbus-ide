# 使用量（枠・文脈・費用）

## 何を解決するのか

エージェントは「あとどれだけ使えるか」を教えてくれない。5 時間の枠を使い切って止まる、
週の枠が尽きて週末が潰れる、気づいたら費用が膨らんでいる — どれも**走らせている最中に
見えていれば避けられた**。数字を並べるのではなく、枠に対する割合とリセットまでの時間で見せる。

対応する tasks.md の項目: T-017（使用量を常時表示）/ T-020（トークン消費のリアルタイムバー）/
T-037（コスト・使用量ダッシュボード）/ T-059（コスト上限アラート）。

## 調べたこと — 枠の残量は SDK から取れる

T-017 に「SDK / CLI から枠の残量が取れるか要調査（取れなければ自前で積算する）」とあった件。
**取れる。自前の積算は要らない。** SDK 0.3.226 の `Query` に次の 2 つがある。

| API | 返るもの |
| --- | --- |
| `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET()` | セッションの累積費用・モデル別内訳・変更行数と、claude.ai プランの枠（5 時間 / 週 / 週 Opus / 週 Sonnet / アプリ経由の週）の消費率とリセット時刻 |
| `getContextUsage()` | いまの文脈の内訳（カテゴリ別トークン数）・合計・上限・割合 |

- 前者は**名前のとおり実験的**で、SDK 側が「変更・削除がありうる。まだ頼るな」と明記している。
  そのため呼び出しは `SessionManager` の 1 メソッドに閉じ込め、**失敗しても `undefined` を返すだけ**にした。
  使用量が取れないことを、セッションが動かない理由にしない
- API キー利用・Bedrock・Vertex では枠の概念が無く `rate_limits` は `null`。
  この場合は「枠の制限は適用されません」と出す（黙って空欄にしない）

## 振る舞い

### 使用量ビュー（T-017 / T-037）

サイドバー Nimbus の **「使用量」**（既定は折りたたみ）。見出しの 🔄 で取り直せる
（コマンド **「Nimbus: 使用量を取得し直す」** = `nimbus.refreshUsage`）。
セッションのターンが終わるたびに自動で取り直す。

出るもの（上から）:

1. **文脈** — `███░░░░░░░ 文脈  50.0k / 200.0k · 25%`
2. **文脈の内訳** — カテゴリ別トークン数を多い順に。何が食っているかが分かると削る先が決まる
3. **このセッションの費用** — 累積 USD（tooltip に API 時間と経過時間）
4. **枠のゲージ** — 5 時間 / 週（対話）/ 週（アプリ経由）/ 週（Opus）/ 週（Sonnet）
5. **モデル別** — モデルごとの費用・入出力・キャッシュ読み書き
6. **変更行数** — `+120 / -33`
7. **取得時刻**

**週の枠は 1 本にまとめない**（T-037）。対話で使った分とアプリ経由（ヘッドレス）で使った分は
別の枠から引かれるので、合算すると「まだ余裕がある」と誤読する。
ラベルの対応は SDK のフィールド名から取っている（`seven_day_oauth_apps` = アプリ経由）。

### ステータスバーの常時表示（T-020）

`$(cloud) Nimbus · ███░░ 25% · $0.1234`

- 文脈の消費率を 5 文字のバーで常に出す。ターンが終わるたびに更新する
- 割合が取れないときは**バーごと出さない**（`0%` と出すと「まだ空」と誤解する）
- 承認待ちがあるときは、そちらを左に置いて最優先で見せる（既存の振る舞い）

### コスト上限アラート（T-059）

- 設定 `nimbus.usage.costLimitUsd`（既定 `0` = 上限なし）
- `nimbus.usage.warnAtPercent`（既定 `80`）に達したら 1 度だけ警告
- 上限を超えたら警告に **「すべて停止」** ボタンを添える（押すと `nimbus.stopAll`）
- **段階ごとに一度だけ出す。** 毎ターン出すと読み飛ばされ、警告として機能しなくなる
- **自動では止めない。** 止めるかどうかは利用者が決める（作業の途中で勝手に切られるほうが困る）

## 設計

- `extensions/nimbus/src/core/usage.ts` — 整形と判定だけ。SDK にも VS Code にも依存しない
  （SDK の型は構造互換のローカル型で受ける。実験的 API の型変更を単体テストに波及させないため）
- `extensions/nimbus/src/usageView.ts` — ツリー表示。ゲージは文字（`█░`）で描く。
  Webview を足すほどの情報量ではないうえ、ツリーなら折りたたんで置いておける
- `extensions/nimbus/src/session/SessionManager.ts` — `getUsage()` / `getContextUsage()`。
  実験的 API との接触点はこの 2 メソッドだけ
- `extensions/nimbus/src/extension.ts` — ターン終了での取り直し・ステータスバー・コスト警告

コアには触っていない。

## 決めなかったこと・やらないこと

- **自前でのトークン積算はしない。** SDK から取れると分かったため。取れなくなったら、
  `turn-result` の `usage` を積む経路に切り替える（イベント側には既に情報がある）
- **上限を超えても自動停止はしない**（T-059）。作業の途中で勝手に切られるほうが困る。
  止めるボタンをその場に置くところまでにする
- **費用の履歴グラフは作らない。** セッションをまたいだ集計は永続化層（T-034）が要る。
  そこができてから考える
- 実験的 API の名前が変わったら、`SessionManager.getUsage()` の 1 行を直せば済む形にしてある
