# 型の変更が壊す場所を洗い出す（T-123）

バックエンドの型が変わったとき、フロント側のどこが壊れるかは**型エラーが出るまで分からない**。
別のパッケージ・別のリポジトリなら、実行するまで分からないこともある。

変わった型の名前さえ分かれば、**参照検索で触っている場所は機械的に出せる**。

## 振る舞い

コマンド **「型の変更が壊す場所を洗い出す」**（`nimbus.trackSchemaImpact`）:

1. `git diff HEAD` から、変わった**型**（`interface` / `type` / `enum` / `class`）の名前を拾う
2. 名前ごとに定義を探し、そこから**参照検索**をかける（定義元のファイルは除く）
3. 影響の大きい順に一覧を出す

```
変わった型 2 件を、7 ファイルが参照しています
  User: 6 ファイル
  Role: 1 ファイル
```

**「確かめさせる」**で、型ごとのファイル一覧を添えてコックピットへ送る。

## 実装

- `extensions/nimbus/src/core/schemaImpact.ts` — 差分の読み取りと文面（純関数）
- `extensions/nimbus/src/schemaImpact.ts` — 参照検索（`vscode.executeReferenceProvider`）
- テスト: `extensions/nimbus/src/test/schemaImpact.test.ts`

## 決めたこと

**型だけを拾う。** 関数や定数まで拾うと、ふつうの変更のたびに全部が並んで読まれなくなる。
API の名前変更は [api-docs](api-docs.md)（T-209）が別に見ている。

**「直して」ではなく「壊れていないかを確かめて」。** 参照しているだけで影響が無い場所の方が多い。
**「問題なし」と報告させる**ところまでを頼む。

**影響の大きい順。** 触っているファイルが多い型から見る。参照が 0 の型は出さない。

**1 型あたり 12 ファイルまで。** 超えたら「…他 N ファイル」。全部並べても読めない。

## 確認すること

- [ ] `export interface` を変えて実行すると、参照しているファイルが出る
- [ ] `export function` を変えただけでは出ない（型だけを見る）
- [ ] 定義元のファイルは一覧に含まれない
- [ ] 参照が無い型は一覧に出ない
- [ ] 「確かめさせる」でコックピットに型ごとの一覧が送られる

## 残っていること

- 言語サーバーが答えられる範囲だけ（別リポジトリのフロントエンドは追えない）
- **どう壊れるか**（プロパティが増えたのか、消えたのか）は見ていない。名前の一致まで
