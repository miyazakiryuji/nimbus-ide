# 並列タスク（worktree × カンバン）

タスク＝ worktree ＝セッションを 1:1:1 で対応させ、同じリポジトリで複数の Claude を
同時に走らせる（旧 F-5 / フォーク F4）。Nimbus の主戦場。

## 何を解決するのか

同じ作業ディレクトリで 2 つのエージェントを走らせると、互いの編集を踏む。かといって
手で `git worktree` を切って回すのは面倒で、切りっぱなしのディレクトリが溜まる。
**切るところから片付けるところまでを製品側が持つ。**

## 振る舞い

### 板（カンバン）

| 列 | 意味 |
| --- | --- |
| 待機中 | 未開始、または同時実行上限の空き待ち |
| 実行中 | セッションが走っている |
| 承認待ち | このタスクのセッションが判断を待っている |
| レビュー待ち | ターンが終わり、人間の番 |
| 完了 | worktree を破棄済み |

- **状態は人間が動かすものではなく、実際に起きていることを映す。**
  セッションの状態と「承認待ちの有無」から導出する
- 実行枠を占有するのは「実行中」と「承認待ち」。この 2 つで同時実行上限を数える
- 再起動後、「実行中」「承認待ち」だったタスクは**レビュー待ちへ倒す**。プロセスが死んだ時点で
  セッションも消えているので、実行中に見せると「動いていないのに待ち続ける」ことになる
  - **倒しただけでは、起動直後の突き合わせで押し戻される**（T-375・2026-09-02 に直した）。
    `restoreState()` は状態しか変えず `updatedAt` を触らないので、ディスクに残った
    `running` と同時刻になり、`mergeTasks()` の「同時刻ならディスク側」に負けていた。
    **部品はどちらも正しく、起動の順番で合成したときだけ壊れる**類の穴
  - かといって無条件に `updatedAt` を進めてはいけない。Memento には**他の窓のタスクも
    入っている**ので、生きた窓が本当に走らせているものまで倒してしまう。
    `ownerWindowId` は起動ごとに変わる UUID なので鍵にならない
  - 決めごと: **セッション台帳で持ち主の生死を見てから倒す**（`reconcileAfterRestart()`）。
    持ち主が生きているものは触らず、突き合わせでディスク側（`running`）に戻してもらう。
    呼ぶ順番は「台帳を読む → `reconcileAfterRestart()` → 最初の `syncWithStore()`」
  - 守り: `taskRestart.test.ts`（**起動の順番を組み立てて**確かめる 3 本）

### worktree

- 実体は**利用者のリポジトリの外**（既定で `~/.nimbus/worktrees/<repo>/<slug>`）。
  リポジトリの隣に見慣れないディレクトリを生やさない
- ブランチ名はタスク名から作った slug（日本語はそのまま残す）
- 「worktree を開く」で別ウィンドウとして開ける（VS Code のマルチウィンドウに乗る）

### 片付け

完了時は worktree を消すが、**未コミットの成果は先に WIP コミットとしてブランチへ保存してから**
消す。`git worktree remove --force` は未コミットの変更を黙って捨てるため、そのままでは使わない。
ブランチは残るので、あとから通常どおりマージできる。**作業が失われることはない。**

### 同時実行

設定 `nimbus.tasks.maxConcurrent`（既定 2）。上限に達したタスクは待機し、空きが出ると
自動で開始する。自動開始に失敗したタスクは待機中のまま残す（利用者が手で開始できる）。

## 設計

- `extensions/nimbus/src/core/tasks.ts` — 状態機械（VS Code 非依存・純粋関数）
- `extensions/nimbus/src/core/worktree.ts` — worktree の生成と破棄（git 呼び出しは注入可能）
- `extensions/nimbus/src/tasks/TaskService.ts` — 永続化・自動開始・セッションとの結線
- `extensions/nimbus/src/tasks/BoardViewProvider.ts` — 板（Webview）

`simple-git` のような依存は足さず、`execFile('git', …)` で済ませている（同梱物を増やさない）。

## 受け入れ条件

- [x] タスクを作ると worktree とブランチができ、そこで Claude が動く
- [x] 同時実行上限を超えたタスクが待機し、空きが出ると自動で開始する
- [x] 完了時、未コミットの変更が WIP コミットとしてブランチに残る
- [x] 再起動後、実行中・承認待ちだったタスクがレビュー待ちになる
- [x] worktree を別ウィンドウで開ける
- [x] 画面確認（`nimbus/docs/testing/f3-f6.md` §6）— GUI ケース `09-task-board.mjs` / `13-worktree-window.mjs`（タスクが板に出ることは `41-task-registry.mjs`）

## 決めなかったこと・やらないこと

- **worktree をリポジトリ内に置くこと** — 利用者のリポジトリを汚さない方針を優先した
- **タスクの手動での状態変更** — 板は「実際に起きていること」を映す。手で動かせると嘘がつける
- **キューの優先度** — 今は先入れ先出しのみ（`tasks.md` T-233）
