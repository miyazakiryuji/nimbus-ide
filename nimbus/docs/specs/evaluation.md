# スキル・プロンプトの評価（回帰・ブレ幅・モデル比較）

## 何を解決するのか

スキルやプロンプトを直したあと、**前に通っていたケースがまだ通るか**を確かめる手段が無い。
さらに、同じ指示を 2 回投げると違う答えが返るのがふつうなので、
**「1 回試して動いた」は根拠として弱い**。

対応する tasks.md の項目: T-165（自作スキルの回帰テスト）/ T-166（ブレ幅の測定）/
T-167（モデル切り替えの比較）。3 つとも「同じケースを何度か走らせて比べる」ので、
1 つの仕組みにまとめてある。

## 振る舞い

コマンド **「Nimbus: スキル・プロンプトを評価する」**（`nimbus.evaluate`）。

1. ケースを選ぶ（無ければ作る）— 名前・投げる指示・**応答に含まれていてほしい語**
2. 何回まわすかを選ぶ（1 / 3 / 5）
3. 比べるモデルを選ぶ（選ばなければ既定のモデルだけ）
4. **走らせる前に必ず確認**（何回まわすか・費用がかかること）
5. 結果を Markdown で開く

### 判定

- **含まれていてほしい語がすべて揃ったときだけ合格。** 部分点は付けない。
  部分点を付けると「だいたい通った」が積み上がって、回帰に気づけなくなる
- 「入ってはいけない語」も指定できる（例: 勝手に変更していないか）
- 大文字小文字は無視する

### ブレ幅（T-166）

**合格率だけでは足りない。** 毎回通っていても、答えの長さが倍半分に振れているなら
「同じことをしている」とは言えない。長さのばらつき（変動係数）も併せて出す。

- 1 回でも落ちたら「**同じ指示で結果が変わっています**」と言い切る
- 振れが 40% を超えたら、通っていてもそう言う
- 走らせていないときは `0%` ではなく「まだ走らせていません」

### モデル比較（T-167）

- 表にして、**合格率が先、同じなら安い順**に並べる
- 「通ったなかで一番安いのは X」を出す。
  **すべて落ちたら「軽いモデルを勧められる状態ではありません」と言う** —
  安くても落ちるモデルを勧めない

### 走らせかた

- 評価中は **`plan` モード**で走らせる。比べたいのは応答であって、副作用ではない
- 1 回あたり 3 分で打ち切る
- 進捗つき・途中でキャンセルできる

## 設計

- `extensions/nimbus/src/core/evaluation.ts` — 判定と集計。VS Code 非依存
- `extensions/nimbus/src/evaluationRunner.ts` — セッションを起こして結果を集める
- `extensions/nimbus/src/extension.ts` — ケースの保存（`globalState`）と入力

## 受け入れ条件

- [x] 含まれていてほしい語が全部揃ったときだけ合格（単体テスト）
- [x] 入ってはいけない語で落とす（単体テスト）
- [x] 毎回通っていても、長さが大きく振れていれば言う（単体テスト）
- [x] 1 回でも落ちたら「結果が変わっている」と言い切る（単体テスト）
- [x] 走らせていないときに 0% と言わない（単体テスト）
- [x] 空の応答ばかりでも 0 除算しない（単体テスト）
- [x] モデル比較は合格率が先、同じなら安い順（単体テスト）
- [x] 通っていないモデルを「安い」と勧めない（単体テスト）
- [x] 走らせる前に回数と費用を確認する（実装）
- [ ] 画面確認: 3 回まわしてブレ幅が出る（実セッションが要る）

## 決めなかったこと・やらないこと

- **応答の意味を judge しない。** 語の一致だけで判定する。
  LLM に判定させる案もあるが、判定そのものがブレると測定にならない
- **自動では走らせない。** 費用がかかるので、必ず人が始める
- **ケースをリポジトリに置かない。** `globalState` に持つ。
  チームで共有したくなったら T-043 の配布物に乗せる
