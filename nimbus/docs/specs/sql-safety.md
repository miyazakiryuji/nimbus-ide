# SQL を流す前に見る

取り返しがつくかどうかを、流す前に確かめる（T-126 / T-127）。

## 何を解決するのか

エージェントが書いた SQL は、**構文が合っていれば流れてしまう**。`WHERE` を忘れた `UPDATE` は
正しい SQL で、正しく全行を書き換える。

## 振る舞い

コマンド「SQL を流す前に見る」（`nimbus.checkSql`）。

- 選択範囲か、開いている `.sql` の中身を読む。**DB には繋がない**
  （接続情報を持つと、それ自体が事故のもとになる）
- コメントを落として文ごとに割り、読み取り／書き込み／スキーマ変更に分ける
- **取り返しがつかないもの**を名指しする

  | 見るもの | 出しかた |
  | --- | --- |
  | `WHERE` の無い `DELETE` | 「**全行が消えます**」 |
  | `WHERE` の無い `UPDATE` | 「**全行が書き換わります**」 |
  | `DROP` | 「テーブルごと消えます。戻せるのはバックアップからだけ」 |
  | `TRUNCATE` | 「中身が全部消えます。多くの DB でロールバックできません」 |
  | `ALTER TABLE … DROP COLUMN` | 「列ごと消えます」 |

- **「危ない」ではなく「何が起きるか」を書く。** 「危険」より「全行が消えます」のほうが手が止まる
- 取り返しがつかないものがあるときは「**流す前に `SELECT COUNT(*)` で対象を数えてください**」
- 読み取りだけなら「そのまま流して問題ありません」と言い切る
- **速いかどうかは静的に分からない**ので、代わりに `EXPLAIN` / `EXPLAIN ANALYZE` の打ち方を出す

## 決めなかったこと・やらないこと

- **DB への接続** — 接続情報を持つと、それ自体が事故のもと。読むのは文だけ
- **実行計画の取得** — 繋がないと取れない。打ち方を出すところまで
- **方言ごとの完全な解析** — SQL の方言は多い。「これをやると必ず起きる」ものだけを見る
