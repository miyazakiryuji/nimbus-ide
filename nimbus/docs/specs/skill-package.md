# スキルを配れる形にする

自分のスキルを、人が入れられる形に整える（T-070・出す側）。

> 入れる側は [market](market.md)（別セッション実装）。**「共有マーケット」には両方要る**。
> こちらが出すのは **Claude Code のマーケットプレイス形式**で、入れるのは Claude Code 自身
> （`/plugin marketplace add`）。Nimbus 側に読み手を用意しなくても成立する。

## 何を解決するのか

良いスキルを書いても、渡す手段が「このフォルダをコピーして」しかない。
Claude Code にはマーケットプレイスの仕組みがあり、**GitHub のリポジトリをそのまま
配布元にできる** — 足りないのは、その形に整えるところだけ。

## 振る舞い

コマンド「スキルを配れる形にする」（`nimbus.packageSkills`）。

1. 配る名前（リポジトリ名）を決める
2. **何が入って何が入らないかを、作る前に見せる**
3. 場所を選ぶと、そこに作る

出すもの:

```
<選んだ場所>/
  .claude-plugin/marketplace.json   ← 一覧
  README.md                         ← そのまま打てる入れかた
  <スキル名>/skills/<スキル名>/       ← 中身
```

### 配らないもの

- **他人のプラグインから来たスキル** — 手元にあっても、自分の名前で配ってよいものではない。
  入れるのは自分で書いたもの（`プロジェクト` と `ユーザー`）だけ
- **説明の無いスキル** — 一覧に名前だけ並んでも、入れる側は選べない

**入れなかったものは理由つきで出す。** 黙って減らさない。

### 秘密が混ざっていたら

[share-session](share-session.md) の判定（`inspectRedactions`）をそのまま使い回して、
鍵らしき文字列とホームのパスを探す。**見つかっても止めない** — 知らせたうえで、
出すかどうかは人が決める。

> 実測（2026-08-13）: この環境のスキル 13 個（プロジェクト 6・ユーザー 7）で警告ゼロ。
> 検査自体は効いていることを別途確認した（`sk-...` → 1 件、ホームのパス → 1 件）。
> **何も出ない検査は、効いていないのと区別が付かない**ので、そこまで確かめている。

### 公開はしない

**作るのはフォルダまで。** git に入れて push するかどうかは人が決める。
公開は取り消せないので、機械が決めてよいことではない。

## 設計

- `extensions/nimbus/src/core/skillPackage.ts` — 何を入れるかの判断と整形（VS Code 非依存）
- `extensions/nimbus/src/skillPackage.ts` — 走査・確認・書き出し

## 受け入れ条件

- [x] 自分で書いたスキルだけを入れる
- [x] 説明の無いものを入れない
- [x] 入れなかったものを理由つきで出す
- [x] 秘密らしきものを知らせる（止めない）
- [x] 作る前に、入るもの・入らないものを見せる
- [x] `README.md` にそのまま打てる入れかたを書く
- [x] 公開しない（フォルダを作るだけ）
- [ ] 画面確認 — **自動化しない**。保存先を選ぶのが OS のダイアログで、画面テストから操作できない

単体テスト: `extensions/nimbus/src/test/skillPackage.test.ts`（10 件）

## 決めなかったこと・やらないこと

- **GitHub への push** — 公開は取り消せない。人が決める
- **独自の配布形式** — Claude Code の形式に乗る。読み手を自前で持たなくて済む
- **サブエージェントの同梱** — スキルと置き場所が違う。要るようになってから足す
