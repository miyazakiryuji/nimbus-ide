# 寝る前に仕込む

朝までにやっておいてほしいことを予約する（T-051）。

## 何を解決するのか

「朝までにこれ調べておいて」は、任せかたとしていちばん筋がいい。待っていないので遅くても
困らないし、失敗していても朝に分かるだけ。**ただし、寝ている間に承認を求められると何も
進まない**ので、そこをどう扱うかが設計の芯になる。

## 振る舞い

- 「寝る前に仕込む」（`nimbus.scheduleRun`）で、内容・時刻・承認の扱いを決める
  - 時刻は `07:30` のような指定か、`30分後` `2時間後`
  - **過ぎた時刻は翌日にする。** 「7:30 に」と言われて過去に実行することはない
  - 承認は「求める（止まってもよい）」か「自動で通す」
- **承認で止まることを黙らない。** 仕込んだ直後に、どちらを選んだかに応じて伝える
  - 求める → 「承認が必要な操作で止まります。調べもの（読むだけ）ならそのまま進みます」
  - 自動 → 「**取り返しのつかない操作もそのまま実行される**ので、調べもの以外には使わないでください」
- 「仕込んであるものを見る」（`nimbus.showSchedule`）で一覧。朝どこで結果を見るか
  （[ふりかえり](digest.md)の「昨夜から」）も書く
- 時刻が来たら、新しいセッションを始めてその内容を送る

**見張るのは Nimbus が開いている間だけ。常駐しない。** 気づかないところで動くものは怖い。

## 設計

- `extensions/nimbus/src/core/schedule.ts` — 時刻の解釈と判定（VS Code 非依存）
- `extensions/nimbus/src/schedule.ts` — 保存・見張り・セッションの開始

## 受け入れ条件

- [x] `07:30` / `30分後` を読み、過ぎた時刻は翌日にする
- [x] 読めない指定を弾く
- [x] 時刻が来たものだけを動かす
- [x] 承認で止まること／自動で通す危なさを、必ず伝える
- [x] 一覧に、朝どこで結果を見るかを書く
- [ ] 画面確認（実際に仕込んで朝に見る・未実施）

単体テスト: `extensions/nimbus/src/test/schedule.test.ts`（10 件）

## 決めなかったこと・やらないこと

- **常駐して閉じている間も動かすこと** — 気づかないところで動くものは怖い。開いている間だけ
- **繰り返しの予約（毎朝など）** — まず 1 回きりから。繰り返しは止め忘れが起きる
