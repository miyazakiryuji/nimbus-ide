## なぜ

同じ指示でも、モデルと思考量で結果も費用もまるで変わる。にもかかわらず、
**いま話しているセッションのモデルは変えられず、思考量は触る口すら無かった**。
既にあった `nimbus.agentModels` は**サブエージェント**への割り当てで、目の前の会話には効かない。

## 振る舞い

入力欄の下の帯に、押せる札を 2 つ出す。

```
[Opus 5] [思考 高]                    🟢 5 時間 ▬▬▬ 94%  🟢 週 ▬▬▬ 92%
```

- **モデル**（`nimbus.chooseModel`）— 選ぶと**次の応答から**効く。走っている最中でも受け付ける
- **思考量**（`nimbus.chooseEffort`）— 選ぶと**このセッションの残り**に効く
- セッションが無いときは札ごと消す（押せない口を置かない）
- **エフォートを持たないモデルでは、思考量の札を出さない**（Haiku など）。
  出しておいて押したら断る、は最も分かりにくい

## 決めたこと

- **候補は必ず SDK から引く**（`supportedModels()`）。モデルごとに使えるエフォートの段が違い、
  手で並べた一覧は必ず古くなる。知らない段（SDK が増やしたもの）は落として、生の英語を画面に出さない
- **エフォートは `applyFlagSettings({ effortLevel })` で変える。** 専用の口は無いが、
  これがセッションの残りに効く。`max` はセッション限りで設定ファイルには残らない（SDK の約束）
- **名前が無いモデルは id で出す。** 空欄にすると、どれを選んだのか分からないまま切り替えることになる
- セッションが名乗る id（`claude-opus-5[1m]`）と一覧の別名（`opus`）は一致しないので、
  `resolvedModel` と前方一致でも突き合わせる
- 効きかたが違う（次の応答から / セッションの残り）ので、**選んだあとに必ず言う**

## 見つかった抜け

一覧を読む側が `entry.id` を見ていたが、SDK が返すのは `value`。
**モデルの候補が `[object Object]` と出ていた**（評価コマンドとサブエージェント割り当ての 2 か所）。
型を付けたところで落ちたので、`toModelOptions()` に通す形へ直した。

## 権限モードのチップ（T-327）

人間工学点検（2026-08-18）の最重量所見 E3 の残り。取り返しのつかない操作の入口（送信）に、
いまどの権限で走るかが出ていなかった — モードが見えるのは畳まれた「文脈」ビューだけで、
`switchPolicy` の告知はトースト 1 回きり（消えたら残らない）。

- runbar の先頭に **`権限 <mode>`** のチップを置く。押すと `switchPolicy`（QuickPick）
- **モデルのチップと違い、セッションが無くても出す。** 送る前にこそ見たい値なので
- 出す値は、走り出したら **`init.permissionMode`（実際に効いている値）**、まだなら設定の
  プロファイル。**2 つがずれている**（切り替えたが、走っているのは前のモード）ときは、
  指を置いたときの説明でそう言う — 「切り替えたのに効いていない」を黙って起こさない
- 切り替えたあとはチップを描き直す。トーストは消えるが、チップは残る
