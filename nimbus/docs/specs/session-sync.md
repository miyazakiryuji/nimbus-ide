# マシンをまたいでセッションを続ける

**タスク**: T-085 / **実装**: `extensions/nimbus/src/core/sessionSync.ts`（判定）,
`extensions/nimbus/src/sessionSync.ts`（VS Code 層） / **テスト**: `src/test/sessionSync.test.ts`

## なぜ

会社の Mac で始めて、家の PC で続きを見たい。会話の記録はファイルなので運べる。
**運んで困るのは会話ではなく前提のほう。**

エージェントは「さっき直した `a.ts` は今こうなっている」という前提で話を続ける。
別のマシンでその前提が崩れていると、**崩れていることに気づかないまま**続きを書く。
これがいちばん危ない — 会話は自然に繋がって見えるのに、指している先が違う。

だから運ぶのは会話だけではなく、**その会話が前提にしていた状態**も一緒に運ぶ。

## 束の中身

| ファイル | 何が入るか |
| --- | --- |
| `transcript.jsonl` | 会話の記録（`~/.claude/projects/…/` のいちばん新しいもの） |
| `nimbus-session.json` | そのとき何を前提にしていたか |

マニフェストが持つのは — リポジトリの URL・枝・HEAD・**出したとき汚れていたか**・
出どころのマシン名・日時・続きの自分へのメモ。

**コミットしていない変更は束に入らない。** 入れると「同期したつもりで別物が動く」ので、
出すときに「先に push するか、WIP コミットを作ってください」と伝えるだけにする。

## Nimbus は運ばない

置き場所は選ばせるだけ（iCloud でも Dropbox でも USB でもよい）。
**どこを経由するかは、その人の事情の話。** 会話の記録は業務の内容そのものなので、
Nimbus が経路を決めるべきではない。

## 入れる前に突き合わせる

| 違い | 判定 |
| --- | --- |
| **別のリポジトリ** | `stop` — 会話の前提が丸ごと違う。続けさせない |
| 枝が違う | `warn` — 同じ HEAD を指していることもある |
| コミットが違う | `warn` |
| どちらかが汚れている | `warn` |

**違いは全部挙げる。** 1 つ見つけた時点で止めない — 何と何が違うかが分からないと、
続けてよいか判断できない。**止める判断は人がする**（`stop` を除く）。

`warn` で続けるときは、入る前にエージェントへ**ずれを先に言う**。

1. 話に出てくるファイルを**読み直す**
2. 直したはずの変更が入っていないなら、**そう言う**（やり直すかは人が決める）
3. **覚えているつもりで書かない**

言わずに続けると、「さっき直したファイル」を今の中身だと思ったまま話が進む。

## 出るもの

| コマンド | すること |
| --- | --- |
| `nimbus.exportSession`（このセッションを持ち運べる形にする） | メモを聞き、置き場所を選ばせ、束を作る |
| `nimbus.importSession`（別のマシンから続きを入れる） | 束を選ばせ、手元と突き合わせ、ずれを言ってから続ける |

束の名前は `nimbus-<枝>-<日時>`。人が見てどれがどれか分かるように。

## 確認項目

- [ ] 記録が 1 本も無いワークスペースで、エラーではなく案内が出る
- [ ] 束に `transcript.jsonl` と `nimbus-session.json` の 2 つが入る
- [ ] 同じマシン・同じコミットで入れると「そのまま続けられます」で終わる（投入なし）
- [ ] 別のリポジトリの束を入れようとすると止まる（続けるボタンが出ない）
- [ ] 枝もコミットも汚れも違うとき、**4 つとも**挙がる
- [ ] `version: 2` の束を読まない
- [ ] 続きに入る文に「読み直してください」が入っている
