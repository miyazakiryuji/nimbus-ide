# 古くなった API ドキュメントを探す（T-209）

公開 API を変えたのに文書が古いままなのは、**コメントだけ古い**のと同じで、
読む人を積極的に間違えさせる。しかも**差分レビューでは気づけない** —
変わっていないファイルは差分に出ないから、レビュー画面には現れない。

## 振る舞い

コマンド **「古くなった API ドキュメントを探す」**（`nimbus.checkApiDocs`）:

1. `git diff HEAD` から、**公開している名前の変更**を拾う
   （`export function` / `class` / `const` / `interface` / `type` / `enum`）
2. ワークスペースの `*.md` から、その名前に**触れている**文書を探す
3. **今回の変更に含まれていない**文書だけを挙げる
4. 「確かめさせる」で、確認と修正を頼む指示がコックピットへ送られる

## 実装

- `extensions/nimbus/src/core/apiDocs.ts` — 判定と文面（純関数）
- `extensions/nimbus/src/apiDocs.ts` — git と文書の読み込み
- テスト: `extensions/nimbus/src/test/apiDocs.test.ts`

## 決めたこと

**名前としての言及だけを拾う。** 部分一致で拾うと `run` のような短い名前が
あらゆる文書に当たり、指摘そのものが信用されなくなる。前後が単語構成文字でないことを見る。

**書かれていない名前は挙げない。** どこにも書かれていないものは古くなりようがない。

**「直して」ではなく「確かめてから直して」。** 名前が一致しているだけで
関係のない記述のこともある。**古くなっていないものは「問題なし」と報告させる。**

**見る文書は 200 件まで。** 読み込みだけで時間を使わない。

## 確認すること

- [ ] `export function` の名前を変えると、その名前に触れている `.md` が挙がる
- [ ] 同じ変更で文書も直していれば、挙がらない
- [ ] `runSomething` を変えても `run` にしか触れていない文書は挙がらない
- [ ] 公開名を変えていないときは「変更は見つかりませんでした」と出る

## 残っていること

- Markdown だけを見ている（dartdoc / TSDoc の生成物は対象外）
- 名前の変更だけを見ていて、**引数や戻り値の変更**は拾えない
  （[lsp-tools](lsp-tools.md) の `hover` と突き合わせれば拾えるが、まだ繋げていない）
