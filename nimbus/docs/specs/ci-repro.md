# CI を手元で再現する

ワークフローから、打つ順を取り出す（T-132）。

## 何を解決するのか

「CI だけ落ちる」は、たいてい**手元と CI で違うことをしている**だけ。ワークフローには何を
しているかが書いてあるのに、読みに行くのが面倒で、結局 push しては待つ、を繰り返す。

## 振る舞い

コマンド「CI を手元で再現する」（`nimbus.openCiRepro`）。

- `.github/workflows/*.yml` を選ぶ（1 つなら自動）
- 出すもの
  - **CI が使っている環境** — `runs-on` と `actions/setup-*` の版。**手元と突き合わせて印を付ける**
    （合っていれば ✅、違えば ⚠️）。「CI だけ落ちる」の多くはここ
  - **同じ順で打つコマンド** — `run:` を上から並べる（複数行の `run: |` もまとめて拾う）
- **CI 専用の行は落とす** — アップロード・ダウンロード・通知・`GITHUB_TOKEN` を使うもの。
  コマンド本文だけでなく、**そのステップの `uses:` も見る**
  （`uses: actions/upload-artifact` は `run` が無害に見えても CI 専用）
- **そのまま実行はしない。** 重いものが混ざるので、見てから人が打つ

**YAML パーサは持ち込まない。** インデントと `run:` だけを見るので、込み入った書き方
（アンカー・合成）は取りこぼす。取りこぼしても「手元で試す取っかかり」としては足りる。

## 設計

- `extensions/nimbus/src/core/ciRepro.ts` — 取り出しと整形（VS Code 非依存）
- `extensions/nimbus/src/ciRepro.ts` — ファイル選択と版の確認

## 受け入れ条件

- [x] `run:` をジョブ名つきで取り出す（複数行も）
- [x] `runs-on` と `setup-*` の版を拾う
- [x] CI 専用のステップを手元の手順に入れない（`uses:` も見る）
- [x] 版が違えば目立たせる
- [x] そのまま実行はしないと書く
- [ ] 画面確認（実際のワークフローで試す・未実施）

単体テスト: `extensions/nimbus/src/test/ciRepro.test.ts`（9 件）
実データでの確認（2026-08-13）: このリポジトリの `chat-lib-package.yml` から
`npm ci` → `npm run extract-chat-lib` → … の並びを取り出せることを確認した。

## 決めなかったこと・やらないこと

- **実行** — 重いものが混ざる（CI は待てるが、手元では待てない）
- **matrix の展開** — `${{ matrix.os }}` はそのまま出す。展開すると嘘の組み合わせが出る
