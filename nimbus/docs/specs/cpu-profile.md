# 計測結果を渡す

`.cpuprofile` を読んで、直しに行ける場所だけを出す（T-128）。

## 何を解決するのか

プロファイラの画面は**情報が多すぎる**。開いてまず目に入る炎のグラフは、
たいていランタイムの内部（`node:internal/...`）で、**直せる場所ではない**。
「重いのは分かったが、どこを触ればいいのか」で止まる。

## 振る舞い

コマンド「計測結果を渡して重い箇所を調べる」（`nimbus.importCpuProfile`）。

- ワークスペースの `.cpuprofile` を新しい順に出す（無ければファイルを選ぶ）
- Chrome DevTools と `node --cpu-prof` のどちらでもよい（**同じ形式**なので取り方は問わない）
- 出すもの
  - **直しに行ける場所** — 自分のコードだけ。自己時間の多い順
  - **その中で呼ばれているもの** — ランタイム・依存。直接は直せないと明記する
  - 計測していた長さと、**待っていた時間**
- 頼むときは **まだ直させない**。「なぜここで時間を使っているか」と
  **「速くなったことをどう確かめるか」**を先に書かせる

### 自己時間の出しかた

**`samples` と `timeDeltas` から出す。** `hitCount` は回数でしかなく、1 回あたりの
長さは一定ではない。実物（`node --cpu-prof` の出力）で確かめたところ、
`timeDeltas` の合計は `endTime - startTime` に**ぴったり一致**した（20041 µs）。

同じ関数は**呼び出し経路ごとに別ノード**になるので、関数単位でまとめ直す。

### `node_modules` を「自分のコード」に混ぜない

依存が重いと分かっても、できるのは「呼ぶ回数を減らす」か「別のものに替える」で、
**直しに行く場所が違う**。だから `own` / `dependency` / `runtime` / `engine` に分ける。
