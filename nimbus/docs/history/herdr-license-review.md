# Herdr の権利まわりの確認（T-280）

**日付**: 2026-08-19 / **対象**: [herdrdev/herdr](https://github.com/herdrdev/herdr) v0.8.1 /
**前提タスク**: T-279（セッションの土台に取り込めるかの検討）

**結論: 「入っていれば使う」なら問題なし。同梱は保留**（③ の孫ライセンスが未確認のため）。

## 確かめたこと

| 見たもの | 実測 |
| --- | --- |
| ライセンス | `LICENSE` は **Apache License 2.0** の標準テキスト。`Cargo.toml` の `license` も `Apache-2.0` |
| NOTICE | **無い**（リポジトリ直下に `NOTICE` ファイルが存在しない） |
| 著作権者名 | LICENSE 付録は `Copyright [yyyy] [name of copyright owner]` の**ひな形のまま**。名前が入っていない |
| 構成 | 単一パッケージ（ワークスペースではない）。直接依存 23 件（`tokio` / `ratatui` / `portable-pty` など） |
| 配布物 | GitHub Releases・Homebrew・mise・Windows インストーラでバイナリを配っている |
| 商標方針 | 明示の記載は見当たらない |

## ① 同梱するときの義務（Apache-2.0 §4）

- **LICENSE の同梱が要る。** 改変したなら「改変した」旨の明示も要る
- **NOTICE は無いので、NOTICE の同梱義務は発生しない**
- 帰属は、LICENSE に著作権者名が入っていないので
  「Herdr（herdrdev/herdr・Apache-2.0）」の形で**出どころを示す**のが妥当

## ② 商標（"Herdr" の名前）

Apache-2.0 **§6 は商標のライセンスを与えない**。明示の商標方針も見当たらないので、保守的に扱う。

- 「Herdr を使う / Herdr のセッションを読む」という**説明的な用法に留める**
- Nimbus の画面で Herdr を**製品名として掲げない**。バイナリを改名して同梱しない

## ③ 孫ライセンス（配布物に何が入るか）

Rust の単一バイナリなので、**静的に混ざった依存のライセンスが配布物に乗る**。
リポジトリに `deny.toml` / `about.toml`（cargo-deny / cargo-about の設定）は無いため、
**こちらで確かめないと分からない**。直接依存 23 件は Rust の慣行どおり MIT / Apache-2.0 の
デュアルが多いと見込まれるが、推移的依存まで確認していない。

→ **確認できるまで同梱しない。**

## ④ Nimbus（MIT の VS Code フォーク）との整合

併置して配ること自体は問題ない（Apache-2.0 のものは Apache-2.0 のまま）。
ただし **Apache-2.0 のソースを MIT のツリーに混ぜ込まない** — 取り込むなら
別バイナリとして置き、ライセンスの境目をファイルの境目と一致させる。

## ⑤ 会社の台帳

`00_hq/ledger/ip-register.md` の第三者 OSS として登録した（扱い: 参照のみ・同梱しない）。

## T-279 への申し送り

- まず **「入っていれば使う」**（利用者が自分で入れた Herdr を Nimbus が見つけて使う）で試す。
  再配布に当たらないので、権利上の負担がほとんど無い
- 同梱に進むなら、先に `cargo-deny` / `cargo-about` を回して配布物のライセンス一覧を作る。
  そのうえで配布・署名・公証（[distribution](../specs/distribution.md)）への影響を見る
