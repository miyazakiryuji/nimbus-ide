Nimbus

Nimbus を入れて、
最初の 1 往復を動かすまで

エージェントを操縦するためのコックピット。Claude Code のセッション・承認・並列タスク・コストを、 ひとつの IDE の中で見渡して操作できるようにすることを目指しています。

最新版をダウンロード GitHub リポジトリ

これは Anthropic 非公式・Microsoft 非公式の独立プロジェクトです。 Anthropic からも Microsoft からも承認・後援・提携を受けていません。

はじめる前に

この 2 つが揃っていれば、あとは上から順に進むだけです。

動作環境

macOS（Apple Silicon）
配布している .dmg は Apple Silicon 向けです。 ほかの環境では「手元でビルドする」を見てください。

別途必要

Claude Code
Nimbus は Claude Code 本体を同梱していません。 未インストールなら先に入れておいてください。

入れる

リリースの .dmg から入れる、いちばん短い道です。

  1. .dmg をダウンロードする

    Releases から nimbus-<版>-darwin-arm64.dmg を落とします。

  2. 「アプリケーション」へドラッグする

    .dmg を開き、Nimbus.app を「アプリケーション」フォルダへドラッグします。

  3. 初回だけ、右クリックから開く

    そのままダブルクリックすると 「開発元を確認できないため開けません」 と出ます。 Apple の開発者証明書で署名していない（ad-hoc 署名の）ビルドのためです。次の手順で開いてください。

    1. Finder で Nimbus.app を 右クリック → 開く
    2. 確認ダイアログで、もう一度 開く

    以降は通常どおりダブルクリックで起動できます。

  4. Claude Code を見つけてもらう

    Nimbus は PATH や ~/.local/bin から自動で探します。 見つからない場合は、設定 nimbus.claudeCodeExecutable に実行ファイルのパスを指定してください。

    同梱していないのは、プラットフォーム別バイナリだけで 280MB あるうえ、 利用者はすでに認証済みのものを持っていることがほとんどのためです。

  5. 最初の 1 往復

    1. フォルダを開く。 信頼していないフォルダでは画面は開きますが Claude は実行しません。 実行しようとすると理由と「このフォルダを信頼する」ボタンが出ます
    2. アクティビティバーの雲アイコン → コックピットに指示を書いて Enter
    3. Claude がファイルを書き換えようとすると差分が開くので、内容を見てから許可・拒否
    4. もう 1 本走らせたいときはコックピットのタブ列の +。 作業ごと分けたいときは Nimbus タスクから「新しいタスク」（こちらは git worktree を切って完全に分離します）

    アクティビティバーには雲の家族が 4 つ並びます — 雲（雨）: コックピットと承認待ち／ 雲＋一覧「Nimbus タスク」: 並列タスクの板／ 雲＋歯車「Nimbus 設定」: スキル・CLAUDE.md・設定／ 雲＋虫「Nimbus デバッグ」: エージェントが詰まったときの面。

最初に見ておくとよい設定

既定のままでも動きます。気になったときに。

設定既定説明
nimbus.claudeCodeExecutable自動探索使う Claude Code の実行ファイル
nimbus.permissions.autoApproveReadOnlyfalse読み取り専用ツールを確認なしで許可
nimbus.permissions.showDiffBeforeApprovaltrue承認の前に差分を開く
nimbus.tasks.maxConcurrent2同時に走らせるタスクの上限

詰まったとき

よく引っかかるところを 4 つ。

Claude が動かない／送信しても何も起きない

「制限モード（Restricted Mode）」を疑ってください。 開いたフォルダは初回に信頼を聞かれ、 答えるまで制限モードのままです。制限モードでは Nimbus は画面は開きますが Claude を実行しません （フォルダの中でコマンドを実行しファイルを書き換えるため）。

送信しようとすると理由と「このフォルダを信頼する」ボタンが出るので、そこから信頼できます。 画面下の「制限モード」からでも同じです。

1 回目の起動だけ英語で出る

表示言語は日本語が既定です。 ただし真っさらな設定フォルダでは、言語パックの読み込みの都合で 1 回目の起動だけ英語になります（2 回目から日本語）。

英語のまま使いたいときは --locale en で起動するか、argv.json に "locale": "en" を書きます。

入れたい拡張機能が見つからない

Nimbus は拡張機能を Open VSX（Eclipse Foundation）から取得します。 Microsoft の Visual Studio Marketplace は、利用規約により Microsoft 製品以外での利用が認められていないためです。 Marketplace にしか無い拡張は入りません（VSIX の手動導入は可能です）。

Open VSX の拡張は Microsoft の署名を持たないため、署名検証は既定で無効にしてあります。 代わりに Eclipse が管理する「無効化すべき拡張」のリストを参照しています。

SSH 先やコンテナの中で使いたい

リモート拡張ホストでの動作は確認済みです。ただし知っておくべきことが 1 つあります — Nimbus の拡張はリモート側で動きます。

その結果、Claude Code の実行ファイル・認証（~/.claude）・ターミナル・git は すべて繋いだ先のものが使われます。手元に入れた Claude Code は使われません。 nimbus.claudeCodeExecutable に書くパスもリモート側のパスです。

なお Microsoft の Remote-SSH / Dev Containers は利用規約によりフォークでは使えません。 Open VSX にある OSS のリモート拡張を入れる形になります。

手元でビルドする

開発ビルドを動かす、配布形式を自分で作る場合。

git clone https://github.com/miyazakiryuji/nimbus-ide.git
cd nimbus-ide

# Node を .nvmrc（24.18.0）に合わせる（nvm を使う場合: nvm install && nvm use）
node --version   # v24.18.0

npm install                        # Xcode Command Line Tools と Python が必要
npm run compile
./scripts/code.sh                  # 開発ビルドを起動

bash nimbus/scripts/package-app.sh      # 配布形式（.app）を作る
bash nimbus/scripts/make-dmg.sh 1.1.3   # .dmg にする（引数は版の名前）
