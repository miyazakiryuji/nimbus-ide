# セッションの健康診断

`nimbus-doctor` が見るのは**リポジトリ**（不要ファイル・辿れないモジュール・台帳のズレ）。
こちらが見るのは**走らせたあとに残るもの** ── セッションの記録。

```bash
node nimbus/scripts/session-health.mjs            # 人が読む形式
node nimbus/scripts/session-health.mjs --json     # 機械が読む形式
node nimbus/scripts/session-health.mjs --dir <台帳のパス>
node nimbus/scripts/session-health.mjs --forget   # 「忘れてよい」ものだけ消す
```

残骸があれば終了コード **1**。無ければ 0。

## なぜ残るのか

台帳（`globalStorage/idris.nimbus/sessions/`）は **1 セッション 1 ファイル**。
持ち主は**心拍**で決まる ── 持っているウィンドウが 5 秒ごとに時刻を書き直し、
**20 秒**途切れたら「手放した」と見なす（`OWNER_TTL_MS`）。

落ちても壊れない代わりに、**ウィンドウが落ちると持ち主のいない記録が残る**。
アプリ側の `sweep()` は落とすが、条件は「持ち主がいないまま **7 日**たったもの」だけで、
しかも **Nimbus が動いているときにしか走らない**。だから横断で数える手段が要る。

## 何を見ているか

| 見立て | 意味 | どうするか |
| --- | --- | --- |
| **走行中** | 持ち主が生きていて走っている | 触らない |
| **待機** | 持ち主は生きているが走っていない（入力待ちなど） | 触らない |
| **終了** | 終わっている | **正常**。復帰の候補として残る（T-252） |
| **持ち主なし** | 持ち主がいないのに終わってもいない | **これが残骸。** 続きから開くか、消す |
| **忘れてよい** | 持ち主がいないまま古くなった | `--forget` で消せる |
| **重なり** | 同じフォルダを生きた持ち主が 2 つ以上で持っている | 片方の前提が黙って壊れる。worktree を切るか、片方を止める |

**「終了」を残骸と読まない。** 終わった記録は「続きから」の材料なので、残っているのが正しい。

## 消してよいものの見分けかた

**`--forget` が触るのは「忘れてよい」だけ。** 走行中・待機・持ち主なしには指一本触れない。
これはアプリ側の `sweep()` と**同じ線**を使っている（`forgettable()` を共有）ので、
ここで新しい方針を作っていない。

「持ち主なし」を消すかどうかは、**機械では決められない**:

- 続きからやりたい仕事なら、消すと `claudeSessionId` ごと失われる（復帰できなくなる）
- もう要らないなら、残っていても実害は無い（7 日で自動的に落ちる）

なので、このスキルは**数えて見せるところまで**。消すのは人が決める。
消したいなら、Nimbus の画面から「続きから」を試したうえで、
それでも要らないものだけを台帳から取り除く。

## 読みかた

```
台帳: …/globalStorage/idris.nimbus/sessions
  4 件 — 走行中 0 / 待機 0 / 終了 3 / **持ち主なし 1**

  ✖ 持ち主のいないセッション（1 件）
    - d90958b2 awaiting-input · 利用できますか?
      /Users/…/testApp · 最終更新 14 時間前
```

- **件数を先に読む。** 「残骸があります」ではなく、何件かで判断が変わる
- **最終更新を見る。** さっき落ちたのか、何日も放置なのかで扱いが違う
- **`cwd` を見る。** 重なりが出ているときは、どのフォルダを取り合っているかがそこにある

## いつ走らせるか

- **並列で走らせたあと。** ウィンドウをいくつも開いて閉じた日は、まず溜まっている
- **「今いくつ走っているか」が合わないとき。** 画面はウィンドウの中しか数えないので、
  横断の数字はここでしか出ない
- **リリース前。** 手元の状態が診断結果に混ざっていないかの確認

**定期実行にはしない。** 残っていること自体は壊れていないので、
毎回出すと「いつもの赤」になって効かなくなる。

## 判定を足したくなったら

判定は `extensions/nimbus/src/core/sessionHealth.ts`（vscode 非依存・モジュールテスト 8 件）。
線を引く関数（生きているか・走っているか・忘れてよいか）は
`core/sessionRegistry.ts` のものを**使い回す**。ここで別の線を引かない ──
アプリと診断で判断が違うと、どちらを信じればよいか分からなくなる。

スクリプト（`nimbus/scripts/session-health.mjs`）は**置き場所と出しかた**だけを持つ。
