# テストを書く

## 1. 足りていない場所を知る

```bash
node nimbus/scripts/doctor.mjs coverage
```

- **要対応** — `vscode` に依存しないのにテストが無いモジュール。ここは必ず書く
- **参考** — `vscode` に依存するモジュール。モジュールテストでは扱えないので、
  GUI テスト（`nimbus/tests/gui/cases/`）の担当か、純粋ロジックを `src/core/` へ切り出す

## 2. 雛形を作る

```bash
node nimbus/scripts/scaffold-test.mjs                     # 足りていないもの全部
node nimbus/scripts/scaffold-test.mjs src/core/skills.ts  # 指定して
```

export ごとに `todo` 付きのテストが並んだファイルができる。**中身は空**。
何を確かめるべきかは、そのコードが何のために在るかを読まないと決まらないため。

## 3. 何を確かめるか決める

雛形の `todo` を、次の観点で置き換える。**関数の実装をなぞらない。**
「この関数が壊れたとき、利用者に何が起きるか」から逆算する。

| 観点 | 例（Nimbus の実際のテストから） |
| --- | --- |
| 間違えると実害が出る判定 | 課金モード（`apiKeySource='none'` はサブスク。誤ると従量課金だと誤解させる） |
| データを失う経路 | worktree 破棄前の WIP コミット（実 git で、成果がブランチに残ることまで確かめる） |
| 安全側に倒すべき既定 | 承認ダイアログを閉じたら「拒否」。答えなかったを許可にしない |
| 推測してはいけない場面 | 差分が作れないときは差分を出さない（対象文字列が見つからない等） |
| 上限・競合 | 同時実行の上限。起動処理中（in-flight）も枠に数える |
| 壊れても止まらないこと | 知らないメッセージ種別は黙って捨てる |

書きかたの約束:

- **テスト名は日本語で、確かめたい事実を書く。** 「〜する」で終える（`test('close 済みに push すると失敗する')`）
- 実物を使えるなら使う（git はモックせず実際に叩く。SDK は `query` を差し替えて実 Claude を呼ばない）
- 失敗メッセージに**実際の値**を入れる（`assert.ok(x, \`見つからない: ${text.slice(0, 200)}\`)`）
- 1 テスト 1 事実。落ちたときに原因が 1 つに絞れるように

## 4. 走らせる

```bash
bash nimbus/scripts/test.sh unit
```

`todo` が残っていると、ドクターが「テストが雛形のまま」と指摘し続ける。埋めきる。

## 5. GUI でしか壊れないもの

画面でしか確かめられないものは `nimbus/tests/gui/cases/` に 1 ファイル足す
（書きかたは `nimbus-test` スキル）。既定テーマ・ビューの存在・承認モーダル・差分エディタなど。

## 不具合を直すとき

**先に、その不具合を再現するテストを書く。** 落ちることを確認してから直す。
直ってから書いたテストは、本当にその不具合を捕まえられるか分からない。
